# 11. Capability Parity Matrix — Reverse-Engineered → Our Implementation → Status

Status: Current
Owner: Founder + platform lead
Last updated: 2026-07-10

This file is the per-capability reverse-engineering table mandated by `docs/current/agi-parity-master-plan.md` ("UX parity targets"). For each capability in the master-plan list it records: what was reverse-engineered from the current claude.ai / ChatGPT apps, where our implementation lives (repo path), and an honest parity status.

**Read the status column literally.** A cited file path proves _code exists_, not that the capability is _wired end-to-end_. Where the master plan or the 2026-07-09/10 live audits say a capability is non-functional, in-progress, deferred, or not started, the status here says so even when component code exists. When this file and `parity-implementation-matrix.md` (dated 2026-06-27, stale relative to the 07-10 wave work) disagree, the newer master-plan status wins and the row notes it.

## 11.1 Status legend

- **Done** — implemented and verified end-to-end (UI → runtime → visible result), or a byte-stable shared path this doc set already documents as live.
- **Partial** — code exists and is partly wired, but placeholder, non-functional in the live audit, or missing the persisted/end-to-end slice.
- **Gap** — no reliable implementation found, or the master plan lists it as not started / deferred.

Grounding column: **code** = a real repo path proves it; **research** = grounded only in the research corpus / matrix, not yet in shipped code; **flagged** = the master plan or live audit explicitly downgrades it.

## 11.4 Cross-reference to the wave queue

This table maps directly onto `docs/current/agi-parity-master-plan.md` §"Wave queue":

- Wave 2 (artifact-viewer parity) → Artifacts, rendering rows.
- Wave 3 (capability wiring) → Web Search, Deep Research, URL Fetch, Sandbox, File Creation, Tool Calling/Results, Thinking blocks.
- Wave 4 (rendering parity) → PDF, Image, Spreadsheet, Presentation, Email, Code chrome, Citations.
- Wave 5 (message-lifecycle unification) → Streaming lifecycle, Progress/Status/Error, Retry, Continue, Cancellation.
- Wave 6 (cross-surface) → carries every "Partial (shared)" row onto desktop v3 + mobile RN (both unverified for these capabilities).

So this file doubles as a parity status-of-record: as each wave lands and is verified end-to-end, flip the relevant rows from Partial/Gap to Done with the verifying evidence.
