# Retention and deletion matrix

Status: Current
Owner: Repository maintainers
Last updated: 2026-09-18

Every store that holds user or workspace data, what class of data it holds, what
erases it, and how long it may live. The table is rendered from
`apps/web/lib/services/deletion-manifest.ts` (`renderRetentionMatrixMarkdown`),
which derives it from the two erasure inventories, the financial retention rules
and the security-log retention window. A store added to either inventory shows
up here; `deletion-manifest.test.ts` fails when this file and the code disagree,
so the table cannot drift from what the product does.

Data classes: `customer_content` is what the subject wrote, `derived_content` is
computed from it, `operational_record` is what the product needs to run the
account, `audit_trail` is evidence that must outlive the account, `telemetry` is
measurement.
