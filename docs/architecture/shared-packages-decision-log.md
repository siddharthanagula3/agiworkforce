## 1. Corrections to the brief's tree evidence (Tier B facts)

- **`packages/ui/unified-chat` is real, not aspirational.** Imported by web (~31 files) and desktop (~25); both apps still keep 200+-file parallel chat trees on top of it. The job is adoption + deletion, not creation.
- **"Mode toggle implemented 3x" is a keyword artifact.** Desktop `SimpleModeToggle.tsx` toggles simple/advanced UI density (`stores/ui` simpleModeStore); web `AdvancedModeToggle.tsx` is a tier-gated manual model picker (no Local mode exists on web by design). The real trust-mode toggles are exactly two — `apps/desktop/src/features/v3/LocalCloudToggle.tsx` and `apps/mobile/src/features/chat/components/ModeToggle.tsx` — one per dual-mode surface, each delegating to its guarded mode store (`appModeStore` with `desktopCloudGate` tests; mobile 4-layer enforcement).
- **`apply-patch` is no longer duplicated.** The Rust crate `agiworkforce-apply-patch` had zero dependents and was deleted in restructure P0 (commit `chore(crates): remove dead ...`). The TS `packages/tools/apply-patch` is the live one (web, desktop, api-gateway).
- **Root `ios/` is not an 81% Pods blob.** Tracked root `ios/` is 19 files (canonical per `ios/README.md`; root `Podfile.lock` current). The 23k/25k path counts came from untracked/gitignored Pods present when the tree file was generated. `apps/mobile/ios/` is entirely gitignored prebuild output. The real problem is name divergence (`agiworkforce` vs prebuild's `AGIWorkforce`) — tracked as `MOBILE-IOS-PREBUILD-DRIFT-01` in known-flaws; canonical-path decision is plan P6. Do not delete root `ios/` on the brief's evidence.
- **HealthKit is NOT "correctly app-local" — it is removed.** On-device HealthKit was deleted 2026-07 (commit `93ca123df`, 1,086 deletions) over dead-code + false store-metadata claims. The surviving `healthData.ts` is a flag-gated-OFF client for a remote `/api/health-context` endpoint that does not exist. Owner requirement (HealthKit on mobile cloud parity) is a tracked gap: re-implement on-device HealthKit as a spec'd feature; delete or complete the dormant remote client. Plan §9.
- **`apps/desktop/{logs,dist-web}` were gitignored, not tracked noise** — removed locally in P0 along with `.code-review-graph` (174M), `.remember/logs` (18M), stray `apps/desktop/apps/` (35M), `.DS_Store`s.
- **Settings file counts are dominated by screens.** Mobile's split (`stores/settings/{local,cloud,sync}SettingsStore.ts` behind a compat facade) is the model architecture, already implemented. R4's own overturn condition triggers.
- **The "45 drift test failures" figure is unverified here.** CI baseline capture is a pending item (brief E6); do not treat the number as current fact.

## 2. Answers to the brief's open questions (from repo truth — no owner ask needed)

1. **CLI/VS Code/Chrome mode posture:** locked in `docs/current/source-of-truth.md` + trust-mode matrix: Desktop/CLI/VS Code support Local + BYOK + Managed; Web and Chrome are cloud/task-scoped; Mobile is Local + Cloud with **no BYOK**. CLI/VS Code/Chrome sessions stay workspace/task-scoped — no app-chat sync without explicit redacted handoff.
2. **Local mode + MCP:** local stdio MCP exists today — desktop (`src-tauri/src/core/mcp/` + MCP settings/config UI) and CLI (`src/mcp/` client + `mcp-server` mode). The cloud-scoped thing is the connectors/plugins directory experience. Both are in the product; they are different layers.
3. **Signed-out local mode:** yes by design — mobile Local works without an account (auth gates only Cloud, `remoteChatGate` fails closed); desktop Local requires no cloud session. Keep as a policy test target.
4. **Sandbox execution per mode:** Local = on-device (`agiworkforce-sandbox-policy` + `execpolicy` crates, desktop `sandbox_runtime`, CLI cross-OS sandbox). Cloud = server-side E2B (`apps/web/lib/e2b/*`). `infrastructure/sandbox` is a third thing: the cross-origin artifact _renderer_ for web (`NEXT_PUBLIC_SANDBOX_ORIGIN` provisioning gap tracked as `WEB-SANDBOX-ORIGIN-ENV-01`).
5. **AGI Work on Web/Mobile cloud = cloud Projects.** Matches shipped direction (desktop V3 AGI Work subpanels; web projects/agi-work routes). Desktop-local adds device folder selection via Tauri fs.
