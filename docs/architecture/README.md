# docs/architecture

How the system is built and why. Ownership, data flow, provider strategy, trust
boundaries, deployment topology, and per-surface architecture.

`ARCHITECTURE.md` at the repository root is the compact map; this tier holds the
depth behind it. Tables that a registry can generate belong in `docs/generated/`.

For ecosystem continuity, `overview.md` owns canonical data and event
semantics, while `trust-boundaries.md` owns what may cross Local, BYOK,
Managed Cloud, Account Cloud, and the host developer boundary. Dated maps and
syntheses remain snapshots and never override those current owners.
