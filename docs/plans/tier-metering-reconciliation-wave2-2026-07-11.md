Only the truthful doc-comment correction shipped this wave; no adapter behavior changed.
- **Sync-route N+1 batching** (needs Neon staging branch + client id-dedup): chat/sync, memory/sync, projects/sync, chat/branch, messages/bulk loop one RLS-bound 5-round-trip call per row. Naive INSERT...SELECT unnest ON CONFLICT DO UPDATE ERRORS the whole statement if two source rows share the conflict id ("cannot affect row a second time"), and nothing dedupes id across the pushed array → would convert today's graceful 200-partial-applied[] into a 500 dropping the whole batch. Fix path = client-side dedupe-by-id before push + staging verification, OR pipeline round-trips without collapsing to one statement. It's a latency tradeoff (not a correctness bug); the real correctness bug in these files (web_messages UPSERT ownership) was fixed this wave.
