Companion to `chatgpt-claude-parity-gap-ledger-2026-07-27.md`. Every feature
block in the founder's seven benchmark specs (`~/Downloads/0*-benchmark-spec.md`)
mapped to its actual state in this repo, with a file:line for each.

**Shared Platform (36%) and CLI (38%) are the weakest.** Shared is the
enterprise/identity/metering/notifications layer, where all four blocker-grade
gaps concentrate. CLI's low figure is different in character — only 9 blocks are
MISSING, but **33 are PARTIAL**, the highest of any surface: the CLI is broadly
capable and narrowly incomplete, so its gaps are mostly finishing work rather
than new subsystems.

**Mobile (68%) is the strongest surface**, which is the opposite of how every
prior document characterised it.

## The 7 UNREACHABLE rows

Desktop: `CodeWorkspace` (F-CODE-01), `TerminalWorkspace` (F-CODE-04),
PR/diff review (F-CODE-06), `GovernanceDashboard` (F-GOVN-03 — the Privacy-tab
button opens a dead sidecar), `TeamAccountSettings` (F-GOVN-04).
CLI: `agiworkforce-licensing` org-policy crate is complete but `apps/cli` has no
dependency on it (F-ENT-01). Mobile: the skills store/service has zero UI
importers (F-WORK-05).

## The 2 PHANTOM rows

`04 F-CMD-02` and `04 F-TOOLR-02` — the CLI spec's "full slash-command parity
table" and "full built-in tool registry parity table". Both reproduce names that
exist only inside a Claude Code _agent session harness_. The real command subset
(~120) is already registered; the real tool subset is already in the catalog.

## Method

Every row opened the implementation — entry files, importers, feature flags,
Expo config plugins, `Cargo.toml`/`package.json` contributions, migrations.
Reachability is part of status, not an afterthought. Where a grep count and the
code disagreed, the code won: this session nearly published 863 phantom Chrome
CSS bugs from a count that looked conclusive.
