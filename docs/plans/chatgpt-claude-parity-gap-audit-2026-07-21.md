# AGI Workforce — ChatGPT / Claude Parity Gap Audit (2026-07-21)

**What this is:** a comprehensive, code-verified map of where AGI Workforce lags Claude and/or ChatGPT (July 2026), and what's specified in our own implementation-pack blueprint but not yet built — across all six surfaces plus shared architecture. Produced by seven parallel research agents, each cross-referencing the founder-supplied spec bundles in `~/Downloads/` against the actual repo (not just docs). Every row below carries a file/line or doc citation; anything that couldn't be verified is explicitly marked "unverified — flag for founder" rather than asserted.

**This is a triage queue, not a to-do list executed yet.** Per repo policy, generated audit markdown is not remediation — it's the starting point for opening the cited files and fixing what's real.

## 2026-07-25 remediation checkpoint

This dated audit remains useful evidence, but several findings below describe
the 2026-07-21 tree and are no longer current:

- Desktop Managed Cloud is now selected by the native composition root for an
  authenticated Cloud workspace. It shares the Web chat and persistence
  boundary, with durable generated files/images and server tool activity.
  Local/BYOK still fail closed away from it. Automated/native UI coverage is
  green; a production-authenticated Tauri turn remains a release check because
  the isolated test app cannot inherit the signed-in browser session.
- The dynamic `/connect/[deviceType]` device-auth route covers VS Code; the old
  statement that a literal `/connect/vscode` file is absent conflated dynamic
  routing with a 404. VS Code sign-in/sign-out now refreshes or clears the
  account-derived tier immediately so model admission cannot retain stale paid
  access.
- Generated Web images now persist in messages and project into the Artifacts
  panel, including a safe image preview, download, v1/1 history, and reload
  restore. Generated image files also remain available as transcript
  thumbnails without a duplicate artifact card.
- Chrome's dead shortcut Start-from/Schedule fields were removed and onboarding
  now points to Workflows. VS Code's 300px composer/header overlap is fixed.
  Both extension suites, a real unpacked-Chromium smoke, and a real Extension
  Host activation/command smoke are green.
- Custom remote-MCP connectors are visible and token-capable in Desktop Cloud;
  Desktop Local retains its separate native MCP system. Mobile cross-surface
  custom-connector administration is still open.
- Web now has a real single-workspace Team administrator for existing AGI
  accounts. This does **not** close the Blocker below: SSO/SCIM, invitation
  delivery, tenant-wide RLS, licensed seats, multi-org creation, and
  enterprise-managed connectors remain unavailable.
- GitHub's flow now proves installation ownership through user OAuth and
  `/user/installations`; legacy unverified rows cannot supply tools. It still
  requires migration `0072`, complete GitHub App/OAuth production
  configuration, and a supervised live install round-trip.

## Executive summary — top cross-surface gaps, ranked

Synthesized across all seven sections below. "Blast radius" = how many other gaps or how much user-facing trust each one touches, not just severity label.

1. **Enterprise SSO/SCIM are non-functional metadata scaffolding, not authentication.** `/api/admin/sso` and `/api/admin/directory-sync` look real in the admin UI but implement zero login callback, zero assertion validation, zero provisioning. The `/enterprise` marketing page sells a capability that doesn't work end-to-end. This is a live "confusing/fake availability" bug per repo policy, and a revenue risk if shown to any enterprise prospect today. — **Blocker**
2. **Desktop cannot reach Managed Cloud at all**, and cross-device sync is unreachable as a direct consequence — the toggle is hard-gated off, and three separate (over-built) sync mechanisms exist with no reachable trigger. Claude and ChatGPT desktop are cloud-native by default; this is the starkest capability gap on the surface where it matters most for a privacy-first pitch to actually need cloud continuity. Deliberate and tracked, but still the single biggest open item on Desktop. — **Blocker**
3. **Web's own memory system may not be wired into the production chat path.** The Memory settings UI can display state the actual `WebChatPage`/`useChatStream` send path never reads — every downstream memory claim (personalization, cross-surface continuity) depends on this being real. — **Blocker**
4. **Tool approvals are not reload-durable anywhere.** Approval/resume state is process-memory-only across Web, Desktop, and the CLI/VS Code app-server host; a server restart or app-server crash during an `awaiting_approval` window stitches together a dead-looking card with no recovery path. This is a correctness bug in the core agent loop, not cosmetic. — **Blocker**
5. **Neither browser/editor distribution channel is live.** The Chrome extension isn't published to the Chrome Web Store; the VS Code extension isn't published to the Marketplace or Open VSX. Both are otherwise functional, well-tested products sitting behind a packaging/publishing step, not a code gap — but until that ships, two of six surfaces have zero real user acquisition path. — **Blocker** (for distribution, not for functionality)
6. **VS Code cloud sign-in is still broken in production** (`/connect/vscode` 404s, confirmed unchanged since the 2026-07-19 finding — no commit since has touched the route). Workaround exists (BYOK/Local), but any Managed Cloud user opening the extension today cannot sign in. — **Blocker** for that one flow
7. **Global search is single-entity everywhere it exists.** Web's search covers chat sessions/messages only — no projects, artifacts, memory, files, or connectors. Desktop's federated search hook (`useGlobalSearch.ts`) is fully built but literally unmounted — imported only by its own test file. — **High**
8. **A recurring "backend complete, zero UI caller" pattern spans a dozen+ Desktop features**: workspace/semantic code indexing, git AI features, git panel, diagnostics/doctor panel, notification actions, email UI, and (newly found this pass) the Ollama model-download button. Each instance is individually cheap to fix relative to the backend work already sunk — this is a wiring gap, not a build gap. — **High** (systemic)
9. **Settings sync is Mobile-only.** Desktop has zero settings-sync wiring in any mode — a setting changed on Desktop silently doesn't exist anywhere else, which directly undercuts the "one product, six surfaces" pitch. — **High**
10. **Connector/MCP state diverges by surface.** Custom remote-MCP connectors are invisible on Desktop and Mobile even though the Web CRUD is real; per-tool permission enforcement is client-only. The same "route theater" bug class was already found and fixed once on Mobile connectors — it's recurring in a new place. — **High**
11. **Desktop eagerly injects full skill bodies into every LLM turn**, unfenced, gated only by a default-on flag — the exact untrusted-content-injection pattern the CLI already remediated. This is a live trust/security gap, not a polish item. — **High**
12. **Voice is correctly triaged but incompletely finished even at the achievable tier.** Full-duplex realtime voice is a known, deliberately deferred hard blocker (not buildable on Web Speech APIs, needs a realtime provider) — that decision is sound and shouldn't be revisited without a provider partnership. But the _achievable_ middle tier (hands-free turn-based loop, a shared `VoiceSessionV1` state machine) hasn't been built on any surface either, and Desktop's voice-mode UI is fully built yet **unshippable as-is** because it hardcodes a Whisper path not compiled into any default build. — **High**
13. **CLI has a silent-failure correctness bug**: zero references to Anthropic's `pause_turn` continuation anywhere in the crate. A paused long-running server-tool turn can appear complete and silently truncate tool work on Anthropic/BYOK routes. — **High**
14. **Mobile is missing several table-stakes platform integrations**: no iOS Share Extension (Android has one), no home-screen widget/Quick Actions, no native in-app purchase path (every SKU is a placeholder — founder/App-Store-Connect action required), and the Skills catalog is browsable but never actually injected into a conversation. — **High**

**Where AGI Workforce is genuinely ahead**, confirmed by these same agents, not just marketing copy — worth stating plainly rather than only cataloguing gaps: real tiered on-device inference with thermal-throttle protection on Mobile (neither competitor has any on-device path); on-device OCR and on-device translate as native iOS modules; `agi migrate` + `agi ecosystem` on CLI (1,610 lines, genuinely imports Claude Code/Codex/Gemini/Cursor configs — no evidence any competitor CLI does the reverse); a hardened macOS Seatbelt sandbox with real SBPL-injection defenses and fail-closed execution; MCP OAuth/resources/elicitation and self-hosting (`agi mcp-server`) all real and wired on CLI; genuinely BYOK-capable Desktop/CLI/VS Code with zero-markup, direct-to-provider routing and AES-256-GCM key storage; a real, hardened computer-use approval gate on Chrome (ask-before-acting default, forge-resistant, fail-closed timeout) that closed a real P0 leak; and cross-surface chat sync (Web/Desktop/Mobile) that is confirmed genuinely working, not aspirational.

### Top priority gaps (Web)

1. **No first-class Cowork/Work surface.** AGI Work is a composer toggle, not a durable WorkRun/Plan/Step/Approval domain with its own Home, run history, and cross-device continuation.
2. **Project knowledge files don't ground chat answers.** Files upload and register metadata, but nothing in the LLM request path reads project file content.
3. **Enterprise SSO cannot actually be used to log in.** Admin can create an SSO connection record; no UI caller of the domain-check exists, and no SAML ACS/OIDC callback route exists anywhere.
4. **Global search is chat-only.** Never touches projects, memory, artifacts, or files.
5. **VS Code cloud device-auth is broken in prod** (`/connect/vscode` 404) — deferred by design decision, needs a founder call on `user_code` vs `device_id`.
6. **Artifact sandbox cross-origin isolation is provisioning-gated, not code-broken** — `NEXT_PUBLIC_SANDBOX_ORIGIN` isn't set anywhere.
7. **Plugins marketplace is a marketing preview, not a live install flow.**
8. **E2B code execution is off by default in prod** and popular-searches is empty in prod (migration 0045 not applied) — both env/ops gaps that make advertised features silently degrade.

### Top priority gaps (Desktop)

4. **Artifact token streaming is incomplete.**
5. **A recurring "backend complete, zero UI caller" pattern spans a dozen+ features** — indexing, diagnostics, git AI, git panel, notification actions, email UI, Ollama model-download. Systemic, individually cheap to fix.
6. **Local model download has no UI trigger at all** (new finding) — undermines the "local mode, no terminal needed" pitch.
7. **Sign-in, billing, account switching unreachable from the live app** — same root cause as the cloud gate.
8. **Linux is a second-class platform** — relevant given the EU-sovereignty/regulated-industry positioning.

### Top priority gaps (Cross-Cutting)

1. **Enterprise SSO/SCIM are non-functional metadata scaffolding, not authentication** — a genuine trust-boundary and revenue risk if shown to any enterprise prospect today.

9. **Managed Cloud usage is a Web-server-local pattern, not a published cross-surface contract** — a metering/abuse-control gap as Desktop/CLI mature.
10. **Voice realtime full-duplex is correctly deferred, but the achievable turn-based/hands-free middle tier also hasn't been built on any surface** — don't let the correctly-deferred blocker mask that buildable-today voice work hasn't started.
