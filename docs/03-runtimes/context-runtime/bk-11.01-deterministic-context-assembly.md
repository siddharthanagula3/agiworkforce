## Purpose

This book establishes the canonical contract for **deterministic context assembly** in the platform: the rule that, given a fixed conversation, memory corpus, project, token budget, and model context window, the assembled context handed to a model is always identical (AC-19). It owns the **source-packing order** — the deterministic precedence by which the five source classes are composed into a single token-budgeted view — and the **cross-trust-boundary read scoping** that prevents a turn from assembling state it is not authorized for (§19 trust rule, AGI-TRUST-0001).

The book exists because the current platform has **no single assembler**. Context assembly today is multi-path: the web surface assembles partly client-side and partly across two server route generations; the desktop surface runs two distinct Rust `ContextManager` implementations; and the CLI, mobile, and VSCode surfaces each carry their own budgeting and gathering logic. **Current** state is therefore divergent by surface. **Target** state is one deterministic shared assembler with one source-packing order. This book specifies the contract all surfaces must converge on and the migration path toward it.

Context is **derived, never authoritative** (§19 framing). It owns no durable state; it is a deterministic function of the session, memory, and storage planes. Everything in this book follows from that single architectural commitment.

## Scope

This book owns exactly three chapters:

- **CH-11.01.01 — Source taxonomy & packing precedence.** The five source classes (conversation, memory, project knowledge, tool results, instructions) and the deterministic order in which they are packed into the token budget.
- **CH-11.01.02 — Deterministic assembly contract.** Fixed inputs producing an identical assembled context, with no ambient nondeterminism, and with decay/recency admitted only as a declared input.
- **CH-11.01.03 — Cross-trust-boundary read scoping.** The rule that a managed turn never assembles local-origin content and a local/BYOK turn never pulls from the shared cloud store (§19 trust rule, AGI-TRUST-0001), with the egress mechanism referenced from VOL-20/§24 rather than redefined here.

The governing law for all three chapters is fixed by the Architecture Constitution: AC-19 (determinism), AC-20 (budget derived from the catalog SSOT, AGI-AI-0001), and the §19 trust rule. This book elaborates that law into a runtime contract; it does not amend it.

## Goals

- Specify the **five source classes** and a single **deterministic precedence** over them, such that fixed inputs yield identical context (AC-19).
- Bind the **token budget** that governs assembly to the model's declared context window in the catalog SSOT (AC-20, AGI-AI-0001), and forbid hardcoded, invented, or guessed budgets.
- Enumerate every observed source of **ambient nondeterminism** in the current assemblers and define the contract clause that eliminates each.
- Define **cross-trust-boundary read scoping** so that assembly itself — not only routing — is gated by the turn's trust boundary (§19 trust rule, AGI-TRUST-0001).
- Provide a **Migration** path from the current per-surface assemblers to one shared deterministic assembler.
- Keep the book's claims **evidence-grounded**: every current-state statement is labeled **Current** and cites implementation; every forward statement is labeled **Target** or **Migration**.

## Definitions

- **Context.** The derived, read-only assembled view of session, memory, and storage state that is handed to a model for a single turn. It owns no durable state (§19 framing).
- **Context assembly.** The deterministic function that maps fixed inputs (conversation, memory corpus, project, token budget, model context window) to an assembled context (AC-19).
- **Source class.** One of the five categories of content that may be packed into context: conversation, memory, project knowledge, tool results, instructions.
- **Source-packing order.** The deterministic precedence by which source classes are composed into the token budget; the subject of CH-11.01.01.
- **Token budget.** The bound on assembled-context size, derived from the model's declared `contextWindow` field in the catalog SSOT (AC-20, AGI-AI-0001).
- **Context window.** The model's declared maximum context size, sourced exclusively from `packages/contracts/types/src/models.json` via `ModelMetadata.contextWindow` (model-catalog.ts:104).
- **Catalog SSOT (AGI-AI-0001).** The single source of truth for model facts, `packages/contracts/types/src/models.json`, carrying a `contextWindow` field per model entry (models.json:1-30).
- **Trust boundary.** The Local / BYOK / Managed isolation level a turn is authorized for; assembly must not read across it without explicit authorization (§19 trust rule, AGI-TRUST-0001).
- **Local-origin content.** State produced under the Local trust boundary — local conversations, memory, project instructions, and developer-session material — that a managed turn must not silently assemble.
- **Ambient nondeterminism.** Any input to assembly that varies across otherwise-identical turns and is not a declared input — for example, wall-clock time, random nonces, or unordered hash-map iteration.
- **Declared input.** An assembly input that is named in the contract and reproducible given the fixed input set — including decay and recency, which are admitted only when supplied as declared inputs rather than read from ambient state.

## Architecture

### Chapter CH-11.01.01 — Source taxonomy & packing precedence

**Target.** Context is composed from exactly **five source classes**, packed in a single deterministic precedence:

1. **Instructions** — system prompts and user/project directives that frame the turn.
2. **Memory** — facts, preferences, and decisions promoted from prior sessions (the memory corpus, ordered by VOL-12 before packing).
3. **Project knowledge** — workspace instruction files, project metadata, and retrieved corpus content (RAG packing mechanics deferred to BK-11.04).
4. **Tool results** — outputs of tool calls returned into the turn.
5. **Conversation** — the message history of the current session.

The precedence is normative: instructions and memory establish stable, cacheable framing first; conversation history is appended last so that the volatile tail of the turn does not perturb the cacheable prefix. The order must be fixed so that identical inputs produce an identical byte sequence (AC-19).

**Current (desktop) — a concrete packing order exists and is largely deterministic.** The desktop assembler packs system content in a fixed sequence before appending history: default system prompt first (send_message_setup.rs:199-206), then memory context as a second system message (send_message_setup.rs:211-219), then OS context (send_message_setup.rs:221-232), then conditional project context (send_message_setup.rs:234-252), then a coding system prompt (send_message_setup.rs:254-269), then custom instructions (send_message_setup.rs:272-288), then browser page context (send_message_setup.rs:290), then up to two matching skills (send_message_setup.rs:291-297), then history appended after all system blocks (send_message_setup.rs:314-319), with the tool catalog injected last (send_message_setup.rs:330-358). The frontend likewise merges instruction-class sources in a fixed sequence — memory, personalization, project instructions, knowledge base, file context, slash instructions (chat/index.tsx:1040-1139). This is the closest current implementation to the Target precedence and is the reference worked example.

**Current (web) — only four of five classes are present.** The web surface assembles conversation (message history), memory (client-side only), tool results (`tool_result` content blocks in `mapMessagesToAnthropic`, anthropic.ts:533-650), and instructions (system messages). **Project knowledge / RAG is absent** — there is no document injection, knowledge-base query, or file-context assembly path; a grep over the API surface yields only a caching heuristic, not assembly code (web Gaps, factory.ts:346). Memory itself is assembled only in `WebChatRuntime` via `buildMemorySystemContent()` + `withMemorySystemMessage()` (WebChatRuntime.ts:126-127); server-side v1/v2 routes perform no memory assembly, so direct API callers bypass the memory source class entirely.

**Current (CLI / mobile / VSCode) — partial and non-uniform.** The CLI assembles a `SystemContext` (OS/shell/cwd/git/project markers) deterministically at startup (context.rs:1-57) and composes instructions, memory, rules, and skills from disk in `assemble_system_prompt` (prompt.rs:61-110). Mobile and VSCode gather context but expose no explicit source-class taxonomy at the assembly layer (cli-mobile-vscode Gaps). No surface today tracks which source class consumes which fraction of the budget.

**Migration.** Converge all surfaces on the five-class taxonomy and the single Target precedence. The immediate steps: (1) add the missing **project-knowledge** source class to web so all five classes are representable; (2) lift web memory assembly out of the client into the shared assembler so direct API callers receive the same context; (3) replace per-surface ad-hoc ordering with the one canonical precedence. RAG packing within the project-knowledge class is specified by BK-11.04, not here.

### Chapter CH-11.01.02 — Deterministic assembly contract

**Target.** Assembly is a pure deterministic function: fixed conversation, memory corpus, project, token budget, and model context window yield an identical assembled context (AC-19). The token budget is derived from the model's declared `contextWindow` in the catalog SSOT (AC-20, AGI-AI-0001) — never hardcoded, invented, or guessed. **No ambient nondeterminism** may enter the assembly path: no wall-clock reads, no per-call random values, no unordered iteration. **Decay and recency** may influence ordering only when supplied as **declared inputs** to the function, never read from ambient state at assembly time.

**Current — budget derivation is partially SSOT-bound, with stale-fallback gaps.** Web derives the context window from the catalog via `getModelMetadataById()` → `ModelMetadata.contextWindow` (model-catalog.ts:287-296), satisfying AC-20 for catalog-known models. However, `getModelContextWindow()` carries a hardcoded prefix-match fallback (claude-=200K, gemini-=1M, gpt-=128K) that overrides the catalog when a model is absent from the index (context-management.ts:73-81); this returns 200K for both `claude-opus-4.8` (catalog: 1,000,000) and `claude-sonnet-4.6` (catalog: 200,000), violating AC-20 when the fallback executes. Desktop resolves the window from `models_config::config().models` (context_monitor.rs:268-276) but falls back to a hardcoded `DEFAULT_CONTEXT_WINDOW = 128_000` (context_monitor.rs:44; context_compactor.rs:32), and `CompactionConfig::max_tokens` is a hardcoded `100_000` decoupled from the SSOT window (context_compactor.rs:7-40). CLI derives the window from the shared catalog via `model_catalog::context_window()` (compaction.rs:143-150) and is AC-20-compliant; mobile derives it from `MODEL_LIST` (contextBudgeter.ts:43-49); VSCode reads a local hardcoded `MODEL_CONTEXT_LIMITS` dictionary rather than the shared catalog and is non-compliant (contextBudget.ts:13-17).

**Current — observed ambient-nondeterminism violations.** The contract clause "no ambient nondeterminism" is violated in the present assemblers:

- **Wall-clock in tool-use IDs.** Web generates Anthropic `tool_use` IDs via `Date.now()` when the caller does not supply one (`id: tc.id || \`call\_${Date.now()}\``, anthropic.ts:602), making the assembled message bytes vary across identical turns.
- **Per-call random nonce.** Desktop tool injection generates a fresh UUID-based nonce per call (prompt_tool_injection.rs:198); identical conversations therefore produce non-identical assembled context. The nonce is a security control (FIX-015) and is intentional, but its per-call randomness is an AC-19 violation that the contract must reconcile (e.g., by deriving the nonce deterministically from declared inputs).
- **Unordered hash-map iteration.** Desktop project-context file counts iterate a `HashMap` and sort by count with no tiebreaker (project_context.rs:539-541); equal counts order non-deterministically.
- **Untiebroken ranking.** Desktop skill selection ranks by Jaccard score and truncates to the top two with no secondary tiebreaker (send_message_setup.rs:659-730); equal scores select non-deterministically.

**Current — two parallel assembly paths.** Web compaction is wired only in the v2 AI-SDK route; the v1 fallback and base providers perform no compaction (route.ts:768-798; factory.ts). Desktop runs two distinct `ContextManager` implementations (core/agi and core/agent, context_manager.rs:7-12 and :81-109). The determinism contract is therefore satisfied only partially and only on one of each surface's paths.

**Migration.** Make assembly a single pure function on every surface: (1) remove the web prefix-match fallback and resolve every window from the catalog SSOT, marking truly-unknown models as an explicit tracked gap rather than a hardcoded default; (2) make the desktop fallback and `max_tokens` a function of the SSOT window rather than standalone constants; (3) point VSCode at the shared catalog; (4) eliminate wall-clock and per-call random inputs from the assembled bytes, replacing them with declared-input derivations; (5) add deterministic tiebreakers (insertion order or stable name sort) to every ranking and hash-map iteration; (6) collapse the parallel v1/v2 and agi/agent paths into one assembler.

### Chapter CH-11.01.03 — Cross-trust-boundary read scoping

**Target.** Assembly is gated by the turn's trust boundary, not only routing. A **managed turn MUST NOT silently assemble local-origin content**; a **local/BYOK turn MUST NOT pull from the shared cloud store** (§19 trust rule, AGI-TRUST-0001). The boundary check happens **before** any source class is read, so that local instructions, local memory, and local project knowledge are never composed into a managed view. Crossing the boundary is permitted only through the explicit fork/continuation mechanism — context selection, secret scan, payload preview, consent, and visible provider label — whose mechanics are owned by **VOL-20/§24** and referenced, not redefined, here.

**Current — assembly is not gated by trust boundary on either primary surface.** On web, the managed-compute gate validates `providerMode` at the handler level but does not condition message assembly; the same message history is sent regardless of trust origin (route.ts:624-661 gates features but not assembly; WebChatRuntime.ts:126-127 injects memory client-side with no mode check). On desktop, cloud **sync** is correctly gated — `derive_cloud_sync_enabled()` forces `cloud_sync_enabled=false` when `active_mode='local'` (send_message_setup.rs:57-70) — but **context assembly itself is not gated**: local-origin sources (project instructions, memory) are assembled at send_message_setup.rs:199-358 before the routing decision is made, so the assembled `LLMRequest` already contains local-origin content when the managed router receives it. The routing-layer `local_only` flag in `RouterPreferences` prevents routing to managed cloud (send_message_setup.rs:148-164) but does not prevent local content from being packed in the first place. The CLI does mark external/untrusted sources with an `encode_untrusted_context()` JSON envelope (prompt.rs:44-57), which is a related but distinct control (untrusted-data framing, not trust-boundary scoping); mobile and VSCode have no trust-boundary framing for assembled content.

**Current — no persisted trust-boundary annotation.** Desktop derives `cloud_sync_enabled` as a pure function but does not attach the resulting boundary to the assembled context or `LLMRequest` metadata (send_message_setup.rs:64-70); there is no audit trail recording which boundary an assembly operated under. Memory promotion likewise carries optional source and project tags but no trust annotation (conversation_summarizer.rs:466-480), so a local-origin memory could in principle be promoted without a boundary marker.

**Migration.** Move the trust-boundary check upstream of source reads: (1) resolve the turn's boundary first; (2) admit only sources whose origin matches the authorized boundary into the assembled context; (3) attach the resolved boundary to the assembled-context metadata for audit; (4) route any genuine cross-boundary need through the explicit fork path owned by VOL-20/§24; (5) tag promoted memories with their origin boundary so the local→cloud promotion path cannot silently cross. The egress mechanism is referenced from VOL-20/§24 and is out of scope for this book.

## Design Principles

The following principles derive directly from the governing law and bind every chapter of this book.

- **P1 — Determinism is the precondition (AC-19).** Fixed conversation, memory corpus, project, token budget, and model context window must yield an identical assembled context. Determinism is what makes capability claims reproducible and behavior explainable; it is not an optimization but a contract.

- **P2 — The budget comes from the SSOT (AC-20, AGI-AI-0001).** The token budget governing assembly and compaction is derived from the model's declared `contextWindow` in `packages/contracts/types/src/models.json`. No surface may hardcode, invent, or guess a window. Where the catalog lacks a model, the gap is tracked explicitly, not papered over with a stale default.

- **P3 — Context is derived, never authoritative (§19 framing).** Assembly owns no durable state. It is a read-only function of the session, memory, and storage planes. Any durable effect (such as memory promotion) is a separate write governed by its own owner (VOL-12), not a side effect of assembly.

- **P4 — No ambient nondeterminism.** Wall-clock reads, per-call random values, and unordered iteration must not enter the assembled bytes. Recency and decay are admitted only as declared inputs supplied to the assembly function, never sampled from ambient state at assembly time.

- **P5 — Trust-boundary scoping precedes source reading (§19 trust rule, AGI-TRUST-0001).** The authorized boundary of the turn is resolved before any source class is read. A managed turn never assembles local-origin content; a local/BYOK turn never pulls from the shared cloud store. Crossing the boundary is only ever an explicit, consented fork via VOL-20/§24.

- **P6 — Fixed precedence over the five classes.** The five source classes are packed in one normative order so that the cacheable prefix (instructions, memory) is stable and the volatile tail (conversation) is appended last. Stable ordering is a determinism requirement (P1), not a stylistic choice.

- **P7 — One assembler, many surfaces (Target).** The Target is a single deterministic shared assembler that every surface invokes, replacing the current per-surface, multi-path implementations. The book's Current/Target/Migration labeling exists to drive that convergence without overstating today's state.

**Current — CLI / mobile / VSCode.** CLI assembles `SystemContext` (OS/shell/cwd/git/project markers) deterministically at startup (`apps/cli/src/context.rs:1-57`) and assembles the system prompt from disk-loaded instructions, memory, rules, and skills (`apps/cli/src/agent/prompt.rs:61-110`); its budget is derived from the shared catalog via `context_limit()` → `model_catalog::context_window(model)` with a `DEFAULT_CONTEXT_LIMIT = 128_000` fallback (`apps/cli/src/compaction.rs:143-150`), AC-20-compliant on a hit. Mobile's `contextBudgeter.ts` is model-aware via `getModelById(modelId)` from `MODEL_LIST` (`apps/mobile/src/features/memory/services/contextBudgeter.ts:43-49`), AC-20-compliant, but only tracks/warns — it performs no compaction and is not wired into the memory CRUD service (`apps/mobile/src/features/memory/services/memory.ts:1-98`). VSCode reads `MODEL_CONTEXT_LIMITS` as a local hardcoded constant rather than the shared catalog (`apps/extension-vscode/src/data/contextBudget.ts:13-17`), which is AC-20-non-compliant, and its context gatherer applies fixed character caps (`MAX_GIT_DIFF_CHARS=2000`, `MAX_FILE_TREE_CHARS=1500`, `MAX_DIAGNOSTICS=20`) that do not reference the budget module (`apps/extension-vscode/src/data/contextBuilder.ts:21-28`).

**Current — determinism defects (AC-19).** Several ambient-nondeterminism sources exist in the assembly paths today: web generates tool_use IDs via `Date.now()` when the caller omits an ID (`apps/web/lib/llm-providers/anthropic.ts:602`); desktop injects a per-call random nonce into the tool catalog (`apps/desktop/src-tauri/src/core/llm/prompt_tool_injection.rs:198`), orders project file-type counts from an unordered HashMap with no secondary tiebreaker (`apps/desktop/src-tauri/src/sys/commands/project_context.rs:539-541`), and ranks injected skills by similarity score with no tiebreaker for equal scores (`apps/desktop/src-tauri/src/sys/commands/chat/send_message_setup.rs:659-730`). Each makes two identical input conversations produce non-identical assembled context, contrary to AC-19.

## Target State

**Target.** One deterministic shared assembler replaces the per-surface assemblers. It exposes a single canonical source-packing order over the five source classes (conversation, memory, project knowledge, tool results, instructions; CH-11.01.01), derives its token budget exclusively from the model's declared context window in the catalog SSOT (AGI-AI-0001; AC-20) with no prefix-match or hardcoded fallback, and produces byte-identical context for fixed inputs (fixed conversation, memory corpus, project, token budget, model context window) per AC-19. The shared assembler is the single owner of packing precedence; per-surface code supplies inputs and consumes the assembled context but does not re-implement the order or the budget derivation. This unified assembler does not exist today: VOL-11/BK-11.01–11.04 are roadmap-planned, not yet built (`docs/00-foundation/master-documentation-roadmap.md:1267-1303`). The contract is specified here abstractly; no concrete function signature for it is asserted as present.

**Target.** The assembler is trust-boundary-aware at the assembly layer, not only at the routing/sync layer (CH-11.01.03; §19 trust rule; AGI-TRUST-0001): a managed turn MUST NOT assemble local-origin content and a local/BYOK turn MUST NOT pull from the shared cloud store, with the boundary checked per turn before any source is packed. The egress mechanism that enforces a payload leaving a boundary is referenced from VOL-20/§24 and is not redefined here.

**Target.** Determinism is structural: tool_use IDs, tool-catalog framing, file-type ordering, and source ranking are all derived deterministically from the inputs (stable tiebreakers, no wall-clock or random seed in the assembly path), so the AC-19 contract holds across all surfaces. Compaction modes/thresholds and summarization cadence remain owned by BK-11.02 and BK-11.03; the Target assembler consumes a budget and a trigger derived from the catalog rather than from per-surface constants.

## Migration Strategy

**Migration.** Convergence proceeds without breaking trust boundaries, in dependency order. First, make budget derivation uniform and SSOT-only: remove web's prefix-match fallback branch (`apps/web/lib/llm-providers/context-management.ts:73-81`), VSCode's local `MODEL_CONTEXT_LIMITS` (`apps/extension-vscode/src/data/contextBudget.ts:13-17`), and the hardcoded `DEFAULT_CONTEXT_WINDOW`/`DEFAULT_CONTEXT_LIMIT` defaults (`apps/desktop/src-tauri/src/sys/commands/chat/context_monitor.rs:268-276`; `apps/cli/src/compaction.rs:143-150`), so every surface reads `contextWindow` from AGI-AI-0001 only — satisfying AC-20 on all paths, not only on catalog hits. Second, collapse web's dual trigger: retire dead `shouldCompact()` (`apps/web/lib/llm-providers/context-management.ts:106-111`) or wire it as the single trigger, eliminating the 60%-inline / 80%-documented split (`apps/web/app/api/llm/v2/chat/route.ts:775-776`). Third, remove the AC-19 nondeterminism sources (the `Date.now()` ID at `apps/web/lib/llm-providers/anthropic.ts:602`; the random nonce, HashMap ordering, and skills tiebreaker on desktop) by deriving each deterministically from inputs.

**Migration.** The packing order is extracted into one shared module and the per-surface assemblers become thin adapters that feed it inputs; desktop's two `ContextManager` implementations (`apps/desktop/src-tauri/src/core/agi/context_manager.rs:7-12`; `apps/desktop/src-tauri/src/core/agent/context_manager.rs:81-109`) and web's v1/v2 split collapse onto it. Trust-boundary scoping is added at the assembly layer: the existing per-surface boundary signals — desktop's `derive_cloud_sync_enabled()`/`resolve_request_flags()` (`apps/desktop/src-tauri/src/sys/commands/chat/send_message_setup.rs:57-70`) and web's managed-compute gate (`apps/web/app/api/llm/v2/chat/route.ts:624-661`) — are promoted from routing/feature gates to gates that condition which sources the assembler may read, before assembly (which today packs local sources at `apps/desktop/src-tauri/src/sys/commands/chat/send_message_setup.rs:199-358` prior to the routing decision). This is staged surface-by-surface so a partially migrated surface still enforces the boundary at its existing routing/sync layer and never regresses to cross-boundary reads. Migration is complete only when a cross-runtime equivalence check confirms identical assembled context for identical inputs; no such CI guard exists today (`docs/00-foundation/architecture-constitution.md:1004`).

## Data Flow

**Current — web.** A user message flows through `WebChatRuntime.sendMessage()` → `buildMemorySystemContent(memory.facts)` + `withMemorySystemMessage(history)` → POST to the chat completions endpoint with a memory-injected history (`apps/web/.../WebChatRuntime.ts:126-127`). At the v2 route, `estimateTokenCount(messages)` is compared against 60% of `getModelContextWindow()`; if exceeded, `buildAnthropicContextManagement(mode='compact')` is computed and streamed to Anthropic with the `compact-2026-01-12` beta header (`apps/web/app/api/llm/v2/chat/route.ts:768-798`). The v1 fallback path does the same token estimation but emits no compaction object.

**Current — desktop.** `prepare_send_message()` packs sources in fixed sequence — default system prompt → memory context → OS context → project context → coding system prompt → custom instructions → browser page context → matching skills → history → tool catalog (`apps/desktop/src-tauri/src/sys/commands/chat/send_message_setup.rs:199-358`). The assembled messages are token-counted, then `maybe_compact_context()` resolves the window from the catalog and triggers compaction at 95% (`apps/desktop/src-tauri/src/sys/commands/chat/context_monitor.rs:108-151`). The summary-generation step is deferred to BK-11.02.

**Current — CLI / mobile / VSCode.** CLI gathers `SystemContext`, assembles the prompt, then checks usage post-assembly and compacts when over budget (`apps/cli/src/agent/prompt.rs:61-110`; `apps/cli/src/compaction.rs:143-150`). Mobile computes `ContextBudget` from `getModelById(modelId).contextWindow` and emits an `ok|warn|compact` status without acting (`apps/mobile/src/features/memory/services/contextBudgeter.ts:32-79`). VSCode gathers workspace context under fixed char caps and computes a percent-mode budget independently of the gatherer (`apps/extension-vscode/src/data/contextBuilder.ts:64-378`; `apps/extension-vscode/src/data/contextBudget.ts:47-72`).

## Control Flow

**Current.** Compaction control flow exists only on web v2 and desktop; CLI checks post-assembly; mobile/VSCode only track. Desktop's control gate requires three conditions in conjunction — threshold (95%), minimum messages (`>= 12`), and a 120s cooldown — before compacting (`apps/desktop/src-tauri/src/sys/commands/chat/context_monitor.rs:95-151`), then emits Tauri events (`compaction:auto-triggered`, `compaction:completed`, legacy `chat:context-compacted`) around the operation (`apps/desktop/src-tauri/src/sys/commands/chat/context_monitor.rs:164-173,241-263`). The decision-to-compact logic and summary construction are owned by BK-11.02; this book records only that the control gate runs at the cited threshold and that no trust-boundary check conditions source selection before assembly (`apps/desktop/src-tauri/src/sys/commands/chat/send_message_setup.rs:199-358`).

**Target.** Control flow runs the trust-boundary check first (per turn, before any source is packed; §19 trust rule, AGI-TRUST-0001), then packs in the canonical order, then applies the SSOT-derived budget/trigger — uniform across surfaces.

## State Flow

**Current/Target.** Per §19, context is DERIVED and owns no durable state: it is a deterministic function of the session, memory, and storage planes and is reconstructed each turn. The one place this needs care is desktop compaction, which writes back to the authoritative session/storage plane — `persist_auto_compaction()` runs a SQLite transaction that DELETEs the superseded messages and INSERTs the summary message (`apps/desktop/src-tauri/src/sys/commands/chat/context_monitor.rs:313-393`). This is a write to the session plane, not context holding durable state; the assembler still owns nothing and re-derives the assembled view from the (now-compacted) plane on the next turn. Memory promotion is likewise a write-only output to the memory plane (VOL-12), not assembler-owned state. The §19 framing holds in both Current and Target: the assembler is a stateless deterministic projection of the underlying planes, and any persistence it triggers lands in those planes, never in the context itself.

## Failure Modes

This section enumerates the ways deterministic context assembly can fail in the current multi-path implementation, classified by the governing-law invariant each failure violates (AC-19 determinism, AC-20 budget-from-SSOT, §19 trust rule).

**Current — ambient nondeterminism breaks AC-19.** Two assembly paths inject non-reproducible content into the assembled context for otherwise fixed inputs:

- **Wall-clock identifiers (web).** When a caller-supplied tool-call id is absent, the Anthropic message mapper synthesizes one from `Date.now()` (`apps/web/lib/llm-providers/anthropic.ts:602`: `id: tc.id || \`call\_${Date.now()}\``). Identical conversations assembled at two instants produce two different `tool_use` blocks, violating the AC-19 fixed-inputs-to-identical-context contract.
- **Per-call random nonce (desktop).** Tool-catalog injection wraps the tool block in a per-call random nonce (`apps/desktop/src-tauri/src/core/llm/prompt_tool_injection.rs:198`, `build_injection_nonce()`), and the nonce is stripped from user content beforehand (`prompt_tool_injection.rs:205`). The nonce is a deliberate FIX-015 prompt-injection defense (`prompt_tool_injection.rs:193-197`), but because it is random per call, identical input conversations assemble to non-identical system content — an AC-19 violation as a side effect of a security control.
- **Wall-clock trigger state (desktop).** Auto-compaction consults a process-global cooldown map keyed by conversation holding a wall-clock `Instant` (`apps/desktop/src-tauri/src/sys/commands/chat/context_monitor.rs:48-49`, `LAST_COMPACT_TIMES`), with the trigger gated on 120s elapsed (`context_monitor.rs:118-127`). Whether the same fixed inputs produce a compacted or non-compacted assembled context therefore depends on elapsed wall-clock time, which is not a declared assembly input. This is the assembly trigger's determinism failure mode; the compaction algorithm itself is owned by BK-11.02.
- **Undefined collection ordering (desktop packing).** Project-context file-type aggregation iterates a `HashMap` and sorts by count only, with no secondary tiebreaker (`apps/desktop/src-tauri/src/sys/commands/project_context.rs:515,539-541`); skill selection ranks by Jaccard score and truncates to the top two with no secondary tiebreaker (`apps/desktop/src-tauri/src/sys/commands/chat/send_message_setup.rs:659-730`). When counts or scores tie, the packed order is non-deterministic.

**Current — budget derivation can desync from SSOT (AC-20 concern).** The web `getModelContextWindow()` fallback branch (`apps/web/lib/llm-providers/context-management.ts:73-81`) returns hardcoded prefix-match defaults (`claude-`→200K, `gemini-`→1M, `gpt-5`→128K, `grok-`→128K, `deepseek`→64K, `sonar`→127K) for any model id absent from `getModelMetadataById()`. When this branch fires, the budget is no longer derived from `packages/contracts/types/src/models.json:contextWindow` (AGI-AI-0001), so the catalog and the live budget can diverge — the brief's example is `claude-opus-4.8` at 1M in the catalog vs. 200K from the prefix match, a 5× underestimate. The desktop equivalent is `DEFAULT_CONTEXT_WINDOW = 128_000` (`context_monitor.rs:44`).

**Current — incomplete source coverage and path divergence.** Project-knowledge / RAG is absent on web (only 4 of 5 source classes present per CH-11.01.01; grep over `apps/web/app/api` yields no assembly code). Memory is assembled only client-side in `WebChatRuntime` (`apps/web/.../WebChatRuntime.ts:126-127`) and not in v1/v2 API routes, so direct API callers silently bypass the memory source class. Compaction is wired only in the v2 AI-SDK path (`apps/web/.../route.ts:768-798`); the v1 fallback performs token estimation but no compaction, so v1 contexts can grow unbounded. These are not crashes — they are silent assembly-correctness failures where the assembled context is missing a source class or an over-budget guard.

**Target.** One shared deterministic assembler with a single source-packing order, no ambient nondeterminism (caller-supplied or content-hashed ids instead of `Date.now()`; deterministic nonce derivation or boundary marking that does not vary the assembled bytes per call), total ordering on every collection-derived source, and budget always derived from the catalog SSOT per AC-20 with no hardcoded fallback that overrides it.

**Migration.** Eliminate the AC-19 ambient-nondeterminism sources first (replace `Date.now()` ids; make nonce/ordering deterministic), then remove the AC-20-violating hardcoded fallbacks in favor of catalog lookup with an explicit, logged unknown-model handling, then converge the web v1/v2 and desktop core/agi-vs-core/agent paths onto the single ordering. Detail of compaction triggers and modes is deferred to BK-11.02.

## Recovery

**Current.** The only context-assembly recovery mechanism present in evidence is desktop compaction-persistence atomicity. `persist_auto_compaction()` runs inside a SQLite transaction that deletes superseded messages, inserts the summary message, and commits; failure rolls the transaction back (`apps/desktop/src-tauri/src/sys/commands/chat/context_monitor.rs:313-393`). This guarantees the persisted conversation never lands in a half-compacted state: either the summary replaces the old messages atomically, or the prior history is preserved intact.

**Current — recovery gap.** The compaction summary is persisted with a temporary id (`id=0`) and `CompactionResult.summary_message_id` is `None` (`apps/desktop/src-tauri/src/core/agent/context_compactor.rs:158-164,279-293`; `context_monitor.rs:320-324`); the persist path uses no `RETURNING` clause to capture the inserted id, and no foreign-key relationship links the deleted messages to their summary. Compaction is therefore opaque to later audit or point-in-time reconstruction: once old messages are deleted, there is no durable linkage back to what was summarized. Because context is derived and owns no durable state (§19 framing), the durable record of what happened lives in the storage plane, and that linkage is what is missing.

**Target.** A recovery contract in which every compaction event records, durably and in the storage plane, the id of the inserted summary and a reference set of the messages it replaced, so that an assembled context can be reconstructed or rolled forward deterministically (AC-19) from the session and storage planes after any compaction. The assembler itself remains a pure derivation and holds no recovery state of its own.

**Migration.** Capture the inserted summary id (e.g., via `RETURNING`) into `CompactionResult.summary_message_id`, and add the summary-to-replaced-messages linkage at persist time, before broadening the same atomic-persist-plus-linkage pattern to any future shared assembler path. Summarization cadence and what is promoted to the memory runtime are owned by BK-11.03 and VOL-12.

## Security

Security here concerns the integrity of the assembled context against adversarial content, distinct from the Local/BYOK/Managed trust-boundary read scoping covered under Privacy.

**Current — prompt-injection defenses at assembly.** Two surfaces harden the assembly boundary against content that tries to forge instructions or tool catalogs:

- **Desktop nonce isolation (FIX-015).** Tool-catalog injection wraps the catalog in a per-call random nonce and strips the nonce from all user messages before injection, so a model jailbroken via attachment text cannot forge a fake tool catalog inside its own reply (`apps/desktop/src-tauri/src/core/llm/prompt_tool_injection.rs:193-206`). This is intentional and is the cause of the AC-19 nondeterminism noted under Failure Modes — a security/determinism tension to be resolved in the Target, not by removing the defense.
- **CLI untrusted-data framing.** The CLI wraps external sources (memory, instructions, skills, rules) in a JSON envelope flagged `untrusted_data` with security notes via `encode_untrusted_context()` (`apps/cli/src/agent/prompt.rs:44-57,166-208`), and neutralizes certain instruction-marker patterns (`apps/cli/src/agent/prompt.rs:20-42`). This is prompt-injection framing for content provenance — it is not the Local/BYOK/Managed trust boundary.

**Current — security gaps.** Secret redaction is partial and per-surface: the CLI marker-neutralization does not redact secrets (`apps/cli/src/agent/prompt.rs:20-42`), and the VSCode context builder calls `redactSecrets()` only for the git diff, not for other gathered sources (`apps/extension-vscode/src/data/contextBuilder.ts:207`). Web and desktop assembly paths show no equivalent assembly-time secret-redaction control in evidence.

**Target.** A uniform, assembly-time content-provenance and secret-redaction contract applied to every untrusted source class across the single shared assembler, with a prompt-injection defense (nonce or equivalent) that does not perturb the assembled bytes per call (preserving AC-19).

**Migration.** Generalize the CLI untrusted-data envelope and a single `redactSecrets`-equivalent pass to every external source on every surface as the assemblers converge, and replace the per-call random nonce with a deterministic boundary mechanism. Egress-side secret scanning at the Local→BYOK fork is owned by VOL-20/§24 and is referenced, not redefined here.

## Privacy

Privacy in this book is trust-boundary read scoping at context assembly: a managed turn MUST NOT silently assemble local-origin content, and a Local/BYOK turn MUST NOT pull from the shared cloud store (§19 trust rule, AGI-TRUST-0001). This is the CH-11.01.03 locus.

**Current — the property holds today only via downstream gates, not via assembly-layer read scoping.** Desktop derives `cloud_sync_enabled = false` whenever `active_mode='local'`, regardless of the user's storage-mode preference (`apps/desktop/src-tauri/src/sys/commands/chat/send_message_setup.rs:57-70`), and `RouterPreferences` carries a `local_only` flag that prevents routing a local turn to a managed-cloud provider (`send_message_setup.rs:148-164`). These gate **storage/sync** and **routing** respectively. They do not gate the **assembly read**: the message-packing logic assembles local-origin sources (default prompt, memory, OS, project context, instructions, history) without first checking `flags.is_local_mode` (`send_message_setup.rs:199-358`). The §19-trust-rule property is satisfied at runtime only because the routing and sync gates downstream prevent local-origin content from reaching a managed provider or the shared store — not because the assembler itself scopes its reads by trust boundary.

**Current — web is simply unenforced.** Server-side context assembly is not gated by provider mode: the managed-compute gate validates `providerMode` but does not condition message building (`apps/web/.../route.ts:624-661`), and the same message history is assembled for Local, BYOK, and Managed callers. Client-side memory injection performs no mode check (`apps/web/.../WebChatRuntime.ts:126-127`).

**Current — desktop also lacks trust-boundary tagging on derived/promoted state.** The derived `cloud_sync_enabled` value is not attached to the assembled context or `LLMRequest` metadata (`send_message_setup.rs:64-70`), and memory promotion stores optional source/project references with no trust-boundary annotation (`apps/desktop/src-tauri/src/core/agi/conversation_summarizer.rs:466-480`). There is no audit trail recording which boundary a given assembly operated in.

The accurate statement is therefore: **no surface enforces trust-boundary read scoping at the assembly layer today (Current gap).** Unified assembly-layer enforcement is **Target**.

**Target.** The shared assembler reads its source set as a function of the turn's authorized trust boundary: a managed turn never reads local-origin sources, and a Local/BYOK turn never reads the shared cloud store, enforced at the point of assembly rather than relying solely on downstream routing/sync gates (§19 trust rule, AGI-TRUST-0001). The assembled context carries its boundary as metadata for audit.

**Migration.** Thread the already-derived boundary signal (`is_local_mode` / `cloud_sync_enabled`) into the assembler so it scopes reads before packing, attach the boundary to the assembled-context metadata, and add the per-turn audit record — converging web (which has no gate) and desktop (which gates only downstream) onto one read-scoped assembler. The egress mechanism for an explicit Local→BYOK fork is referenced from VOL-20/§24.

## Performance

Performance covers assembly latency and token-budget efficiency. Both are dominated by token estimation (which decides whether the expensive compaction path runs) and by prompt-cache reuse (which governs per-request cost on Anthropic).

**Current — token estimation is a fixed heuristic, not a tokenizer.** Web estimates `ceil(text.length / 3.5) + 4` tokens per message (`apps/web/lib/llm-providers/context-management.ts:90-98`); desktop, CLI, mobile, and VSCode use a 4-chars-per-token approximation (desktop `estimate_tokens` divides by 4, `apps/desktop/src-tauri/src/core/agent/context_compactor.rs:268-270`; CLI `BYTES_PER_TOKEN=4`, `apps/cli/src/compaction.rs:20`; mobile/VSCode `CHARS_PER_TOKEN=4`). No surface uses a provider-specific tokenizer. This keeps assembly latency low (a linear character scan rather than tokenization) but means the estimate that gates compaction — and, on web, that feeds credit cost estimation (`apps/web/.../route.ts:865-869`) — can diverge from the provider's true token count, triggering compaction early or late.

**Current — prompt caching governs token-budget efficiency on Anthropic.** Cache eligibility is gated on model capability (from the catalog) plus a substantial-system-prompt (>~1000 tokens) or document/RAG (>~500 tokens) heuristic (`apps/web/lib/llm-providers/prompt-cache-helper.ts:17-68`). Cache control is resolved once per request and explicitly not re-evaluated mid-session (`apps/web/lib/llm-providers/anthropic.ts:183-190`). A stable-prefix upgrade caches tools + system at 1h TTL when caching is on, tools are present, and `cacheRetention` was not explicitly set; one-shot (no-tools) requests stay at the 5m default to avoid paying the 2.0× write multiplier on unreused content (`anthropic.ts:206-217`). Cache breakpoints are bounded to at most one per tools array and four total to stay within Anthropic's limit (`anthropic.ts:107-124`). These choices trade cache-write cost against reuse, and the once-per-request stability rule keeps the cached prefix from thrashing.

**Current — compaction is the latency-bearing path and is gated.** Desktop gates auto-compaction on three conditions before doing any summarization work — token threshold, a minimum message count, and the 120s cooldown (`apps/desktop/src-tauri/src/sys/commands/chat/context_monitor.rs:95-151`) — and emits progress events around it (see Observability). The cooldown specifically bounds how often the expensive summarization path can run per conversation.

**Target.** Token-budget efficiency that does not depend on a single global character ratio: per-provider token accounting accurate enough that the compaction trigger and any credit estimation derive from a consistent count, so AC-20-derived budgets are spent precisely. Compaction-algorithm performance characteristics are owned by BK-11.02.

## Scalability

The Target architecture treats the assembler as stateless (AC-107). The defensible anchor for this property is §19 framing: context is derived, never authoritative, and owns no durable state — it is a deterministic function of the session, memory, and storage planes (`docs/00-foundation/architecture-constitution.md:301-303`). A stateless assembler scales horizontally because any worker can assemble any turn from those planes alone.

**Current — the web assembly path is effectively stateless and scales accordingly.** The v1/v2 API routes do not re-assemble context from server-held state; they receive pre-assembled history and derive the budget and compaction decision per request from the model catalog and the message payload (`apps/web/lib/llm-providers/context-management.ts:64-67`; `apps/web/.../route.ts:768-798`). There is no per-conversation server-side assembly state to coordinate.

**Current — the desktop compaction path holds process-local mutable state, which is in tension with the stateless Target.** The auto-compaction trigger consults `LAST_COMPACT_TIMES`, a process-global `Mutex<HashMap<i64, Instant>>` keyed by conversation holding wall-clock instants (`apps/desktop/src-tauri/src/sys/commands/chat/context_monitor.rs:48-49`). On the single-process desktop runtime this is sound, but it makes the trigger decision a function of process-local state rather than purely of the planes; lifted to a multi-worker setting it would not be coordinated across workers, and it is the same wall-clock state that underlies the AC-19 trigger-determinism concern noted under Failure Modes. Additionally, desktop maintains two separate `ContextManager` implementations (core/agi and core/agent, `apps/desktop/src-tauri/src/core/agi/context_manager.rs:7-12` and `apps/desktop/src-tauri/src/core/agent/context_manager.rs:81-109`), so there is not yet a single assembler to make uniformly stateless.

**Target.** A single stateless assembler (AC-107) that holds no process-local mutable trigger or cooldown state — every assembly and compaction-trigger decision is a pure function of the session, memory, and storage planes (§19 framing), allowing any worker to serve any turn.

**Migration.** Move the desktop cooldown/trigger state out of a process-global map into the storage plane (or recompute it from persisted compaction records), and converge the two desktop `ContextManager` implementations and the web v1/v2 paths onto the single stateless assembler.

## Reliability

Reliability is the assembler's guarantee that the same fixed inputs yield the same assembled context every time (AC-19), and that the over-budget guard runs whenever it is needed.

**Current — reliability is path-dependent, not uniform.** The deterministic primary-source packing order on desktop is reliable for the fixed-sequence sources (default prompt, memory, OS, project context, custom instructions, history are packed by straight-line code, `apps/desktop/src-tauri/src/sys/commands/chat/send_message_setup.rs:199-319`). But the AC-19 guarantee is broken by the ambient-nondeterminism sources catalogued under Failure Modes: `Date.now()` tool-call ids (web, `anthropic.ts:602`), the per-call random nonce (desktop, `prompt_tool_injection.rs:198`), the wall-clock cooldown deciding whether compaction fires (desktop, `context_monitor.rs:118-127`), and untie-broken `HashMap`/score ordering (desktop, `project_context.rs:539-541`; `send_message_setup.rs:659-730`). For those, identical inputs do not reliably reproduce identical context.

**Current — the over-budget guard is reliable only on some paths.** Compaction runs on the web v2 AI-SDK path and on desktop, but the web v1 fallback performs token estimation without compaction (`apps/web/.../route.ts:768-798`; factory/base providers compute no compaction), and mobile and VSCode track and warn on budget but implement no compaction at all. On those paths the context can exceed the AC-20-derived budget with no reliable corrective step.

**Current — dead/divergent trigger logic.** The documented `shouldCompact()` (80% threshold) is never called (`apps/web/lib/llm-providers/context-management.ts:106-111`; 0 callers), while the live v2 trigger is computed inline at 60% of the window (`apps/web/.../route.ts:775-776`). Two thresholds with one unused implementation reduce confidence that the documented behavior matches the live behavior.

**Target.** Uniform AC-19 reproducibility across all paths (no ambient nondeterminism), one over-budget guard that runs on every path before a request exceeds the AC-20-derived budget, and a single live compaction trigger with no dead alternative implementation.

**Migration.** Remove the ambient-nondeterminism sources, delete or wire the dead `shouldCompact()` so there is one trigger, and extend the over-budget guard to the web v1, mobile, and VSCode paths as the assemblers converge. Compaction modes and the canonical threshold value are owned by BK-11.02.

## Observability

Observability is how assembly determinism is made visible: whether an operator can confirm that fixed inputs produced the expected assembled context, see when compaction fired, and audit which trust boundary an assembly ran in.

**Current — desktop emits compaction lifecycle events; no other surface does.** Desktop auto-compaction emits a `compaction:auto-triggered` Tauri event before summarization (carrying `conversation_id`, `current_tokens`, `max_tokens`, `percentage`) and a `compaction:completed` event after persistence, plus a legacy `chat:context-compacted` event for backward compatibility (`apps/desktop/src-tauri/src/sys/commands/chat/context_monitor.rs:164-173,241-263`). These make the _occurrence_ of compaction observable on desktop. Web, CLI, mobile, and VSCode show no equivalent assembly-determinism telemetry in evidence.

**Current — determinism itself is not observable anywhere.** No surface emits a reproducible assembly fingerprint (a hash or manifest of the packed sources and their order) that would let an operator confirm two assemblies of the same fixed inputs were identical. Combined with the gaps under Privacy — `cloud_sync_enabled` is derived but never attached to assembled-context metadata (`apps/desktop/.../send_message_setup.rs:64-70`) and there is no per-turn boundary audit record — an operator today cannot verify AC-19 reproducibility or §19-trust-rule read scoping after the fact from emitted signals.

**Target.** An assembly-determinism manifest — a stable fingerprint over the ordered, packed source set plus the AC-20-derived budget and the turn's trust boundary — emitted on every surface, so reproducibility (AC-19) and read scoping (§19 trust rule, AGI-TRUST-0001) are auditable rather than assumed. A determinism fingerprint and a per-turn boundary tag are Target capabilities, not Current.

**Migration.** Generalize the desktop compaction-event pattern to a uniform set of assembly events across surfaces, then add the determinism manifest and boundary tag to the single shared assembler.

## Configuration

The only configurable quantity governing assembly in scope is the context budget, which AC-20 requires be derived from the model's declared context window in the catalog SSOT (AGI-AI-0001) and never hardcoded, invented, or guessed. Configuration compliance is therefore per-surface and is the cleanest split in the evidence.

**Current — compliant surfaces.**

- **Web (primary path).** `getModelContextWindow()` resolves the budget through `getModelMetadataById()` → `modelsCatalog.models[canonicalId].contextWindow`, sourced from `packages/contracts/types/src/models.json` (`apps/web/lib/llm-providers/context-management.ts:64-67`; `apps/web/.../model-catalog.ts:287-296`). When the model is in the catalog this satisfies AC-20.
- **CLI.** The compaction context limit is derived from the shared catalog via `model_catalog::context_window(model)` (`apps/cli/src/compaction.rs:143-150`; `apps/cli/src/model_catalog.rs:1-33`) — AC-20 compliant.
- **Mobile.** The budget is model-aware: `getContextWindow()` fetches the model from `MODEL_LIST` via `getModelById(modelId)` and reads `contextWindow` (`apps/mobile/src/features/memory/services/contextBudgeter.ts:43-49`), sourced from `@agiworkforce/types` — AC-20 compliant.

**Current — non-compliant or risk surfaces.**

- **Web (fallback branch).** When a model id is absent from the catalog index, the hardcoded prefix-match defaults override the catalog (`apps/web/lib/llm-providers/context-management.ts:73-81`). When this branch executes, the budget is not derived from the SSOT — an AC-20 violation for that case (e.g., a stale 200K for `claude-opus-4.8`, which is 1M in the catalog).
- **Desktop.** Catalog lookup is correct for known models via `resolve_context_window()` reading `models_config::config().models` (`apps/desktop/src-tauri/src/sys/commands/chat/context_monitor.rs:268-276`), but the unknown-model fallback is hardcoded `DEFAULT_CONTEXT_WINDOW = 128_000` (`context_monitor.rs:44`), and `CompactionConfig::max_tokens` defaults to a hardcoded `100_000` decoupled from any catalog lookup (`apps/desktop/src-tauri/src/core/agent/context_compactor.rs:7-40`).
- **VSCode.** `contextBudget.ts` reads a hardcoded `MODEL_CONTEXT_LIMITS` dictionary as a local constant rather than the shared catalog (`apps/extension-vscode/src/data/contextBudget.ts:13-24`), even though a catalog-backed path exists in `modelConstants.ts` (`apps/extension-vscode/src/features/model-picker/modelConstants.ts:1-23`) — AC-20 non-compliant where the local dict is used.

**Target.** Every surface derives the context budget solely from `contextWindow` in the catalog SSOT (AGI-AI-0001) per AC-20, with no hardcoded value that can override the catalog and an explicit, logged handling for unknown models that does not silently substitute a guessed window.

**Migration.** Remove the web prefix-match override and the desktop `100_000`/`128_000` decoupled constants, point VSCode `contextBudget.ts` at the shared catalog, and add a CI guard that asserts every surface reads `contextWindow` from the catalog so AC-20 compliance is machine-verified rather than per-surface-audited.

## Versioning

The deterministic assembler defined by this book is versioned along two independent axes, and the distinction is load-bearing for AC-19.

**Current.** The context-budget input is already version-coupled to the model catalog SSOT: `getModelContextWindow()` resolves `contextWindow` through `getModelMetadataById(modelId)` against `modelsCatalog.models[canonicalId]` (context-management.ts:64-67), and that catalog carries its own `version`, `lastUpdated`, and dated `verificationLog` (packages/contracts/types/src/models.json:1-30). A change to a model's declared context window is therefore a catalog-version event, not an assembler-code event — this is the correct seam, and it satisfies AGI-AI-0001 for the catalog-resolved path. The assembly _logic_ (packing order, compaction trigger) is, by contrast, versioned only implicitly through source revisions: there is no declared assembly-contract version, and the live web compaction threshold is an inline literal in the v2 route (`compactionThresholdPct=0.6`, route.ts:775-776) rather than a versioned policy value.

**Target.** Two declared versions: a **catalog version** (already present, owns context-window and pricing facts) and an **assembly-contract version** that owns the source-packing precedence (CH-11.01.01), the determinism rules (CH-11.01.02), and the trust-scoping rules (CH-11.01.03). The assembly-contract version MUST bump whenever packing precedence, the canonical tie-breakers, the trigger-threshold derivation, or the trust-scoping predicate changes — because any of these alters the assembled context for fixed inputs and therefore changes what AC-19 reproduces against.

**Migration.** Stamp the assembled-context envelope with both versions (catalog version + assembly-contract version) so a reproduced assembly is comparable only against an assembly produced under the same two versions. Until the assembly-contract version exists, reproducibility (see Testing) can only be asserted against a fixed source revision, not against a declared contract.

## Compatibility

**Current.** There is no single assembler; there are several, and they are not wire-compatible at the assembly layer. Web runs two paths — a client path (`WebChatRuntime` injects memory via `buildMemorySystemContent` + `withMemorySystemMessage`, WebChatRuntime.ts:126-127) and server v1/v2 API paths that receive pre-assembled history and do not re-assemble memory (grep shows zero `buildMemorySystemContent` callers under `apps/web/app/api`). Compaction is wired only in the v2 AI SDK path (route.ts:768-798); the v1 fallback performs token estimation but no compaction (factory.ts uses base providers with no `buildAnthropicContextManagement`). Desktop runs its own Rust assembler (`maybe_compact_context`, context*monitor.rs:95-266) with two distinct `ContextManager` types (core/agi vs core/agent). CLI, mobile, and VSCode each carry separate budgeters (compaction.rs, contextBudgeter.ts, contextBudget.ts). The one fact these paths \_do* share is the catalog SSOT for the context window — web (context-management.ts:64-67), desktop (`resolve_context_window`, context_monitor.rs:268-276), CLI (model_catalog.rs:1-33), and mobile (`getModelById`, contextBudgeter.ts:43-49) all read it; VSCode is the exception, reading a local `MODEL_CONTEXT_LIMITS` constant rather than the shared catalog (contextBudget.ts:13-17).

## Testing

The roadmap review requirement for BK-11.01 is explicit: a **reproducibility test — fixed inputs → identical assembly** (master-documentation-roadmap.md:1270). This is the single gating test for AC-19 and the primary acceptance criterion for the deterministic assembler.

**Reproducibility test (Target, the AC-19 gate).** Hold the five inputs fixed — conversation, memory corpus, project, token budget, model context window (the exact tuple AC-19 governs, §19) — and assert that two independent assembly runs produce byte-identical assembled context. The test MUST fail on any ambient nondeterminism. The evidence brief already names the concrete failure injectors this test must catch:

1. **`Date.now()` in tool_use ID generation** — `id: tc.id || \`call\_${Date.now()}\`` (anthropic.ts:602). Two assemblies of an identical conversation produce different tool_use IDs, so the test must assert tool_use IDs are derived deterministically from caller-provided IDs or a content-stable function, never wall-clock.
2. **Random per-call nonce in desktop tool injection** — `build_injection_nonce()` emits `Uuid::new_v4()` per call (prompt_tool_injection.rs:198); identical conversations yield non-identical assembled system prompts. The test must treat the nonce as a declared input (fixed seed) for reproducibility, while preserving its security purpose (FIX-015) for production runs.
3. **HashMap iteration order in project-context file counts** — `file_counts` is iterated and sorted by count descending with no secondary key (project_context.rs:515,539-541); equal counts order non-deterministically. The test must assert a stable total order (count, then a canonical tie-breaker such as extension name).
4. **Skills selection tie-break** — top-2 by Jaccard score with no secondary tie-breaker (send_message_setup.rs:659-730); equal scores select non-deterministically. The test must assert a declared tie-breaker.

**Budget-derivation test (Target, the AC-20 gate).** Assert the trigger budget is the catalog `contextWindow` for the model under test, and assert the **fallback branch never overrides the catalog** for a model that is present in the SSOT. This test catches the web prefix-match fallback that returns 200K for `claude-` while the catalog declares `claude-opus-4.8` at 1,000,000 (context-management.ts:73; models.json claude-opus-4.8:1000000) — a 5× underestimate that violates AC-20 whenever the fallback executes for a catalogued model.

**Trust-scoping test (Target, the CH-11.01.03 gate).** Assert a managed turn assembles no local-origin content and a local/byok turn pulls nothing from the shared cloud store (the §19 trust rule / AGI-TRUST-0001). The desktop derivation `derive_cloud_sync_enabled()` (send*message_setup.rs:57-70) gives a pure, test-doubled predicate to assert against; the test must additionally assert the predicate gates \_context assembly* (lines 199-358), not only routing — the current gap is that routing is gated (RouterPreferences.local_only) but assembly is not.

**Cross-surface equivalence test (Target).** For a fixed input tuple, assert each surface's assembler produces the same packing order and the same trigger budget. No CI guard currently confirms this (the brief records no machine-verified mirror equivalence for budget derivation across surfaces).

## Validation

**Current.** Validation that exists today is narrow and per-surface: the catalog lookup path is exercised wherever `getModelMetadataById` / `resolve_context_window` / `model_catalog::context_window` is called, and desktop's trust predicate is duplicated into tests to keep the `derive_cloud_sync_enabled` contract consistent (the brief notes the pure function is mirrored in tests). There is no validation that assembly is deterministic, that packing precedence is canonical, or that assembly respects the trust boundary.

**Target.** Validation is layered:

- **Static (CI guard).** A guard that fails the build if any surface reads a context window from anything other than the catalog SSOT — this directly addresses the AC-20 enforcement gap the brief flags (no CI guard confirms all surfaces read `contextWindow` from the catalog) and the VSCode local-dict non-compliance (contextBudget.ts:13-17). A second guard forbids wall-clock (`Date.now()`, `Uuid::new_v4()`) inside the assembly path unless seeded.
- **Contract (unit).** The four reproducibility injectors above plus the budget-derivation and trust-scoping assertions.
- **Equivalence (integration).** Cross-surface packing-order and budget equivalence for a shared fixture.

**Migration.** The static guards land first because they are cheap and catch regressions while the assembler is still multi-path; the contract and equivalence layers land as each surface converges.

## Monitoring

**Current.** Desktop is the only surface with assembly observability: auto-compaction emits `compaction:auto-triggered` before summarization (carrying `conversation_id`, `current_tokens`, `max_tokens`, `percentage`) and `compaction:completed` after persistence, plus a legacy `chat:context-compacted` event (context_monitor.rs:164-173, 241-263). Web v2 computes the trigger inline but emits no equivalent assembly-event stream from the evidence shown. No surface emits a trust-scoping decision event.

**Target.** Each assembly turn emits a structured record sufficient to reconstruct the AC-19/AC-20/trust verdict without re-running the model: the resolved context window and its source (catalog vs fallback), the estimated token count and estimator used, the compaction mode and trigger percentage, the source classes packed and their order, and the trust verdict (managed/local/byok and whether any cross-boundary read was refused). The egress/audit mechanism itself is owned by VOL-20 (§24) and is referenced, not redefined here.

**Migration.** Desktop's two-event model (`auto-triggered` / `completed`) is the template; the missing fields are the context-window _source_ (catalog vs fallback) and the trust verdict. Adding those two fields to the existing desktop events is the first monitoring increment.

## Metrics

Metrics are the aggregate view of the Monitoring records; the operational thresholds below feed Operational Guidance.

- **Fallback-window rate** (Target) — fraction of assemblies whose context window came from the fallback branch rather than the catalog. Target is zero for catalogued models; any nonzero value for a catalogued model is an AC-20 violation surfaced by the web prefix-match fallback (context-management.ts:73-81).
- **Compaction-trigger rate and headroom** (Current data, desktop) — derivable from `current_tokens` / `max_tokens` / `percentage` in `compaction:auto-triggered` (context*monitor.rs:164-173). Desktop triggers at 95% (context_compactor.rs:37); a trigger-rate near 100% of long sessions is expected, but a trigger \_before* the threshold indicates token-estimate drift.
- **Token-estimate drift** (Target) — divergence between the heuristic estimate and provider-reported usage. The heuristics differ by surface (3.5 chars/token web, 4 chars/token desktop/CLI/mobile/VSCode; context-management.ts:90-98, context_compactor.rs:268-270) and the same estimate drives both compaction triggers and credit estimation (route.ts:865-869), so drift has billing-determinism consequences, not only assembly consequences.
- **Cross-boundary-read-refusal count** (Target) — number of assemblies where a local-origin source was withheld from a managed turn (or vice versa). This is the operational signal that CH-11.01.03 scoping is active; today it is unmeasurable because assembly is not trust-gated.
- **Reproducibility-test pass rate** (Target) — the CI signal for AC-19.

## Operational Guidance

**Current operational facts an operator can rely on today:**

- Desktop auto-compaction is atomic: it runs inside a SQLite transaction (DELETE old messages → INSERT summary → COMMIT, rolling back on failure), and is rate-limited by a 120s per-conversation cooldown plus a ≥12-message minimum (context_monitor.rs:95-151, 313-393). An operator seeing rapid repeated compaction on one conversation should suspect the cooldown or token-estimate path, not the trigger threshold.
- Desktop compaction keeps the 10 most recent messages verbatim and replaces older history with a single `[Compacted Context]` System message (context_monitor.rs:39-40,181). The summary is persisted with `id=0` and re-fetched (context_compactor.rs:279-293), and `CompactionResult.summary_message_id` is `None` (context_compactor.rs:158-164) — so there is **no foreign-key link from old messages to the summary**; compaction is not auditable/recoverable at the row level. An operator cannot reconstruct pre-compaction history from the summary row.
- Desktop summary generation degrades gracefully: LLM-powered when a router is present, heuristic (keyword/sample extraction) otherwise (context_compactor.rs:167-216). An operator without a configured local/cloud LLM still gets compaction, at lower summary quality.
- Web compaction is **Anthropic-and-v2-only** (route.ts:768-798); v1 fallback sessions do not compact and can grow toward the model limit. An operator triaging an unbounded web context should first confirm the request took the v2 AI SDK path.

**Target operational guidance:** a single runbook keyed to the Monitoring verdict — fallback-window alarms point at catalog coverage; trust-refusal anomalies point at the scoping predicate; estimate drift points at the tokenizer contract.

## Implementation Guidance

How an engineer converges a surface onto the deterministic assembler, ordered by risk (lowest first), each step grounded in a specific current-state gap:

1. **Point the budget at the catalog (AC-20).** If the surface reads a context window from anything but the SSOT, redirect it. VSCode is the live offender: `MODEL_CONTEXT_LIMITS` is a local constant (contextBudget.ts:13-17) while `modelConstants.ts` already exposes `getModelContextLimits` from `@agiworkforce/types` (modelConstants.ts:1-23) — switch the budget to the shared accessor. On web, remove or fence the prefix-match fallback so a catalogued model never receives a hardcoded window (context-management.ts:73-81). This step changes only the window source, never the packing, so it is safe to land first.

2. **Make the trigger derivation single-sourced.** Replace inline trigger literals with one derivation reading the catalog window. On web, the live 60% inline value (route.ts:775-776) and the never-called `shouldCompact()` 80% value (context-management.ts:106-111; zero callers) are two thresholds with one dead implementation; collapse to one declared value so the trigger is auditable.

3. **Remove ambient nondeterminism from the assembly path (AC-19).** Derive tool_use IDs deterministically instead of `Date.now()` (anthropic.ts:602); seed or declare the desktop injection nonce as an input rather than a per-call `Uuid::new_v4()` (prompt_tool_injection.rs:198) while preserving its FIX-015 security role; add a canonical secondary tie-breaker to the project-context file-count sort (project_context.rs:539-541) and to skills selection (send_message_setup.rs:659-730).

4. **Fix the packing precedence to one canonical order.** Desktop already executes a fixed sequential packing order (default system prompt → memory → OS → project context → coding prompt → custom instructions → browser context → skills → history → tools; send_message_setup.rs:199-358) — adopt this as the canonical precedence for the five source classes and converge other surfaces onto it, keeping a source class absent only when the surface genuinely cannot supply it.

5. **Gate assembly by trust boundary (CH-11.01.03).** Move the trust check from routing-only to assembly-time. Desktop routing is gated by `RouterPreferences.local_only` (send_message_setup.rs:148-164) but the assembly block (lines 199-358) does not consult `flags.is_local_mode` before reading local sources; condition local-origin assembly on the trust verdict so a managed turn cannot assemble local content even before routing. Web has the same shape: the managed-compute gate validates `providerMode` (route.ts:624-661) but does not condition message building.

6. **Close the absent source class where the surface supports it.** Project knowledge / RAG is absent from web (no document/file injection; grep yields only a caching heuristic at factory.ts:346) — it is a distinct packed source class owned by BK-11.04, so converging it follows that book, not this one. Memory on web is client-only (`WebChatRuntime`, WebChatRuntime.ts:126-127) and absent from server API routes; converging direct API callers onto memory assembly requires moving memory injection server-side under the same trust gate as step 5.

## Future Evolution

**Target.** The endpoint is one shared deterministic assembler invoked identically by every surface, parameterized only by which source classes the surface can supply, with packing precedence, trigger derivation, token-estimation, and trust scoping all single-sourced. The five-source taxonomy (CH-11.01.01) becomes complete on every surface that can supply a class; the reproducibility test (Testing) is a standing CI gate.

**Migration path beyond convergence.** Per-surface heuristic token estimation (3.5/4 chars-per-token) is a known approximation; a future evolution replaces it with provider-accurate tokenization where the billing-determinism cost of drift justifies it (the estimate drives both compaction and credit calc, route.ts:865-869). Desktop embedding storage at native dimensions (768 Ollama / 1536 OpenAI, conversation_summarizer.rs) is honest-but-incomplete and a candidate for a normalization layer — but that is memory-runtime territory (VOL-12), not this book. RAG as a source class evolves under BK-11.04; compaction-mode and summarization-cadence detail evolve under BK-11.02 / BK-11.03.

## Known Limitations

Each limitation is a current-state fact from the evidence, with its governing-law impact:

- **Web fallback overrides the catalog (AC-20).** The prefix-match branch returns fixed windows (claude-=200K, gemini-=1M, gpt-5=128K) that override the SSOT when a model is absent from the index; `claude-opus-4.8` is catalogued at 1,000,000 but the `claude-` prefix returns 200K (context-management.ts:73-81; models.json claude-opus-4.8:1000000).

## Glossary

- **Trust boundary.** The authorization perimeter separating Local, BYOK, and Managed origins; context assembly must not read across a boundary the turn is not authorized for (§19 trust rule, AGI-TRUST-0001).

- **Context.** The assembled per-turn model input; **derived, never authoritative**, owning no durable state (§19 framing).
- **Token budget.** The compaction-governing bound, derived from the model's declared `contextWindow` in the catalog SSOT (AC-20, AGI-AI-0001; context-management.ts:64-67).
- **SSOT.** The single source of truth for model facts, `packages/contracts/types/src/models.json`, carrying `version`/`lastUpdated`/`verificationLog` (models.json:1-30).
- **Source class.** One of the five packed inputs — conversation, memory, project knowledge, tool results, instructions (CH-11.01.01).
- **Compaction.** Budget-driven reduction of assembled context; modes and thresholds owned by BK-11.02, referenced not redefined here.
- **Reproducibility test.** The AC-19 gate: fixed inputs → identical assembly (master-documentation-roadmap.md:1270).
