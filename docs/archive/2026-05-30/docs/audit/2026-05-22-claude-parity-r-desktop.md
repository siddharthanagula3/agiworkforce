# R26-PARITY Lane R-DESKTOP — Runtime Parity (AGI Workforce.app vs Claude.app)

Status: Draft (initial runtime sweep)
Date: 2026-05-22
Lane: R-DESKTOP (runtime side-by-side)
Sibling lanes: W2a (Claude Free static), W2b (Claude Max static), W2c (Claude artifacts/connectors static)
Audited by: lane-r-desktop subagent

**Reproducibility key dates**: installed binary `/Applications/AGI Workforce.app` mtime = `Apr 29 19:54:08 2026`. Several key locks (`v1-local-only-cloud-waitlist-2026-05-18`, `v1-model-selection-final-2026-05-18`) are dated _after_ this binary was built. Findings tagged "stale-data" should be re-verified against the current `main` build before patching; some are likely "install needs rebuild + reinstall" rather than "source needs patching".

## TL;DR

The Claude desktop app launches into a fully-rendered Pro/Max product surface with three first-class tabs (Chat / Cowork / Code), a rich sidebar, model selector, mode-of-work pills, recents, onboarding nudges, and an account/settings/auto-update path. **The installed AGI Workforce.app (v1.1.5, binary mtime `Apr 29 19:54:08 2026`) cold-boots into a stuck loading-skeleton (one rounded avatar placeholder + two grey bars) and never advances to a usable surface in ~10 minutes of observation.** The Tauri host and WebKit engine are alive (JavaScript is executing successfully, the React bundle and CSS are loading), but the application chrome that should mount inside `#root` does not paint. Code-signing, system permissions, and TCC plumbing reinforce that this is a developer build promoted to /Applications, not a hardened release.

**Critical caveat for sections 3 and 6: the installed binary is dated 2026-04-29, ~19 days before the `v1-local-only-cloud-waitlist-2026-05-18` and `v1-model-selection-final-2026-05-18` locks were written.** Many "stale-data gap" findings below are most-likely "install needs refreshing" (the user-facing fix is `pnpm --filter @agiworkforce/desktop build && tauri build && reinstall`), not "code on `main` contradicts the lock". W2a/b/c source-side lanes should reconcile each row against the _current_ dist before remediation is sequenced.

**Root cause of the boot hang — empirically confirmed.** Both expected localhost endpoints declared in `settings.json` are dead at audit time:

- `curl http://localhost:11434/api/tags` (Ollama) → `Failed to connect: Couldn't connect to server`
- `curl http://localhost:9999` (the `http://localhost:9999` URL hardcoded in `desktop-core-Bct2rNh5.js`) → `Failed to connect`

The skeleton is therefore not a "React mount failure" — it is a **missing timeout / error-state fallback in the boot sequence**. The orchestrator-init / provider-status IPC chain is waiting forever on a backend that the OS isn't running, and React renders the skeleton suspense state indefinitely. This re-orders the P0 recommendations below.

Side-by-side runtime: AGI is functionally broken at the _first-pixel_ level relative to Claude _for this user, on this machine, today_. We cannot meaningfully audit "model picker UX", "settings tabs", "composer pills", etc. because none of those surfaces render at runtime. All flow-level parity claims below are gated on "AGI: did not render".

## 2. UX divergence (qualitative)

Cannot evaluate AGI runtime UX beyond the skeleton — nothing visible. Claude observations from the runtime captures:

- **Visual hierarchy** — Claude home uses a serif-display headline ("Let's knock something off your list" / "Good evening, Siddhartha Nagula") that anchors the page; the composer is large and centered with breathing room; quick chips are visually equal-weight; recents are dense but typographically restrained. The whole surface reads as a _workspace_, not a chatbot.
- **Info density** — Claude packs ~25-30 chat titles into the left rail visible at once without feeling crowded. The Code tab (`108_claude-max20x_code_home.png`) is data-dense — stats grid + contribution heatmap — and still readable.
- **Micro-interactions / state** — Claude surfaces three runtime states _at once_: "Pinned or active" (currently being worked on), "Active" (recent), "Get to work with Legal" (suggested workflow). The "Schedule a task" floating popover (`claude/2026-05-15/207…png`) is a proactive nudge, not a static menu item.
- **Copy** — Claude is short and direct: "Let's knock something off your list", "Get to work with Legal", "Schedule a recurring task". Cowork branding is consistent (Cowork tab + Cowork onboarding + Cowork-mode pills).
- **Identity** — Profile chip bottom-left of sidebar shows `Siddhartha Nagula · Max` (plan badge inline); account menu opens upward (`202_…png`).
- **AGI's intended hero copy** — searching the bundled JS (`desktop-core-Bct2rNh5.js`) returns strings like `"Unexpected error during initialization"`, `"orchestrator_init_default"`, `"All extensions started"`, `"starting default worker"`. These suggest the intended boot flow performs orchestrator-init + worker-start + extension-mount _before_ rendering any UI. **If any of those promises hang, the React tree never paints anything past the skeleton** — which matches the observed behavior.

## 4. Broken flows (what hangs/freezes/doesn't render)

These are **runtime-observed, not source-inferred**.

1. **Skeleton never resolves into UI.** From cold launch to >10 min later, AGI renders only `avatar-placeholder + 2 grey skeleton bars` (see `agi-01-launch.png` through `agi-08-after-cmd-tilde.png`, all identical). Cmd-R (no-op), Cmd-`\`` (no-op), cold quit + relaunch (`agi-06-cold-relaunch.png`→`agi-07-after-dismiss.png`, same skeleton) all leave state unchanged.
   - **Root cause confirmed by direct probe:** `settings.json` ships `ollamaUrl: "http://localhost:11434"`, and `desktop-core-Bct2rNh5.js` contains the literal `"http://localhost:9999"`. At audit time both endpoints respond with `curl: (7) Failed to connect to localhost port {11434|9999} after 0 ms: Couldn't connect to server`. Combined with the bundle's `orchestrator_init_default`, `llm_check_provider_status`, `llm_get_available_models`, and `All extensions started` IPC names, the boot sequence almost certainly awaits provider-status from one or both of those endpoints with no timeout. The skeleton is **the React suspense fallback waiting on a never-resolving fetch** — not a JavaScript crash, not a React mount failure. Adding a `Promise.race([init, timeout(5s)])` + an error-state UI would unblock the surface from skeleton even on a misconfigured machine.
2. **Tauri host runs but UI does not mount.** Process (PID 90748, 133 MB RSS) is healthy. WebKit `WebContent` child (PID 90753) is running. `WebPageProxy::runJavaScriptInFrameInScriptWorld: Request to run JavaScript succeeded` fires every ~30–90 s — JS engine is alive. The React `<div id="root">` exists, the modulepreload chain (`rolldown-runtime` → `desktop-core` → `react-vendor` → `markdown-vendor` → `ui-vendor` → `event` → `dist-js` → `utility-vendor` → `bundle-mjs`) is correctly declared in `apps/desktop/dist/index.html`. The JS engine ran enough to fetch chunks; what hangs is the _async data-readiness_ gate, not mount.
3. **Multiple WebKit sandbox errors at boot** (`agi-01-launch.png` epoch):
   - `WebContent[90753] checkinWithServer Failed bootstrap_lookup2 for name of coreservicesd, kern_return_t=#1100/0x44c Permission denied`
   - `Failed to set up CFPasteboardRef 'Apple CFPasteboard general'. Error: … "Connection invalid". Invalidation reason: Connection init failed at lookup with error 159 - Sandbox restriction`
   - `WebContent[90753] TCCAccessRequest_block_invoke: Connection invalid`
   - `[com.apple.SkyLight:default] WebContent[90753] Conn 0x0 is not a valid connection ID.`
     These all flow from the ad-hoc signing — the WebContent process has no entitlements to access the sandboxed services it needs.
4. **AppIntents registration fails.** `[com.apple.appintents:Connection] Unable to get synchronousRemoteObjectProxy, error: … Code=4097 "connection to service named com.apple.linkd.autoShortcut"` followed by `Error registering app with intents framework`. The app declares it integrates with App Intents (per Info.plist `NSAccessibilityUsageDescription`, `NSAppleEventsUsageDescription`) but the registration is rejected by `linkd`.
5. **Cmd-R, Cmd-`\``, Cmd-, do nothing.** Power-user keyboard nav broken because no custom menu items exist.
6. **TCC dialog at cold relaunch** (`agi-06-cold-relaunch.png`): macOS prompts `"AGI Workforce" would like to access data from other apps`. This is the system's TCC dialog responding to the `TCCAccessRequest` from launch. Bad first-pixel UX.
7. **Filesystem MCP server is auto-spawned but invisible to user.** `ps -ef | grep agiworkforce` confirms `npm exec @modelcontextprotocol/server-filesystem …` runs as a child of `agiworkforce-desktop`, scoped to `~/Desktop/agiagentautomation · ~/Desktop/agiworkforce · ~/Documents · ~/Desktop`. **Filesystem access to all of `~/Desktop` and `~/Documents` is auto-granted to the LLM** with no in-app consent or scope-narrowing UX — material privacy concern. Compare Claude's `213_…png` per-tool, per-action **Always allow / Deny** flow.
8. **"Overlay" window declared but not spawned.** `~/Library/Application Support/com.agiworkforce.desktop/.window-state.json` declares a second `overlay` window (2940×1912, undecorated, fullscreen-bordereless) intended for global hotkey/quick-query. `osascript … count of windows` returns 1. The overlay surface — bundle chunks `floating-chat-D_4GRZrd.js`, `quick-query-BO2XwMgg.js`, `VoiceInputOverlay-DkmYcHRB.js` indicate it exists — does not spawn on launch even though `globalHotkeyPreferences.enabled = true, combo = "Command+Shift+Space"`. (Did not test the hotkey to avoid stealing global focus during the audit.)

## 6. Recommendations

P-numbering is severity; effort is rough engineering days for one engineer.

### P0 — Ship blockers (UI does not render at runtime)

- **R26-PARITY-RUNTIME-DESKTOP-001 — Add a boot-state timeout + error-UI fallback.** Direct probe confirms both `localhost:11434` (Ollama) and `localhost:9999` (hardcoded in `desktop-core-Bct2rNh5.js`) are unreachable on the user's machine. The boot sequence (likely `orchestrator_init_default` + `llm_check_provider_status`) awaits provider-status with no timeout, so React holds the skeleton suspense fallback forever. **This is not a React mount bug, it is a missing-timeout UX bug.** Wrap the boot promise in `Promise.race([init, timeout(5s)])` and surface a real error-state ("Couldn't connect to local model runtime — Start the local server or open Settings → Local Models") instead of hanging silently. This is the single biggest user-facing fix from this audit. Effort: 0.5–1 day.
- **R26-PARITY-RUNTIME-DESKTOP-002 — Ship a real macOS code signature.** Promote the build pipeline to use Developer ID (or App Store) signing + hardened runtime + notarization. The current `adhoc, linker-signed` build is causing concrete sandbox failures in WebKit (pasteboard, TCC, coreservicesd, SkyLight) that may be contributing to the boot hang. Reference: Claude.app is `Developer ID Application: Anthropic PBC (Q6L2SF6YDW)` + notarized + hardened. Effort: 0.5–1 day if Apple Developer ID is already provisioned; otherwise multi-day for cert procurement.
- **R26-PARITY-RUNTIME-DESKTOP-003 — Add native menu items.** File → New Conversation (⌘N), View → Reload This Page (⌘R) / Zoom In/Out / Actual Size, Edit → Find (⌘F), App → Settings… (⌘,), Help → AGI Help / Troubleshooting / Get Support. These are 1-line Tauri menu builder additions. Effort: 0.25 day.
- **R26-PARITY-RUNTIME-DESKTOP-004 — In-app updater.** Claude shows "Restart to update to Claude 1.8555.2" both in app menu and as a sidebar pill `v0.0606.2`. AGI ships no updater visible. Adopt Tauri's built-in updater (`tauri-plugin-updater`). Effort: 1–2 days.
- **R26-PARITY-RUNTIME-DESKTOP-005 — Narrow ATS exception.** `Info.plist` allows plaintext HTTP to **all** domains. Narrow `NSExceptionDomains` to `localhost`, `127.0.0.1`, `[::1]` only — keep HTTPS-only for everything else. Effort: 0.1 day. Risk: low. Privacy: high.

### P1 — Stale-data alignment to locks

- **R26-PARITY-RUNTIME-DESKTOP-006 — Strip cloud-mode IPC commands from v1 binary or gate them behind a build flag.** Per `v1-local-only-cloud-waitlist-2026-05-18.md`, v1 ships local-only. The bundle (`desktop-core-Bct2rNh5.js` string grep) still exports `cloud_get_conversations`, `cloud_create_conversation`, `cloud_delete_conversation`, `cloud_update_conversation_title`, `listCloudConversations`, `handleCloudWebCommand`, plus `master_password_setup`/`master_password_start_migration` for cloud sync. Either tree-shake these out for v1 builds, or add a runtime feature flag that disables them and replaces with waitlist-modal calls. Effort: 1 day.
- **R26-PARITY-RUNTIME-DESKTOP-007 — Default `settings.json` to local provider + Qwen3-4B model.** Currently ships `defaultProvider: "managed_cloud"` + `ollama: "llama4-maverick"`. Change defaults to `defaultProvider: "local"` + lookup against `packages/types/src/models.json` for the Qwen3-4B model ID. Drop the hardcoded `llama4-maverick` literal. Effort: 0.5 day (mostly find-and-update tests).
- **R26-PARITY-RUNTIME-DESKTOP-008 — Reconcile brand-AGI lock.** Lock says public name = "AGI". App ships as "AGI Workforce" everywhere (Info.plist, menu bar, About, copyright). Decide: update the lock to reflect "AGI Workforce" as the public-facing brand, OR rename the bundle Display Name + menu bar. Effort: 0.25 day (rename) or 0 (lock update).
- **R26-PARITY-RUNTIME-DESKTOP-009 — Add per-tool consent UI for filesystem MCP.** Today the filesystem MCP is auto-attached at boot with all of `~/Desktop`, `~/Documents` writable. Claude's reference `213_…png` shows per-action `Always allow / Deny` granularity, surfaced inline in chat. AGI bundle has the IPC names (`auto_approve_tools`, `mcp_list_connected_providers`) so the wiring is partially there. Surface the dialog. Effort: 2–3 days.

### P2 — Feature parity with Claude surface

- **R26-PARITY-RUNTIME-DESKTOP-010 — Decide whether AGI ships the 3-tab structure (Chat / Cowork / Code).** This is now Claude's signature desktop architecture. AGI's bundle has fragments (`floating-chat`, `quick-query`, `code-` chunks) but no surfaced tabs. Cross-reference with PRD V5 + locks; this is product, not engineering. Flag in the next sprint. Effort: framing call only.
- **R26-PARITY-RUNTIME-DESKTOP-011 — Build the floating "overlay" surface that `~/Library/Application Support/com.agiworkforce.desktop/.window-state.json` already declares.** A global hotkey (Cmd-Shift-Space, already configured) → 2940×1912 borderless overlay → quick-query composer is a real differentiator vs Claude. Today the overlay window is declared in state but never spawned. Effort: 2 days.
- **R26-PARITY-RUNTIME-DESKTOP-012 — Add the in-chat permission prompt pattern.** Match `213_…png`. Even with the local-only stance, MCP tool actions should be confirmed inline in chat with `Always allow / Deny` granularity. Effort: 2 days.
- **R26-PARITY-RUNTIME-DESKTOP-013 — Sidebar with Recents.** Once UI renders, the left-rail Recents list (Claude `200_…png`, `202_…png`) is the single most space-efficient pattern in the Claude home. AGI's SQLite + codebase_index already exists locally — surface it. Effort: 2 days.

## 7. Methodology notes / limitations

- Runtime captures done via `screencapture -o -x` (macOS native) because the computer-use MCP `request_access` API returned `granted` but subsequent `list_granted_applications` / `screenshot` calls reported empty. This is a server-side state bug in the computer-use MCP for this session (not the agent's misuse), confirmed by 4 separate request_access cycles. Switching to `screencapture` got the audit moving; the tradeoff is **I could not click or type inside either app, so I could not walk model-picker drawers, settings tabs, or per-message flows**. Where W2a/b/c lanes did source-side review, this lane is strictly runtime-observed defaults.
- All AGI runtime claims are reproducible against `/Applications/AGI Workforce.app` `CFBundleShortVersionString = "1.1.5"` and the user-data dir at `~/Library/Application Support/com.agiworkforce.desktop/`. Two cold boots (`agi-01-launch.png`, `agi-06-cold-relaunch.png`) and one Cmd-R reload (`agi-05-after-cmd-r.png`) all produced the same skeleton state.
- All Claude runtime claims are reproducible against `/Applications/Claude.app` (Anthropic PBC notarized) `CFBundleShortVersionString = "1.7196.3"`.
- Read-only audit: zero clicks were sent to either app; the only keystrokes were `Cmd-R` and `Cmd-`\``(View-menu non-destructive) and`Cmd-.` (dismiss permission dialog with no-op). No settings changed, no messages sent, no sign-outs.
