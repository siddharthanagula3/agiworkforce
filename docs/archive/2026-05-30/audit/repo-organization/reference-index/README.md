## Canonical mobile layer-map

```
apps/mobile/
├── app/                       # Expo route entrypoints — UNCHANGED (Expo router contract is sacred)
│   └── <route>.tsx            # each route delegates to src/entry/<route>
└── src/
    ├── entry/                 # bootstrap, route wrappers, app wiring
    ├── core/                  # state orchestration, flows shared across screens
    ├── features/              # chat, onboarding, billing, settings, messaging, models, companions, waitlist, …
    ├── platform/              # native adapters: health, permissions, intent bridges
    ├── integrations/          # api, auth, sync, supabase, mcp, cloud/local backends
    ├── storage/               # data boundary — existing apps/mobile/storage/ retained, aliased during migration
    └── ui/                    # reusable UI primitives
```

### Layer rules

1. `entry/` owns no domain logic. It wires features into Expo routes and provides app-level providers.
2. `features/`, `core/`, `platform/` do **not** import UI siblings (other feature/core/platform modules) directly — they go through barrels or domain interfaces.
3. `integrations/` is the only place network/IO/SDK calls happen. Features call into integrations, not the other way around.
4. `storage/` is the data boundary. Code outside `storage/` reads/writes via storage's public API.
5. `ui/` is presentation-only. No business logic, no integrations, no platform calls.

These rules will be enforced by ESLint import-boundary rules in a later phase. The current phase ships them as soft warnings only.

## Temporary barrel pattern

When migrating a file from `apps/mobile/<old-path>/X.ts` to `apps/mobile/src/<layer>/<feature>/X.ts`:

1. `git mv` the file to its new location.
2. Replace the old path with a barrel file that re-exports the new location, e.g.:
   ```ts
   // apps/mobile/services/waitlist.ts
   export * from '@/src/features/waitlist/service';
   ```
3. Add (or update) `apps/mobile/src/<layer>/<feature>/index.ts` so the new location has its own public barrel.
4. Do **not** rewrite call sites in the same commit. Active teammates' edits keep working unchanged.

Barrels are removed only after every call site has been migrated and the import-boundary lint check is enforced as an error. That cleanup is a separate phase.
