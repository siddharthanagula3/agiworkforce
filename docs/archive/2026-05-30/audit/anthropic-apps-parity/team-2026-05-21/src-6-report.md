# src-6 — `apps/extension-vscode` parity audit (read-only, 2026-05-21)

Scope: `apps/extension-vscode/src/features/{sidebar-webview, chat-participant, model-picker, code-lens, inline-completions, hover, trees, desktop-bridge}` and surrounding wiring in `extension.ts`, `package.json`, `core/`, `providers/`. Surface name: VS Code Extension.

Rubric severities — P0 blocks v1 parity, P1 visible UX gap, P2 polish. Hours assume one mid-level engineer with familiarity, design+impl+basic test only.

---

## 0. Architecture caveats (informs every row below)

- Sidebar UI is a **string-templated HTML/CSS/vanilla-JS webview**, not React. The entire chat surface (composer, messages, tool calls, popovers, usage meter, empty-state, mention dropdown, model picker overlay) is generated by template literals in `apps/extension-vscode/src/features/sidebar-webview/webviewContent.ts:40-1724`. Markdown rendering is delegated to a separately bundled `out/webview/render.js` (markdown-it + DOMPurify), referenced at `webviewContent.ts:66-68,1233-1244`. There is no shared component library — `packages/unified-chat` is **not consumed** by this extension. Only `@agiworkforce/design-tokens` is imported, for CSS-var token strings (`webviewContent.ts:11`, `cssVarsToString(agiVsCodeCssVars)` at line 86).
- Chat participant is a separate code path (`features/chat-participant/chatParticipant.ts:316-545`) writing to `vscode.ChatResponseStream` — that surface is whatever the host (GitHub Copilot Chat panel) renders. The extension only emits markdown + a follow-up button list.
- The same `webviewContent.ts` HTML is also reused by `providers/chatEditorPanel.ts` ("Open Chat in Editor" command).

This baseline framing matters because most "polish" gaps below are not 1-component fixes — they would require either lifting components into a webview component framework or porting `packages/unified-chat` into the webview bundle.

## 13. Self-noted parity flags for lead reconciliation

1. **Lack of a React-based component layer.** Most of the per-row UX deltas above would be cheaper to close if `packages/unified-chat` were consumed by the webview. This is a strategic call, not a small fix — flagging for the lead.
2. **"Add file or image" misleads.** The button label promises image attach; the implementation pins file paths only. Either rename or implement.
3. **Slash-commands exist on Copilot path only.** Sidebar webview composer and Copilot panel have meaningfully different command grammars — a parity gap _within_ the extension.
4. **Sidebar webview does not write to ConversationStore** (only `@agi` Copilot path does, per `chatParticipant.ts:381-396`). The History tree therefore mostly shows Copilot-path conversations, not sidebar conversations. Bears verifying — possible regression vs design intent.
5. **`agi-workforce.fallbackToVscodeLm` default true** lets the extension silently use the user's Copilot key. Strategic choice, but worth lead's awareness.

End of report.
