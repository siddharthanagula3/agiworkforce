## Architectural notes (orient the rest of the report)

1. **Two coexisting chat surfaces under `/chat`:**
   - **Default surface** = `WebChatPage` at `apps/web/features/chat/pages/WebChatPage.tsx:123-559`. Uses **web-local** sidebar/composer/message-list components (`features/chat/components/{Sidebar,Composer,messages,artifacts}`). Does **not** consume `@agiworkforce/unified-chat`.
   - **Opt-in surface** = `UnifiedChatPage` at `apps/web/features/chat/pages/UnifiedChatPage.tsx:1-67`, gated by `?unified=1` query param (selector at `apps/web/app/chat/page.tsx:15-19`). This is the only path that mounts `WebShellV3` + `ChatInterface` from the shared `@agiworkforce/unified-chat` package.
   - Result: most of `/chat` traffic runs on the **web-local fork**, not the cross-surface unified chat. Drift between the two surfaces is the dominant architectural risk.

2. **`apps/web/src/*` is skeleton-only.** Every layer (`entry/`, `core/`, `platform/`, `integrations/`, `data/`, `ui/`) is an empty `export {}` barrel — see `apps/web/src/README.md:36-46` ("Migration Status: skeleton only"). All production code lives in `apps/web/app/`, `apps/web/features/`, `apps/web/components/`, `apps/web/lib/`, `apps/web/services/`. The brief's "src/\*" surface is therefore vestigial; the meaningful surface is `features/`.

3. **Build oddity:** `apps/web/package.json:8` runs the desktop's web-Vite build into `apps/web/public/chat` before `next build`. So `/chat` is **also** served as a static SPA bundle from the desktop's web target, layered on top of the Next route. The Next route under `app/chat/page.tsx` takes precedence when present, but this dual-source pipeline means a desktop-driven `index.html` may shadow client-side routing in some deploy modes. Worth flagging — not strictly a "Claude parity" gap, but it affects every web feature delivered.

4. **Authentication gate:** both `/chat` and `/settings/*` use Supabase `getUser()` (JWT-revalidated) layouts — `apps/web/app/chat/layout.tsx:7-21`, `apps/web/app/settings/layout.tsx:15-26`. Unauthenticated users redirect to `/login?next=…`. Solid.

5. **Marketing pages (`/customers`, `/payment-failure`, `/byok`, `/signup`, `/verify`, `/get-started`, `/pricing`, `/features`, `/use-cases`, `/integrations`, `/connectors`, …)** all use a separate `data-design="agi"` shell (`Header` + `MarketingFooter` + `agi-shell` CSS), distinct from the chat shell. These are static editorial pages, not product UI.
