## Blockers, founder gated

- **apps/web**: 25 migration files across `apps/web/db/neon/` (0047, 0059, and a contiguous 0151-0174 run) carry a `NOT YET APPLIED, draft only, pending explicit approval` header. By repo convention this header text is retained verbatim after a migration is applied, because the ledger hashes the full file text, so the header alone cannot confirm current production state; only a founder-authorized check of the live schema can. Stripe live-mode setup, the production KV/Redis quota decision, a Places API key, and a separate Google key/project for local versus QA all remain open per `docs/research/p0-capability-classification-2026-09-05.md`, along with the single production deploy itself.
- **apps/desktop**: `macos-release` and the Tauri release environment need `APPLE_CERTIFICATE`, `APPLE_CERTIFICATE_PASSWORD`, `APPLE_API_KEY`, `APPLE_API_ISSUER`, `APPLE_API_PRIVATE_KEY`, `TAURI_SIGNING_PRIVATE_KEY`, `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` provisioned as real secrets; this audit can confirm the workflow requires and validates them, not that they hold live values.
- **apps/mobile**: `EXPO_TOKEN`, `ASC_API_KEY_ID`/`ASC_API_KEY_ISSUER_ID`/`ASC_API_PRIVATE_KEY_BASE64`, `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON_BASE64` must exist, plus actual App Store and Play Store listing review and approval, which is a vendor gate outside repo control.
- **apps/extension**: `CWS_PUBLISHER_ID`, `CWS_EXTENSION_ID`, `GCP_WORKLOAD_IDENTITY_PROVIDER`, `CWS_SERVICE_ACCOUNT`, `CHROME_EXTENSION_PUBLIC_KEY` and production Clerk variables, plus Chrome Web Store review approval.
- **apps/extension-vscode**: `VSCODE_MARKETPLACE_AZURE_CLIENT_ID`/`TENANT_ID` and the publisher-role grant on the Marketplace identity for the `agiworkforce` publisher.
- **apps/cli**: `NPM_TOKEN` for the 7-package npm publish.

## Blockers, engineering gated

- **apps/desktop**: Windows is excluded from the auto-triggered release pipeline for both shells by explicit policy (`release-desktop.yml` header) until its build, signing, updater, smoke-test and ingestion paths are implemented together; `build-windows-release.yml` is a manual-only stopgap. The Electron cloud shell ships with no in-place auto-update feed by design, only a new signed DMG per release. `wiring-allowlist.json` lists several Tauri commands recommended for deletion as unreachable dead code with a live attack surface; they have not been removed. No an apps/desktop agents file exists, leaving the surface without a local statement of its claimed journeys.
- **apps/web**: Confirm actual production migration state against the live schema rather than file headers before treating 0153-0174 as settled either way.
- **apps/mobile**: No Android-equivalent of the iOS Detox E2E job exists in `ci.yml`; only iOS simulator journeys are exercised in CI. Crash reporting is deliberately absent (documented privacy stance); confirm this tradeoff is still accepted before a public-track release.
- **apps/extension** and **apps/extension-vscode**: neither has a Sentry-equivalent error-tracking service; failures are only visible through the browser's or editor's own extension-error surfaces or user reports.
- **apps/cli**: release binaries are unsigned on macOS and Windows; the npm install path avoids OS Gatekeeper/SmartScreen friction, but direct binary downloads from the GitHub release will not.
