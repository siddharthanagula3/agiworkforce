## Critical scoping correction (read first)

There are **two parallel web chat shells** in the repo. Only one ships:

- **LIVE:** `/chat` and `/chat/[sessionId]` render `apps/web/features/chat/pages/WebChatPage.tsx`, which uses the `@agiworkforce/ui` `Sidebar`, `ChatComposerNew`, `ChatMessageList`, `GreetingBanner`, in-shell `ArtifactsPanel` + `ResearchPanel`, and a header with a real Share button.
- **DEAD (web):** `WebShellV3` / `WebSidebar` / `WebEmptyChat` (rendered only by `UnifiedChatPage`) — nothing in `apps/web/app` imports `UnifiedChatPage`; its sole reference is a test mock (`apps/web/features/chat/pages/__tests__/chat-route.test.tsx`). The unified-chat `ChatInterface` / `ChatInput` / `QuickChips` / `ConversationHeader` are likewise not on the web chat path.

Net: the shipped web chat shell is **closer to reference parity than a code skim suggests** — Share, in-shell artifacts, research/sources panel, greeting+composer co-located, and an upgrade affordance all already exist. The honest gap list below is therefore shorter and skews Medium/Low. The dead second shell is a code-hygiene item, not a visual gap.
