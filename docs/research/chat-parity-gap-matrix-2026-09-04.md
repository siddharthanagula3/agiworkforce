## 2. Waves (disjoint files, each verified in a browser before the next starts)

1. Wave 0 (now): P0 send reliability; P0 sidebar collapse rail and reopen.

Wave 1: composer (ChatComposerNew.tsx, ComposerFooter.tsx, ComposerInput.tsx, composer tokens in chat.css); transcript (ChatMessageList.tsx, MessageBubble.tsx: spacing, hover-gated action row, bubble width, streaming cursor, follow-up chips off); streaming presentation (AgentActivityTimeline.tsx, ToolTimeline.tsx, the activity row's move into the turn: this touches WebChatPage.tsx, so it runs after the shell agent or by the same agent).
3. Wave 2: shell (WebChatPage.tsx header and landmarks, Sidebar.tsx rows as links, section labels, rail); vendor branch removal in the composer; keyboard contract for the connectors submenu.
4. Wave 3: model picker rows and trigger; code block header and padding; prose scale; dark theme measurement and token fixes.
5. Wave 4: mobile re-measure at 390 and fixes; drawer verification.

Each wave ends with the probe run again on localhost at 1543 and 390, in light and dark, and a row-by-row delta against the Shared column recorded as an iteration entry in docs/research/chat-parity-iterations-2026-09-04.md.

## 3. Acceptance states

The thirty-six states named in the brief are the checklist; each iteration entry names the state tested, the reference, the observed gap, the cause, the change and the verification. States: fresh chat; sidebar expanded; sidebar collapsed; two messages; long conversation; streaming; long streaming; manual scroll up while streaming; markdown; nested lists; large table; inline code; long code block; copy code; multiple attachments; image attachment; long prompt; composer at maximum height; editing a previous message; retry; regeneration; stop; error response; tool call; multiple sequential tool calls; tool failure; artifact; citation interaction; model selector; conversation menu; search; narrow desktop; tablet; mobile; mobile sidebar; mobile keyboard and composer.
