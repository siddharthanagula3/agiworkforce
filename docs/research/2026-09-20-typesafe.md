# TypeSafe System One research

Status: Dated research
Owner: AI platform maintainers
Research date: 2026-09-20

Follow-up: [browser, desktop and mobile action control](2026-09-20-jev-action-control.md)
examines current implementations, parallel action/target selection, supplied-value typing,
published performance evidence and the concrete integration point in this repository.

Start with the [official documentation index](https://docs.typesafe.ai/llms.txt).
The [source manifest](evidence/2026-09-20-typesafe-sources.json) records retrieved official Markdown
URLs and content hashes. The official [agent skill](https://github.com/typesafe-ai/skills/blob/main/skills/typesafe-ai/SKILL.md)
was read directly; no second SDK or global skill installation was needed.

The API evaluates supplied state against independent questions in one request. Choice
compares known alternatives, Score reports an expected position over described levels, and
Noul reports a yes-probability without a separate confidence field. Question identifiers are
not model instructions. Confidence summarizes a distribution, not a correctness or
permission guarantee. State and criteria must be narrowly relevant. See
[primitives](https://docs.typesafe.ai/primitives), [state](https://docs.typesafe.ai/concepts/state),
[confidence](https://docs.typesafe.ai/confidence), and [advanced structure](https://docs.typesafe.ai/primitives/advanced).

The current [models page](https://docs.typesafe.ai/models) lists a stable version, movable
aliases, input-only pricing and text-only input. Live account/route availability must be
verified separately. This study used the returned pinned version recorded in its evaluation
report. Configured pricing is a dated evaluation input, not a permanent product constant.
The [JavaScript SDK](https://docs.typesafe.ai/sdk/javascript) matches installed 0.6.0.
Its declarations confirm a per-attempt timeout, automatic retries by default, and optional
body-bearing debug logs. The adapter disables retries/logging and supplies explicit timeout,
model and URL. The [HTTP contract](https://docs.typesafe.ai/api) defines the response fields.

The [jaggedness page](https://docs.typesafe.ai/model-jaggedness/jev-1.13), reviewed by the
vendor on September 17, identifies literal interpretation, numerical/date precision,
indirection, irrelevant context, adversarial content and inconsistent structural invariants.
Keep arithmetic, authorization, normalization, database writes and irreversible actions in
code. Do not turn bounded choices into an arbitrary string generator. The
[building guide](https://docs.typesafe.ai/concepts/how-to-build-with-system-one) supports
narrow judgments composed by ordinary application control flow.

The [fan-out pattern](https://docs.typesafe.ai/patterns/fan-out) batches independent
questions; it does not make dependent retrieval stages disappear. [Confidence routing](https://docs.typesafe.ai/patterns/confidence-routing)
requires task-specific risk gates. [Composite scoring](https://docs.typesafe.ai/patterns/composite-scoring)
is appropriate only when dimensions genuinely compensate; a serious violation should not
be averaged away. [Intent routing](https://docs.typesafe.ai/patterns/intent-routing) is a
semantic front end to deterministic handler selection, not a replacement for business rules.

The [skill cookbook](https://docs.typesafe.ai/cookbooks/skill_suggestion) ranks descriptions,
then reads more evidence for a shortlist; it retains the agent's judgment and can reject
all candidates. Its published roster and labels differ from this repository. The
[function-calling cookbook](https://docs.typesafe.ai/cookbooks/function_calling) selects known
functions/enum arguments. It does not solve arbitrary argument generation. Our candidate
experiment uses one request because all six descriptions fit; a full-catalog evaluation
must decide whether a second evidence stage earns its additional round trip.

[RAG classification](https://docs.typesafe.ai/cookbooks/classifying_rag_passages) separates
relevance, answer evidence, contradiction and injection. Contradiction can be useful evidence,
not a reason to discard. [Reranking](https://docs.typesafe.ai/cookbooks/rerank_typesafe)
judges query/candidate pairs after retrieval. [Line search](https://docs.typesafe.ai/cookbooks/semantic_find)
combines relative ranking with absolute answer presence, since a winner exists even when
all candidates are irrelevant. These are patterns to evaluate, not proof that this product
should replace its already deterministic RRF/coverage ranker.

[Citation checking](https://docs.typesafe.ai/cookbooks/citation_check) first checks literal
quote presence in code and then checks semantic support. Its exact-match fabrication label
requires care with paraphrases. [Guardrails](https://docs.typesafe.ai/cookbooks/llm_guardrails)
provide supplementary hazard signals, not immunity to adversarial content. Existing tool
permissions, tenant isolation and egress remain necessary regardless of the verdict.

[Extraction cascades](https://docs.typesafe.ai/cookbooks/sde_cascade) retain a generator and
use field-grounded checks to trigger escalation. The example includes a fixed fabricated
extraction; reproducing that example is not an end-to-end live quality result. [Date extraction](https://docs.typesafe.ai/cookbooks/date_extraction_cookbook)
resolves dates in code. [Pre-parsed extraction](https://docs.typesafe.ai/cookbooks/pre_parsed_value_extraction_cookbook)
selects existing candidates and copies exact spans, so missing candidates remain a hard limit.

[Hierarchical classification](https://docs.typesafe.ai/cookbooks/hierarchical_classification)
uses multiple retained branches when a greedy early choice is unreliable. [Entity alignment](https://docs.typesafe.ai/cookbooks/entity_alignment)
includes a review outcome instead of forcing a merge. [Classification with confidence](https://docs.typesafe.ai/cookbooks/classification_using_confidence)
can back off to a parent category; that is useful only if the coarser category is acceptable
to the caller. None authorizes a destructive database operation.

[Parallel questions](https://docs.typesafe.ai/cookbooks/parallel_questions) compares batching
with serial calls on cached examples; its speed ratio is not a comparison with concurrently
issued requests. [Noul self-consistency](https://docs.typesafe.ai/cookbooks/consistency_noul_cookbook)
and [Choice self-consistency](https://docs.typesafe.ai/cookbooks/consistency_choice_cookbook)
study repetitions/uncertainty. Some experiments change an irrelevant input identifier, so
variation can mix sampling noise and input sensitivity. Many cookbooks ship cached runs
from earlier versions: cached rerendering is not a fresh provider benchmark.

The [launch article](https://typesafe.ai/blog/introducing-system-one-models-and-jev) describes
parallel sampling and calibrated-decision training. Its speed/cost figures are vendor
measurements, not this product's gains. The [workflow evaluations](https://evals.typesafe.ai)
assume the harness is correct and use frontier-model consensus as reference labels. They
measure agreement under that premise, not independent domain correctness. Our tests must
validate the harness and consequences too.

Implementation, measured results, rejected uses and remaining rollout gates live in the
[canonical integration audit](../specs/semantic-decisions/audit.md).
