# Volume 39 — Output Directory Structure

Status: Canonical · domain volume (depth of Master Spec Vol 39)
Authority: this manual; per-surface output paths defined in `docs/strategy/12-website-production-plan.md`, `13-mobile-production-plan.md`, `14-desktop-production-plan.md`. Related: Vol 14 (Artifacts), Vol 15 (Files), Vol 25 (Storage), Vol 38 (Contracts).

## Philosophy & Cloud/Local stance

"Outputs" are everything the product _generates_: artifacts, exported documents, generated images/audio/video, agent run logs, downloaded models, scratch/temp files, and report bundles. They are distinct from source code and from user-uploaded files. The governing idea is simple: **a generated artifact is not an output until it has a manifest, a storage scope, and a retention rule** — anonymous bytes on disk are a liability, not a feature.

Cloud/Local stance is the whole point of this volume. **Local outputs stay local.** A file generated under the Local trust boundary is written to a Local-scoped output path on the user's device and never leaves unless the user explicitly transfers it (Vol 3/15). **Managed outputs follow the managed retention/deletion policy** (Vol 25/28). An output's `storageScope` and `privacyMode` are set at creation from the active trust boundary and travel with it. The hard rule that protects both code health and trust: **never write generated outputs into source trees** — generated bytes belong in a designated output/scratch location, never beside the code that made them.

## Binding rules

1. **Every generated artifact/file carries a manifest.** At minimum: id, owner (org/workspace/user scope), MIME type, checksum, size, source surface, `privacyMode`, `storageScope`, retention/TTL, and provenance (the run/conversation/tool that produced it) (Vol 14/38).
2. **Every output has a defined storage scope and retention.** No output is written without both. Scope is one of Local / BYOK-derived / Managed; retention follows that scope's policy.
3. **Local generated files stay local.** They are never auto-uploaded, synced, or routed across a trust boundary. Transfer is an explicit, consented user action with a payload preview (Vol 3).
4. **Managed outputs follow retention/deletion policy.** Managed-scoped outputs honor the managed retention window and user deletion/export controls; deletion is real (object + manifest + index), not a flag.
5. **Never write outputs into source trees.** Generated bytes go to the designated per-surface output path or scratch dir — never into `apps/*`, `packages/*`, `crates/*`, or `services/*` source. (Generated _type bindings_ are the one structured exception and live under `*/generated/` — Vol 38.)
6. **Define per-surface output paths in the surface plan.** Each surface declares where it writes outputs, scratch, model downloads, and caches (`strategy/12`/`13`/`14`); code reads those paths, never ad-hoc literals.
7. **Outputs are indexed and discoverable, within scope.** Generated artifacts are findable via global search (Vol 9) but only within the user's trust/RBAC scope; a Local output never surfaces cross-boundary.

## Competitor notes

Claude Artifacts persist with versioning, publish/share, and **per-artifact storage limits (~20MB)** plus the AI-powered-artifacts viewer-pays routing (`strategy/01` §2.2; Vol 14) — every persisted output is a managed object with a lifecycle, never a loose file. OpenAI's Responses runtime uses a **hosted container workspace** for code-interpreter outputs with its own lifecycle (`strategy/01` §3.2). AGI's deliberate divergence: outputs default to the user's _own_ device/scope under Local, with managed hosting as the opt-in path — the same "manifest + lifecycle" rigor, but with the storage location governed by the trust boundary rather than always living on the vendor's infra.

## Checklists

### Creating an output (every generation path)

- [ ] Determine `storageScope` + `privacyMode` from the active trust boundary at creation.
- [ ] Write to the surface's declared output/scratch path — never into a source tree.
- [ ] Generate a manifest (id, owner scope, MIME, checksum, size, source surface, retention/TTL, provenance).
- [ ] Set retention according to scope (Local device policy / Managed retention window).
- [ ] Run a secret-scan on generated content where applicable before persisting (Vol 30).
- [ ] Index for in-scope discovery (global search), respecting trust/RBAC scope.

### Trust-scope enforcement

- [ ] Local outputs are written Local-scoped and never auto-uploaded/synced.
- [ ] No Local output is included in a BYOK/Managed request payload.
- [ ] Cross-boundary transfer (if any) is explicit, consented, with payload preview + redaction hash.
- [ ] A Local output never surfaces in cross-boundary search results.

### Retention & deletion

- [ ] Managed outputs honor the managed retention window.
- [ ] User deletion removes object + manifest + index entry (not a soft flag) for managed scope.
- [ ] User export produces the output + its manifest in a documented, validated format (Vol 38).
- [ ] TTL/forgetting runs for scratch/temp outputs; temp never silently persists.

### Per-surface output paths

- [ ] **Web:** Neon-backed object storage with manifests; no client-side source-tree writes; CDN for served artifacts.
- [ ] **Desktop:** OS app-data dir for local generated files + scratch + caches; model downloads in a dedicated cache; never the repo.
- [ ] **Mobile:** app sandbox (Documents for durable, Caches for transient); SHA-verified model downloads in a managed cache; nothing leaves the sandbox unless transferred.
- [ ] **CLI/IDE/Chrome:** workspace/task-scoped output dirs; no auto app-chat sync (Vol 3/26); local scratch cleaned up.

### Hygiene

- [ ] No generated bytes committed to the repo (CI/`.gitignore` guards source trees).
- [ ] No ad-hoc output path literals in code — read the surface-declared path.
- [ ] Orphaned/expired outputs are reaped (no unbounded scratch growth).

## Definition of Done

The output system is "production-ready" when: every generation path writes only to a surface-declared output/scratch location (never a source tree); every persisted output has a complete manifest with scope + retention; Local outputs are provably Local-only (covered by trust-boundary tests, Vol 32); managed outputs honor retention + real deletion + export; outputs are discoverable only within trust/RBAC scope; and temp/scratch is reaped on a TTL. Per-surface output paths are documented in each surface's production plan.

## Anti-patterns

- Writing generated artifacts/files into `apps/*`/`packages/*`/`crates/*`/`services/*` source trees.
- Persisting an output with no manifest, no scope, or no retention.
- Auto-uploading or syncing a Local-scoped output across a trust boundary.
- "Deleting" a managed output by setting a flag while the object/index persist.
- Hardcoding output path literals instead of reading the surface-declared path.
- Letting scratch/temp accumulate without a TTL (unbounded growth; stale-output leakage).
- Surfacing a Local output in a cross-boundary search or share.
