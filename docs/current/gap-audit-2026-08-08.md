# AGI Workforce Gap Audit and Autonomous Remediation Plan

**Repository:** `siddharthanagula3/agiworkforce`  
**Audit snapshot:** 2026-08-08, current `main` at `fc7184ceb6da370bf1f66c28108562afffa41030`  
**Primary baseline:** the supplied full-stack AI terminology/architecture map, the repository's current source, current GitHub Actions state, `audit/capability-gaps.csv`, `docs/current/parity-implementation-matrix.md`, and current implementation files.

> This is an evidence-led gap plan. It distinguishes:
>
> - **CONFIRMED** — visible in current source or current GitHub Actions.
> - **TRACKED** — recorded by the repository's own gap ledger but not independently revalidated on the current head.
> - **CONFIGURATION / LIVE-PROOF REQUIRED** — code exists, but production configuration or a live end-to-end proof cannot be established from the repository.
> - **DEFERRED / NOT PLANNED** — an explicit product decision, not an accidental omission.
> - **STALE** — an older audit entry contradicted by newer code or newer repository documentation.

---

## 1. Executive Verdict

AGI Workforce is not primarily suffering from missing breadth. It already contains six client surfaces, extensive provider/model infrastructure, local and cloud runtimes, tools, MCP, agent execution, billing, database migrations, release workflows, and a large test suite.

The main gaps are:

1. **Production closure is not reliable.** The latest `main` CI is red, downstream E2E jobs are skipped, and production promotion for the same SHA is skipped.
2. **The CI graph hides independent evidence.** Every expensive E2E lane depends on one large `check` job, so a native-test failure prevents web, mobile, desktop, Chrome, VS Code, and cross-platform lanes from running.
3. **Security gates are not fully blocking.** Semgrep is advisory with a documented pre-existing backlog; some Rust advisory policy is also nonblocking.
4. **Durable automation is below the product promise.** User schedules run only daily and claim at most ten due tasks across the whole deployment per invocation.
5. **Some managed usage is not metered.** The managed audio-transcription proxy calls OpenAI without a reservation/settlement/usage-ledger path.
6. **The connector framework is more complete than the connector product.** The OAuth broker deliberately ships with zero configured providers; most catalog entries are unavailable until an operator supplies endpoints, credentials, and MCP mappings.
7. **Security-sensitive AI artifacts are correctly blocked, but not redesigned.** CAP-052 has a repository-authored NO-GO review covering anonymous wallet DoS, origin/auth contradictions, capability copying, idempotency abuse, and a fail-open concurrency limiter.
8. **Policy storage and policy enforcement are not consistently the same thing.** Browse-domain rules, tenant restrictions, extension access, plugin governance, and reasoning-effort access are tracked as incomplete.
9. **The repository's source-of-truth system is not trustworthy enough for autonomous agents.** Current files contradict one another; several open gap rows are already cut or shipped, while README claims and root links remain stale.
10. **The runtime is broad but fragmented.** Desktop, CLI, web, extensions, and hosted runtime paths still contain duplicate orchestration/provider/MCP behavior and independently evolving semantics.
11. **Several customer-facing capabilities remain partial across surfaces.** Files, connected sources, memory scope, artifacts, research, voice, remote control, reauthentication recovery, and workspace/navigation primitives do not yet have consistent end-to-end behavior.
12. **Enterprise sale blockers remain intentionally deferred.** SAML/SCIM, residency, CMEK, IP allowlists, compliance export, tenant governance, organization analytics, and organization switching are not current-alpha blockers, but they are enterprise blockers.

The correct next move is not another breadth pass. It is a **truth reset followed by production-gate closure, core-runtime closure, and only then surface parity/expansion**.

                Channel adapter / BFF
                       ↓

        Conversation and context services

AGI Workforce has implementation in every major layer, but the maturity is uneven:

### GAP-P0-009 — AI-powered artifacts are security-blocked and must not ship as currently designed

**Status:** CONFIRMED / BLOCKED  
**Evidence path:** `audit/capability-gaps.csv`, CAP-052

The repository's own red-team review identifies:

- anonymous wallet denial-of-service against an artifact publisher,
- opaque-origin authentication contradiction,
- inability to prove the public bridge is structurally absent with a shared renderer,
- copied capability state and weak idempotency enabling repeated billing,
- a fail-open concurrency limiter.

**Required work**

Do not enable CAP-052 until the design is replaced.

Required redesign properties:

- viewer-funded or platform-bounded execution, never an anonymous path billing an arbitrary publisher,
- short-lived capability tokens scoped to artifact, viewer, action, budget, and expiry,
- private and public renderers built as distinct artifacts,
- server-enforced budget and concurrency with fail-closed behavior,
- immutable published artifact snapshot without copied live grants,
- strong idempotency tied to execution intent and billing record,
- complete audit trail and abuse controls.

**Acceptance**

- The security review changes from NO-GO to GO.
- Public artifact execution cannot consume a publisher's unlimited balance.
- Public builds contain no private bridge code.
- Concurrency and budget controls fail closed.
- Red-team regression tests run in CI.

## 9. Source-of-Truth and Documentation Reset

### Problem

The repository has many “current” documents, generated inventories, gap CSVs, known-flaw ledgers, audit reports, README claims, and code comments. They do not always agree.

This is particularly dangerous for an autonomous coding loop: an agent can spend hours rebuilding something already shipped or preserve a false “Done” status because a component file exists but is not mounted.

### Required work

Create one generated, machine-readable capability registry:

```ts
type CapabilityState =
  | 'absent'
  | 'designed'
  | 'implemented_unwired'
  | 'mounted_partial'
  | 'production_verified'
  | 'blocked'
  | 'deferred'
  | 'declined';

interface CapabilityRecord {
  id: string;
  name: string;
  surfaces: string[];
  state: CapabilityState;
  productionMounts: string[];
  runtimeEntryPoints: string[];
  persistence: string[];
  policyBoundaries: string[];
  tests: string[];
  liveProof?: {
    commit: string;
    environment: string;
    evidence: string;
    verifiedAt: string;
  };
  owner: string;
  decision?: string;
  blockers?: string[];
}
```

Generate:

- README capability counts,
- parity tables,
- gap CSV,
- release notes,
- agent backlog views

from this registry.

### Acceptance

- A capability cannot be marked `production_verified` without mount, runtime, test, and live-proof evidence.
- A removed/cut capability cannot remain Open.
- README model count and app versions are generated.
- All root Markdown links resolve.
- Docs-only changes run a documentation/reference CI workflow.
- The legacy dangling-reference allowlist reaches zero for required root/current documentation.
