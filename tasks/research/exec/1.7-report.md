## 3. Edge Cases Handled

### 3.1 WorkSecret Envelope (version-pinned base64url-JSON)

`types.ts:encodeWorkSecret()` serializes to JSON and base64url-encodes. `decodeWorkSecret()` validates:

- `version === WORK_SECRET_VERSION` (= 1) — rejects any other value to block downgrade attacks
- `session_ingress_token` is non-empty — rejects malformed envelopes
- `expires_at > now` — rejects expired envelopes
- base64url parsing failure throws with "malformed" message

Workers call `decodeWorkSecret()` on every received envelope before accepting a work unit.

### 3.2 validateBridgeId Regex (`^[a-zA-Z0-9_-]+$`)

All route handlers call `validateBridgeId(environmentId)` and `validateBridgeId(workId)` before any DB lookup. The regex blocks slashes, dots, percent-encoded sequences — prevents path-traversal attacks. Applied to both `req.params` extractions (via `paramString()`) and user-supplied IDs.

### 3.3 Worker Epoch Bumping

`POST /v1/environments/:id/bridge` increments `worker_epoch` in `worker_registrations` and returns a new `WorkSecret` envelope. Both refresh paths (OAuth re-registration and environment_secret /bridge call) return a fresh envelope containing a new `session_ingress_token`. The design doc explicitly states: callers MUST treat a `/bridge` response as a full transport replacement, not just a header swap. A JWT-only swap that doesn't rebuild the transport will 409 within 20s on the next heartbeat because the epoch is part of every wire message.

### 3.4 Four-Tier Auth Ladder

Each endpoint enforces exactly one auth tier; tiers are not interchangeable:

| Tier                       | Credential                                                                                                          | Endpoints                                                                                           |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 1 — OAuth Bearer           | `Authorization: Bearer <gateway-jwt>` via `authenticateToken` middleware                                            | POST /v1/environments/bridge (register), POST /api/auth/trusted_devices                             |
| 2 — environment_secret     | `X-Environment-Secret` header, SHA-256 hashed + server secret before comparison                                     | POST /archive, GET /work/poll, POST /stop, GET /heartbeat (worker-level), POST /bridge (epoch bump) |
| 3 — session_ingress JWT    | `Authorization: Bearer <session-ingress-token>` — base64url-encoded JSON with environment_id + work_id + exp fields | POST /ack, POST /complete, POST /work/:wid/heartbeat                                                |
| 4 — X-Trusted-Device-Token | Optional alongside Tier 1 (registration) or Tier 3 (heartbeat)                                                      | Logged but not yet enforced (two-flag staged rollout pattern from reference)                        |

All header values extracted via `headerString()` / `paramString()` to handle Express 5 `ParamsDictionary` `string | string[]` type correctly.

### 3.5 Trusted-Device Enrollment

`POST /api/auth/trusted_devices`:

- Gated on `authenticateToken` (Tier 1 — gateway JWT)
- Fetches most recent `account_sessions` row for the user, ordered by `created_at DESC`
- Rejects if no session found (`NO_ACTIVE_SESSION`)
- Rejects if session age > 10 minutes (`ENROLLMENT_WINDOW_EXPIRED`) — mirrors reference `trustedDevice.ts:142-200` `account_session.created_at < 10 min` gate
- Token stored as SHA-256 hash (never plaintext)
- Client side: the enrolled token should be memoized so macOS `security` subprocess (~40ms) is not spawned on every poll (documented in design doc, client responsibility)

### 3.6 Backward-Compat Window

The existing inbound bridge at `/ws` and all legacy routes remain untouched. The worker routers add new path prefixes (`/v1/environments/*`) that do not collide with any existing routes. The 30-day window is tracked via `worker_registrations.worker_type` — once no rows are using the legacy path, the window is considered closed.

### 3.7 Heartbeat Protocol

- Workers POST `/work/:wid/heartbeat` every 30s (HEARTBEAT_INTERVAL_MS constant)
- Missed heartbeats > 90s (HEARTBEAT_OFFLINE_THRESHOLD_MS) mark worker offline
- Background sweep (`startHeartbeatSweep()`) runs every 60s:
  - Queries `worker_registrations` WHERE `status IN ('available', 'busy') AND last_heartbeat_at < now - 90s`
  - Marks each stale worker `offline`
  - Finds all `work_units` WHERE `worker_id = stale_worker AND status = 'assigned'`
  - Reassigns each to the next available worker in the same environment, or resets to `pending` if none
  - Idempotent: two workers receiving the same work unit detect the collision at ack time (second ack returns existing `assigned` state)

### 3.8 Step-Up Auth

`types.ts` exports the `StepUpRequired` interface: `{ code: 'insufficient_scope', required_scope: string, pkce_redirect_url: string }`. The design doc documents the rule: on receiving HTTP 403 + `{ code: 'insufficient_scope' }`, callers MUST NOT attempt a token refresh (per RFC 6749 §6) and must instead start a fresh PKCE authorization flow. The gateway issues this response shape if a future scope-gated endpoint is called without the required scope.

## 9. Architectural Decisions

1. **SHA-256 hash of secrets**: `environment_secret` and `trusted_device_token` are stored as `SHA-256(secret + JWT_SECRET)` — never plaintext. Brute-force is infeasible for 32-byte random secrets.

2. **session_ingress_token as base64url JSON**: Chosen over a signed JWT to avoid `jsonwebtoken` overhead per request. The token embeds `environment_id` + `work_id` + `exp` and is validated inline. Future: replace with a short-lived HS256 JWT when the token refresh scheduler lands.

3. **Long-poll capped at 20s**: Industry standard for server-sent polling. Prevents connection accumulation while still achieving near-real-time work assignment. Workers re-poll immediately on 204.

4. **Background sweep on 60s interval**: Not on-demand to avoid thundering-herd on stale-worker detection. 60s sweep + 90s threshold gives a 30s grace margin before reassignment.

5. **paramString() / headerString() helpers**: Express 5 `ParamsDictionary` types params as `string | string[]`. These helpers normalize to `string | undefined` without silent truncation, keeping the type system honest.
