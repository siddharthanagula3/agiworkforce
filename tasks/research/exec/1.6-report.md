Task 1.6 closes that gap by creating `@agiworkforce/llm-runtime` and migrating consumers to use it.

## 3. Edge cases handled (with citations)

### 3.1 Sticky `RetryContext` (§1.6 edge case 1)

Lifted from `m8 §4` Anthropic `withRetry.ts`. The generator carries `model`, `maxTokensOverride`, `thinkingConfig`, `fastMode`, `consecutiveOverloads`, `attempt`, `fallbackModel`, `signal`, `querySource`, `metadata` across attempts. The operation closure receives `Readonly<RetryContext>` on each call so it can re-derive request params (`maxTokensOverride` is set automatically when a context-overflow error is observed and there is sufficient headroom for the FLOOR_OUTPUT_TOKENS=3000 floor). `CannotRetryError` and `FallbackTriggeredError` cleanly separate retry-exhausted from model-switch.

### 3.2 90-second stream watchdog (§1.6 edge case 2)

`withStreamIdleWatchdog<T>(source, options)` wraps any `AsyncIterable<T>`. Implementation races each `iterator.next()` against a per-chunk `setTimeout`. Critical: the timer is **fresh per chunk**, not a single AbortController consumed once. SDK request-timeout only covers initial fetch; any silent-drop transport failure mid-body would otherwise hang the for-await loop forever. `DEFAULT_STREAM_IDLE_TIMEOUT_MS = 90_000` matches Anthropic's reference. Half-time warning hook (`onHalfTimeWarning`) lets the UI render a "server slow…" indicator before the full timeout fires. `EmptyStreamError` is also exported for `m8 §1.2 phase 5` empty-stream detection (proxy returns 200 + non-SSE OR `message_start` then drop).

### 3.3 Latched session-stable headers (§1.6 edge case 3)

`LatchedHeaderStore` is a per-process Map with FIFO eviction at 64 sessions (vs Anthropic's 10 — see `m8 §5`; we hold more because subagents create more sessions per parent). `latch(sessionId, headerName, value)` is idempotent. Header names are lowercased internally so future merges are case-insensitive. `applyLatchedHeaders(sessionId, outbound, store)` lets callers merge their request headers with the latched set; latched **wins** on collision. The whole point of latching is to preserve the cache key across a feature toggle — once `Anthropic-Beta: fast-mode` has been sent for a session, dropping it busts ~50–70 K tokens of cached prefix on the next turn.

### 3.4 30+ branch error taxonomy (§1.6 edge case 4)

`classifyError(err)` returns `ClassifiedError` with `category` (14 enums), `code` (specific), `retryable: bool`, `fallbackable: bool`, optional `retryAfterSeconds`, `status`, `message`, `providerHint`. Branch order is significant — most specific signals first. Branches: aborted, connection/timeout, server_overload (529 + 503 with `overloaded_error`), rate_limit (429), capacity_off_switch (Anthropic Opus marker), context_overflow (regex matches Anthropic's "input length and `max_tokens` exceed context limit: A + B > C" + OpenAI's `context_length_exceeded`), tool_validation, media_too_large, 413 request_too_large, invalid_model, credit_balance_low, auth (401/403 with `oauth_revoked` / `org_disabled` sub-codes), safety/refusal, pause_turn (Anthropic server-tool resume), generic 5xx server_error, generic 4xx client_error, unknown. Anthropic's overage-disabled-reason header is read into `providerHint` for richer rate-limit messaging.

### 3.5 detectGateway fingerprinting (§1.6 edge case 5)

Two-tier matcher: header-prefix table (9 entries: `x-litellm-`, `helicone-`, `x-helicone-`, `x-portkey-`, `cf-aig-`, `x-kong-`, `x-bt-`, `x-braintrust-`, `x-databricks-`) THEN hostname-suffix table (10 entries). Header match wins over URL match. `gatewayEnforcesUserSideLimits` returns true for all known gateways — the retry generator can use this hint to suppress fallback (a Helicone 429 means the user's Helicone limit, not the upstream provider's; switching models on the same Helicone account is pointless).

### 3.6 Fallback chain from `models.json` (§1.6 edge case 6 — locked rule compliance)

`buildFallbackChain(currentModel, strategy, options)` reads **only** from `@agiworkforce/types` (`getModelMetadataById`, `getModelsForProvider`, `getEconomyFallbackModels`, `getAllowedModelsForTier`). Strategy = `same-provider-cheaper` (Opus → Sonnet → Haiku style: walk same-provider models filtered by qualityTier ≤ current, ordered by cost asc), `economy-tier` (cheapest tools-capable economy models), or `cross-provider` (top model from each OTHER provider, ordered by quality tier). NO model IDs hardcoded anywhere in this module. Tests read the live catalog and assert behaviour generically (e.g., "the chain excludes the current model" rather than "the chain is [X, Y, Z]").

### 3.7 Provider-cloud constructors (§1.6 edge case 7)

Out of scope for the initial package — Bedrock/Vertex/Foundry constructors are gated by Sprint 3 (per `pkg-api-providers-normalize.md` "Effort to reach 100% (days)" sprint plan). The `RetryContext` shape carries everything those constructors will need (`querySource` for Anthropic-style FOREGROUND_529_RETRY_SOURCES gating, `signal` for abort plumbing, `metadata` for the BaseURL/credentials hash a per-cloud `getClient` callback would key against). When Task 3 lands, the constructor abstraction can plug in via the `op` closure inside `withRetry` without any change to the runtime package.

### 3.8 `pause_turn` semantics (§1.6 edge case 8)

The classifier categorises `pause_turn` as its own coarse category — `retryable: false`, `fallbackable: false`. The retry generator surfaces it via `CannotRetryError(originalError, classified)` which downstream callers can catch + branch on `classified.category === 'pause_turn'`. Treat-as-error vs continue-on-pause-turn is a **per-use-case** decision the caller makes — by exposing the category cleanly, `llm-runtime` keeps that policy out of the generic generator. (Anthropic's reference treats it as continue for managed-agent server tools and as error for top-level chat. The decision point lives in the caller's stream-event handler, not in retry.)

## 4. Consumer migrations

All migrations are minimal — they preserve existing public API while replacing inline retry/error fragments with the shared package.

### 4.1 `packages/providers/{anthropic,openai}/src/retry-after.ts`

Both files were verbatim duplicates of the same RFC 7231 parser. Replaced with a one-line re-export from `@agiworkforce/llm-runtime`. The public exports `parseRetryAfter` / `parseRetryAfterFromError` are unchanged so no upstream call site breaks.

### 4.2 `packages/providers/anthropic/src/index.ts`

The `stream()` body is now wrapped in `withStreamIdleWatchdog` (so silent-drop connections surface as `StreamIdleTimeoutError` instead of hanging) and the catch block uses `classifyError(err)` to populate the error chunk's `code` / `retryable` / `retryAfterSeconds` consistently with the rest of the surfaces. `parseRetryAfterFromError` is now imported from `@agiworkforce/llm-runtime` directly (the local re-export still works for any other consumer).

### 4.3 `packages/providers/openai/src/index.ts`

Both Chat Completions and Responses API stream paths get the same migration: `withStreamIdleWatchdog` wrap + `classifyError` in the catch block.

### 4.4 `packages/providers/google/src/index.ts`

Direct-fetch pattern. Two error sites migrated: the `fetch()` throw (network-class failures) and the `!res.ok` non-stream-error path. The latter builds a synthetic SDK-shaped error to feed `classifyError` so retry-after parsing from `Headers` works for free. Stream is wrapped in the watchdog.

### 4.5 `packages/providers/ollama/src/index.ts`

Same pattern as google — direct fetch, two error sites migrated, stream wrapped.

### 4.6 `packages/providers/{xai,deepseek,perplexity,lmstudio}/src/index.ts`

All four reuse the OpenAI SDK with a base URL override + `translateOpenAIStream`. Each got the watchdog wrap on its translated stream + `classifyError` in the catch block. The `withCitationFooter` decorator on the perplexity adapter is preserved (watchdog wraps the post-citation pipeline).

### 4.7 `services/api-gateway/src/routes/providerStream.ts`

The stream-error path now uses `classifyError(err)` so the SSE error-chunk that gets written to the client carries `retryable`, `retryAfterSeconds`, and `code` consistently regardless of which adapter threw.

### 4.8 `services/api-gateway/src/routes/llm.ts`

NOT migrated — this route is the legacy OpenAI-compatible proxy that talks raw HTTP to upstream providers (no adapter). Its hand-rolled SSE pump would require a structural refactor (rewrite to use `buildProviderAdapter`) that is out of scope for §1.6. The route comment explicitly states that "eventually that proxy can migrate onto this pipeline, but not in this PR" — this stays true.

### 4.9 `apps/web/app/api/llm/v2/chat/route.ts`

NOT migrated — uses the Vercel AI SDK (`@ai-sdk/provider-utils`, `streamText` → `toDataStreamResponse`) which has its own retry/streaming abstraction. Migrating would entail rewriting the route off the AI SDK, also out of scope.

### 4.10 `apps/desktop/src-tauri/src/llm/`

NOT migrated in TS — the Rust side has its own `tokio::task::spawn` retry loop. The TS scope of `llm-runtime` doesn't touch Rust. When the desktop's TS-side `command()` wrappers ever issue HTTP directly (currently they don't — they all dispatch via Tauri IPC to Rust), they will pick up `withRetry`.

## 6. Architectural decisions

1. **`@agiworkforce/llm-runtime` is provider-agnostic by design.** No SDK imports (no `@anthropic-ai/sdk`, no `openai`). Errors are read structurally from any object with `{ status, message, headers, response, name, type, error }` fields. This keeps the package as a leaf-of-the-graph with one upstream dependency (`@agiworkforce/types` for the model catalog) — the runtime can be unit-tested in isolation.

2. **Sticky retry context lives on a single mutable object.** Anthropic's reference uses a private closure with an `RetryContext` object; we lift the same shape into a public type. The generator mutates `ctx.consecutiveOverloads`, `ctx.maxTokensOverride`, `ctx.attempt` directly — callers reading `Readonly<RetryContext>` see the updates on the next attempt. This is the simplest path to the §1.6 "model, maxTokensOverride, thinkingConfig, fastMode persist across attempts" requirement without forcing callers to thread state through closures.

3. **The watchdog is a per-chunk timer race, not an AbortController.** An AbortController can only be aborted once. We need to **reset** on each chunk. Wrapping iterator.next() in `Promise.race()` with a fresh `setTimeout` per iteration is the correct primitive. We do clean up the inner iterator on early exit (`iterator.return()` in finally) so the underlying SDK stream releases resources.

4. **Latched headers normalise on lowercase keys.** HTTP headers are case-insensitive but JS object keys aren't. Storing internally as lowercase + merging via `outbound[name] = latched[name]` would lose information when the outbound key has a different case. We accept this — the merged object emitted by `applyLatchedHeaders` may have a mixed-case outbound key shadowed by a lowercase latched key with the same field. Real clients (`fetch`, `Headers`) downcase on the wire so this is wire-equivalent. Tests cover the case-insensitive merge.

5. **Fallback chain reads catalog at call time, not at module load.** `buildFallbackChain` calls `getModelsForProvider` and `getModelMetadataById` for every invocation. This is intentional: the catalog can change at runtime (e.g., user adds a Custom provider via `apps/cli/src/models.rs`), and a freeze-at-load implementation would miss it. The cost is O(catalog size) per fallback call, but the catalog is ~100 entries and fallback only fires on threshold-breaching errors so the overhead is negligible.
