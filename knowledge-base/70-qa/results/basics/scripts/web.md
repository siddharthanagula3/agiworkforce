# Web baseline

Follow the shared capture and scoring rules in [Run protocol](../README.md). Use the scorecard to see which tasks apply to each platform and mode. Each row below is a separate recorded run.

| Task | User action | Expected and recovery checks |
|---|---|---|
| **W-1** Sign up, age step, sign in, sign out and back in | From a signed-out window create a fresh QA account through the public form, complete verification and the age/terms choices with an eligible tester. Sign out and sign back in through the same browser. | Clock each handoff. Verify a single settled workspace with the same identity, then reload. Check that canceling at the age step leaves the protected workspace unavailable. |
| **W-2** Ask a question and get a fast, streamed, correct answer | Open a new conversation. Ask “What is 17 × 19? Give the number, then show the calculation.” | Capture the first painted words and last word. Verify 323 and a valid calculation; refresh and compare. |
| **W-3** Follow up in the same chat with context kept; stop, regenerate, edit a message | Say “Our test parcel code is VELA-74.” Ask for the code, edit the first message to VELA-75, then ask again. Generate a longer answer, stop it, and regenerate. | The active branch uses the edited code, streaming stops, and regeneration has a visible result without losing the transcript. |
| **W-4** Attach a PDF and an image and get answers about them | Attach route-brief.pdf and tiles.png. Ask which station the parcel goes to and how many shapes are in the image. Remove a staged attachment before another send. | Verify Cedar Bay, three shapes, both filenames and readable previews. Reload and check the same attachments. An unsubmitted removed file stays absent. |
| **W-5** Search the web and get an answer with working source links | Turn on web search and ask for the HTML Living Standard publisher and a source. Open the citation in a new tab. | Verify the destination is the official WHATWG standard, the cited content supports the answer and a working link survives reload. |
| **W-6** Choose a model, or leave it on Auto | Open the model picker and deliberately choose an available model. Send a short question; switch to Auto for the next conversation. | Verify selection, per-turn attribution and persistence where advertised. A locked model explains access before consuming credits. |
| **W-7** Generate an image and edit it | Generate an image with a blue circle above a yellow square on white. Edit that result so only the circle becomes red. | Inspect both actual images and their positions. Open the output after reload. No unrelated shape should change. |
| **W-8** Create a document, code or chart artifact, edit it, download it | Ask for an editable HTML artifact that sums 17 and 19 with labeled inputs; change the second input to 20 and export. | View the rendered result, check 36 then 37, reopen the exported artifact and verify its behavior. |
| **W-9** Create a Word, Excel or PowerPoint file and open it | Ask for a Word document, spreadsheet and slide deck summarizing 2 red and 3 blue units, total 5. Download and open each in its normal viewer. | Each real Office file opens, all totals are 5, the sheet has working totals and no slide or document content is clipped. |
| **W-10** Talk by voice and hear the answer | Start voice, speak “What is five plus six?”, listen, interrupt or mute, then stop and revoke microphone permission in a fresh session. | Hear eleven, confirm transcript and mic indicator stop, and verify denied access gives a recovery path without sending recorded audio. |
| **W-11** Make a project with instructions and files, and chat inside it | Create a QA project, give it the instruction “Finish answers with END-42”, upload the route brief and ask its station. Open a separate unrelated chat. | In-project answer contains Cedar Bay and END-42. The unrelated chat does not automatically receive private project content. |
| **W-12** Memory: tell it something, see it used in a new chat, delete it | In a disposable account explicitly save the invented preference “My sample label is hazel kite”. Start a new chat and ask about it. Inspect memory settings. | Verify its source and cross-chat recall. With founder approval remove only the synthetic memory via UI and check a fresh chat and settings. Record deletion pending otherwise. |
| **W-13** Find, rename, pin, archive and delete past chats | Create two run-tagged disposable chats. Find one by search, rename, pin, archive and find it in the archive. | Verify each state after reload, including restore if offered. For deletion use only the named synthetic chat with founder approval and inspect recovery behavior. |
| **W-14** Share a chat by link and open the link signed out | Share a run-tagged synthetic chat; open its link in a signed-out clean profile. Revoke sharing with approval and reopen the link. | Verify only the intended transcript is visible; no owner controls or adjacent chats; revoked sharing no longer shows it. |
| **W-15** Give it a multi-step task (Work) and get the finished result | Give Work the route brief and ask for a three-item dispatch checklist plus a downloadable summary. Watch the steps, interrupt a second throwaway run. | Open the final output, check the correct station and count. Reopen the completed task; stopping the second run must stop further work. |
| **W-16** Schedule a task and receive its result | Schedule a one-time task a few minutes ahead in the displayed timezone to return the parcel code. Close the task view and await the scheduled time. | Verify due time, one delivered result in the intended account, and visible completion time. Avoid a recurring charge or external message. |
| **W-17** Connect one outside app and use it in a chat | Connect a designated test provider account holding only the run-tagged fixture. Use its picker and ask for the parcel code. Test declining consent first. | Declined access yields no connector content; granted access returns VELA-74 with the right file reference. Use only a founder-authorized OAuth recipient. |
| **W-18** Start a cloud coding task on a repository and get a pull request | Use an approved disposable remote test repository, ask the hosted coding task to fix its failing total and open a PR. Review the actual PR in a browser. | The right repo, branch, two-input sum and green test are visible; no extra files, merged changes, or production repository edits. |
| **W-19** See usage and limits; hitting a limit explains what happens next | Read Usage before and after a normal request, then use a prearranged exhausted test account to send one more. Follow its visible recovery path. | Balance and period make sense, denial uses the appropriate Upgrade/waitlist path, and a denied send does not reduce credits. Do not exhaust a live balance to simulate this. |
