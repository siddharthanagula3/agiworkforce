# VS Code · 18. Conversation-level controls

## S18.01 Automatic title.

- **Expected:** A new conversation gets a meaningful title automatically without the user naming it.
- **Code:** done. Evidence moved: apps/extension-vscode/src/features/sidebar-webview/ChatStateManager.ts:5153; apps/extension-vscode/src/core/commandSetup.ts:1243 (quoted code not found in the file now)
- **Where to find it:** no screen of its own. The evidence line apps/extension-vscode/src/core/commandSetup.ts:1243 no longer holds the feature. The title is set in apps/extension-vscode/src/features/sidebar-webview/ChatStateManager.ts (title: text.trim().slice(0, 80) || 'Developer session'). Not a title generated by a model, and I did not confirm the row text in the Sessions sheet.
- **Steps:**
  1. Sign in, open the AGI Code panel and send a first message in a new chat.
  2. Click the Sessions button (title "Sessions") in the panel header.
  3. Compare: the new session's row shows the start of your first message (cut at 80 characters), not a blank row. An empty first message gets the fallback title "Developer session".

## S18.04 Archive and restore.

- **Expected:** A conversation can be archived (hidden, kept) and later restored.
- **Code:** done. Evidence present: apps/extension-vscode/src/features/trees/sessionPickers.ts:134; apps/extension-vscode/src/features/trees/sessionPickers.ts:202; apps/extension-vscode/src/features/trees/conversationTreeProvider.ts:352
- **Where to find it:** Command Palette > Code: Archive Conversation (archive). Restore: Sessions button > Archived sessions, or Command Palette > Code: Show Sessions History > Archived sessions (labels found in the code)
- **Needs:** a session to archive
- **Steps:**
  1. Open the Command Palette and run "Code: Archive Conversation".
  2. Pick the session to archive, then click "Archive" in the modal warning.
  3. Open the Command Palette and run "Code: Archived Sessions" (or click the Archived sessions button in the Sessions sheet).
  4. Select the archived session and click the Restore button (tooltip "Restore"), then compare: the session is back in the normal Sessions list and was not lost.
