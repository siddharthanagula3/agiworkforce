# mobile app

The mobile app (surface:mobile) is an Expo and React Native client for iOS and Android under apps/mobile. It chats with on-device models in Local mode with no sign-in, and with AGI Cloud after Clerk sign-in and consent. It has no own-key mode. Not published: the release registry and the web surface-status file both say "Coming soon", with no store listing verified. Native purchases are off.

## What it is and who uses it

**Purpose.** AGI Mobile is the phone client of AGI Workforce, a Claude/ChatGPT-style assistant. The display name under the icon is "AGI Mobile" (apps/mobile/app.config.js APP_DISPLAY_NAME) [code]. Bundle id and Android package are both `com.agiworkforce.app` (apps/mobile/app.config.js:165, :299) [code].

**Users.** Two groups [code/inferred]:
- People who want private chat on the phone itself (Local mode, the default). No account is needed to reach the app after the age gate and onboarding (apps/mobile/src/features/auth/services/rootRouting.ts `resolveRootRedirect`, signed-out path goes to the app) [code].
- Signed-in people who switch to Cloud mode to use AGI-managed models, projects, sync, tasks, connectors, schedules and the Code companion. Free and paid accounts both can; the plan decides which cloud models and limits apply (apps/mobile/lib/models.ts `getCloudModelsForTier`; apps/mobile/src/features/billing/store.ts reads /api/me) [code].

**Product role.** docs/product/suite.md says Mobile must ship a small Local LLM default, public-alpha Cloud (sign-in gated), preview/share of generated files, and clear privacy labels, and must not expose BYOK in v1 [requirement] (docs/product/suite.md:46).

**Status in one line.** Implemented in code, unpublished in stores, never recorded as run on a store build [code: apps/mobile/src/features/release-state/mobileReleaseState.json].

## Sign-in

**Provider.** Clerk via `@clerk/expo`. The publishable key comes from `EXPO_PUBLIC_CLERK_PUBLISHABLE_KEY`; preview and production builds throw unless it starts with the live-key prefix (apps/mobile/src/integrations/clerk.ts, app.config.js:41-47) [code]. Session tokens are minted from a Clerk token template named by `MOBILE_SESSION_TOKEN_TEMPLATE` in `@agiworkforce/types` [code].

**Methods.** Native `AuthView` plus custom `MobileSignIn` and `MobileSignUp` (email and password flows) and social providers named by `EXPO_PUBLIC_AGI_AUTH_PROVIDERS` (beta and production EAS profiles set google, github, apple) [code: eas.json]. On iOS the app shows either all third-party providers with Sign in with Apple or none (loginProviders.ts, App Store rule 4.8) [code].

**Gates before Cloud.** Age gate (region thresholds, e.g. 18 in India and Brazil; `ageGate.ts`), accepted Terms (`termsAcceptanceStore`), adult eligibility (`adultEligibilityStore`), and a Cloud provider-sharing consent (`services/providerConsent.ts`) [code]. Memory notes say 18+ on every surface with a server-held decision [requirement: owner notes, not a repo file].

**Signed-out use.** `resolveRootRedirect` lets a signed-out person who finished onboarding into `/(app)`; Local mode works without an account [code: rootRouting.ts]. A session that ends while Cloud was active owes a sign-in (`endedSession.ts`) [code].

**Other.** Optional biometric app lock (`useBiometricGate`, expo-local-authentication), step-up checks, a second account on one device (accounts feature) [code]. Review accounts need password sign-in [requirement: owner notes only].

## Modes: Local, own key, Cloud

The persisted mode value is only `'local' | 'cloud'` (apps/mobile/src/features/chat/store/appModeStore.ts:6); default `'local'` (line 62) [code]. There is no third mode value for own key.

| Mode | Supported? | Who | Where it runs | Basis |
|---|---|---|---|---|
| mode:local | Yes, default | Anyone past the age gate and onboarding; no account, no payment | On the phone: system model (iOS Foundation Models, Android AICore) or a downloaded model via ExecuTorch / llama.rn. Chats stored in encrypted SQLite and MMKV. Model files download from a public model host (URLs in the local-llm catalog) | [code] tier1.ts, catalog.ts, storage/db.ts |
| mode:own-key | Not exposed | Nobody | No provider-key entry screen exists in the app. The only API-key sheet is for connectors (`ConnectorApiKeySheet.tsx`). `RemoteChatFeatureFlags.byokKeys` is accepted and never consulted. The egress guard comment still mentions BYOK; suite.md forbids BYOK in v1 | [code] services/remoteChatGate.ts:8-11; [requirement] docs/product/suite.md:46 |
| mode:cloud | Yes, after gates | Signed-in Clerk users with age, Terms and provider-sharing consent. Free and paid | AGI servers: `/api/llm/v1/chat/completions` and, for the Free quota catalogue, `/api/models/free-quota/completions` | [code] cloudModeDoor.ts:94-100, streaming.ts |

**Switch rule.** Every write to the mode store passes `admitAppMode`: Cloud is admitted only when a current provider-sharing consent exists; otherwise the app stays Local and starts the consent flow (cloudModeDoor.ts:94-100). Withdrawing consent returns the app to Local [code].

**Free vs subscribed in Cloud.** The tier store starts every account at Free, then `/api/me` confirms the plan (billing/store.ts, planCheck.ts). The cloud model list is filtered by tier for surface `mobile/cloud-chat` (lib/models.ts:117). Free-quota models come from a catalogue endpoint (model-picker/freeQuotaCatalogue.ts). Limits and entitlements are the server's AGI Subscription system; the phone only reads them (`/api/usage`, `/api/usage/limits`, services/usage.ts) [code]. Which plan names exist is in `@agiworkforce/types`; see the model catalog `packages/contracts/types/src/models.json` (generated) and `packages/ai/model-registry/catalog/models.curation.json`. No model IDs are written here.

**Local is free of payment.** Local chat has no plan check in the route or egress path read; `mapBillingPlanToUIPlan` maps free, byok, basic and local-only to the `local` UI tier (tierGuard.ts) [code]. Local also needs no sign-in [code].

**Selling.** `nativePurchases: false` in src/features/billing/storePurchases.json: no purchase, upgrade, top-up or restore control, no store connection, no Play Billing permission. `FEATURES.billing` is also false. So no subscription is sold inside the app; existing plans are managed on the web [code]. docs/product/suite.md:20 matches [requirement].

## Gaps

Largest known gaps, from the code and the registers (all [code] unless noted):

1. **Unpublished.** No store listing, no `v-mobile-*` tag, no verified App Store Connect or Play record; release workflow never evidenced as run.
2. **No proof on devices.** audit/live-check/mobile-feature-gaps-2026-11-13.md says 21 features were built and checked only by unit tests and typecheck, not on a simulator or phone [requirement/document].
3. **Android.** No Android screenshots, no Android E2E in CI, Android share-intent plugin needs clean prebuild (README).
4. **Account and push lifecycle defects** (open, source-corrected but not runtime-accepted): MOBILE-PUSH-REVOCATION-ORDER-01 (High), MOBILE-LOGOUT-SESSION-LIFETIME-01 (High), MOBILE-SIRI-ROTATION-DISABLE-01 (High), MOBILE-LOCAL-WIPE-CLEANUP-ORDER-01 (High), MOBILE-COLD-START-CLOUD-DEMOTION-01 (Medium: slow start demotes a Cloud user to Local), MOBILE-NOTIFICATION-OTHER-ACCOUNT-TAP-01.
5. **Privacy copy mismatches.** Web privacy policy and Play data-safety notes omit mobile on-device inference and Read aloud via Cloud (MOBILE-PRIVACY-PAGES-LOCAL-01, MOBILE-READ-ALOUD-PRIVACY-COPY-01); store copy says Local chats stay on device while a manual copy to Cloud exists (MOBILE-LOCAL-CHATS-STORE-COPY-01).
6. **Local-model packaging.** llama.rn version range mismatch with `@agiworkforce/local-llm` (MOBILE-LOCAL-LLM-PEER-RANGE-01); memory entitlement unguarded.
7. **Feature gaps vs the leaders.** No study mode, video, Fast mode, local tools; library filters, a push on plain Cloud replies, files in live voice and some coding-session states are left out because the server or a native module is missing (audit/live-check document).
8. **Test suite size.** Full Jest run needs sharding to avoid heap exhaustion (run-jest-shards.mjs; MOBILE-TESTS-RED-ON-MAIN-2026-10-23).
9. **No own-key mode** by decision (suite.md), so users with their own provider keys have no mobile route.
