# F016-04 Copy

Puts the text of a sent message on the clipboard. On web a Copy icon in the message's action row turns into a check for two seconds and shows a 'Copied to clipboard' toast. Mobile has 'Copy Message' in the long-press menu, Chrome has a Copy message button, and the shared desktop bubble has a Copy button. CLI and VS Code have none.

Area: [16. User-message components](README.md). Requirement items: [S16.07](../../10-requirements/capabilities/016-user-message-components.md#s1607).

## 1. Purpose and user value

**What it does.** Copies message.content to the clipboard and confirms it.

**Why it exists.** Every chat surface should offer Copy (docs/product/requirements.md section 6.2) and the brief requires it on sent messages (S16.07).

**Who uses it.** Anyone who wants to reuse or share a prompt.

**Problems it solves**

- Retyping a long prompt.
- Moving a prompt to another tool.

**Use cases**

- Copy a long prompt to tweak it elsewhere.
- Copy a question to paste into a ticket.
- Copy a prompt on phone through the long-press menu.

## 3. Current implementation

From reading the code. Not a test result.

**Working in the code**

- Web: handleCopy writes message.content for user messages (for assistant messages rich blocks are flattened), sets a 2-second check state and toast (MessageBubble.tsx:2271-2286).
- Web: Copy button hidden while that message's isStreaming is true (MessageBubble.tsx:3706-3707).
- Mobile: copyMessage copies message.content (apps/mobile/src/features/chat/components/MessageBubble.tsx:1555-1558).
- Chrome: copy button with failure state (bubbles.ts:482-513).
- Shared bubble: handleCopy with 1.5-second feedback (packages/ui/unified-chat/src/components/MessageBubble.tsx:698-706).

**Incomplete**

- Web handleCopy has no try/catch: a refused clipboard write would reject unhandled and no error toast shows (MessageBubble.tsx:2271-2275) [inferred].
- The shared bubble swallows a clipboard error silently (packages/ui/unified-chat/src/components/MessageBubble.tsx:704-706).
- Brief says web hides Copy while streaming; the code hides it only when that message itself streams, so a user message stays copyable while a reply streams (Copy sits under !message.isStreaming, MessageBubble.tsx:3706).

**Present but disconnected or switched off**

- none found

**Not available**

- User-message Copy in the CLI and VS Code.
- Brief says Chrome is missing Copy; the code shows a Copy message button for user bubbles, so the brief is out of date (bubbles.ts:624-626).

## 4. Required behaviour

**Established requirements**

- A sent user message offers a Copy action that puts its text on the clipboard. (source: capability ledger `audit/ledger/ecosystem-capability-ledger.jsonl`, item S16.07)
- Every chat surface should support or explicitly gate Copy. (source: docs/product/requirements.md section 6.2)

**Acceptance criteria**

1. Web: clicking Copy on a user message puts exactly message.content on the clipboard.
2. Web: after Copy the icon shows a check for about 2 seconds and a toast 'Copied to clipboard' appears.
3. Web: the action row is visible without hover on a touch device.
4. Mobile: long-press then 'Copy Message' copies the text.
5. Chrome: Copy message copies the text; if refused it shows a failed state.
6. Copying twice quickly leaves one timer (the earlier timer is cleared).

**Inferred requirements** (not stated anywhere; reasoned from the code or from competitor parity)

- A failed clipboard write should tell the person; web does not [inferred].
- Copy should include attachment names? Not required by the brief; not done.

**Proposed improvements** (suggestions, not requirements)

- [proposed] Add a try/catch and an error toast on web.
- [proposed] Add Copy to the VS Code message actions and a CLI command to copy a prompt.
