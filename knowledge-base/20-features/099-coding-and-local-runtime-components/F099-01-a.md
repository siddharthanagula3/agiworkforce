# F099-01 a

One coding-session service, the AGI CLI's developer-session host, owns coding threads, turns, approvals and history. The CLI, VS Code and Desktop talk to it over a shared JSON protocol. Cloud Code sessions are listed beside local ones but cannot take turns there. Mobile reaches it only through the relay [inferred].

## 1. Purpose and user value

**What it does.** Holds the state of coding sessions (called threads) in one place: the list of threads, each thread's messages, status, working folder, branch, worktree, trust mode and the single client allowed to write to it. Clients start turns, stream output, steer, interrupt, approve actions and resume threads through one wire protocol. (apps/cli/src/app_server/developer_host.rs:2341, crates/agiworkforce-protocol/src/developer_session.rs:1)

**Why it exists.** So that every coding surface shows the same session instead of each keeping a private copy. The protocol file says it is shared by AGI CLI and AGI for VS Code, and v8 exists so an editor client rides the CLI instead of keeping a second copy of each surface. (crates/agiworkforce-protocol/src/developer_session.rs:1, :32-35)

**Who uses it.** Developers using the AGI CLI, the AGI VS Code extension and the Desktop app's coding view. Engineers building clients against the protocol. The mobile phone reaches desktop coding sessions through the relay (see F099-99).

**Problems it solves**

- Two clients no longer drift apart on the same session: one writer lease decides who may send turns, and others can take over or release it (thread/writer/takeover, thread/writer/release).
- A session started in one app can be resumed, forked, searched, archived, pinned or rewound from another.
- Cloud Code sessions for the same GitHub repository show up in the local thread list (in Managed privacy mode only), so the person sees all work for a repository in one place.

**Use cases**

- Start a coding thread in the CLI, then reopen it in the VS Code sidebar and continue it.
- Open Desktop's coding view, which starts the AGI CLI as its runtime and lists the saved sessions for a folder.
- Interrupt a running turn, answer an approval request, then resume after restart.
- See a cloud Code session next to local threads and be told to continue it on the web or with agi code teleport.

- VS Code: the sidebar chat and chat participant ride the CLI host. Exact visible labels not opened: unknown. (apps/extension-vscode/src/features/sidebar-webview/ChatStateManager.ts, apps/extension-vscode/src/features/chat-participant/chatParticipant.ts)
- Web, Mobile, Chrome: no direct use found. Web only receives cloud sessions; mobile uses the relay. [inferred]

**Before you start**

- The AGI CLI binary must be present and new enough; Desktop refuses a runtime below its minimum version and says to update the AGI CLI or point Settings at a current binary. (apps/desktop/electron/runtime/developerSessionService.ts:1322-1356)
- A WebSocket server needs the environment variable AGI_APP_SERVER_TOKEN, otherwise it refuses to start. (apps/cli/src/lib.rs:6727-6737)
- Cloud threads are listed only when the account privacy mode is Managed, the user is signed in (agi login), and the git origin remote is a GitHub repository. In Local or BYOK mode the list is empty by design (trust boundary). (apps/cli/src/app_server/cloud_threads.rs:34-41, :84-97; apps/cli/src/cloud/client.rs:361-373)

**Screens and controls**

- The protocol exposes thread list, read, resume, fork, compact, handoff, archive, pin, search, checkpoints, rewind, plan, delete, reconnect and writer takeover/release methods. (crates/agiworkforce-protocol/src/developer_session.rs:57-85)
- Turn methods: turn/start, turn/steer, turn/interrupt, with notifications turn/started, output_delta, model, completed, failed, interrupted, agent_event, childTask. (crates/agiworkforce-protocol/src/developer_session.rs:100-116)
- Approval round trip: approval/requested and approval/respond; question round trip: userInput/requested and userInput/respond. (crates/agiworkforce-protocol/src/developer_session.rs:122-126)
- Visible control labels in each client: unknown, not opened.

**Journey**

1. 1. A client starts the host (agi app-server) or Desktop spawns the CLI as a child process.
2. 2. The client sends initialize with its protocol version and gets the server's version and capabilities; an unsupported version is refused with code -32005. (crates/agiworkforce-protocol/src/developer_session.rs:36-44)
3. 3. The client sends thread/start (or thread/list then thread/resume).
4. 4. The client sends turn/start with text, image, skill or mention inputs; the host bounds the count and size of items. (apps/cli/src/app_server/developer_host.rs:1650-1700)
5. 5. The host streams turn/output_delta and turn/agent_event; approvals are requested with approval/requested.
6. 6. The turn ends with turn/completed, turn/failed or turn/interrupted.

**What the person sees and gets**

- Thread summaries carry title, model, working folder, provider, trust mode, status, pinned flag, git branch, worktree root, client, repository and writer. (apps/cli/src/app_server/developer_host.rs:1615-1640)
- Cloud threads carry the id prefix cloud: and provider managed_cloud with trust mode managed. (apps/cli/src/app_server/cloud_threads.rs:13, :47-60)
- A turn sent to a cloud thread is refused with: This is a cloud Code session. Continue it on the web, or bring it here with agi code teleport. (apps/cli/src/app_server/cloud_threads.rs:22-26)
- The refusal of cloud threads covers thread resume and turn steer as well as turn start. (apps/cli/src/app_server/developer_host.rs:2948, 4893)

**Settings**

- AGI_APP_SERVER_TOKEN: owner token for WebSocket. (apps/cli/src/lib.rs:6727)
- AGI_APP_SERVER_READ_ONLY_TOKEN with --allow-query-token: a separate read-only credential for URLs. (apps/cli/src/lib.rs:6737-6750)
- Default listen address 127.0.0.1:8788; AGI_CLI_SERVER_ADDR is only a fallback used when the listen argument does not parse as a SocketAddr. (apps/cli/src/lib.rs:6710-6722)
- Allowed origins and allow-public-listen options in WebSocketSecurity. (crates/agiworkforce-app-server/src/lib.rs:39-48)
- Desktop Settings: confirmed path to the AGI CLI binary. (apps/desktop/electron/runtime/developerSessionService.ts:368-376)

## 4. Required behaviour

**Established requirements**

- One coding-session service owns session state for every client. Status in the brief: platform done. (source: capability ledger `audit/ledger/ecosystem-capability-ledger.jsonl`, item S99.01)
- The wire protocol is stable and shared by the CLI and VS Code; every v8 method is additive. (source: crates/agiworkforce-protocol/src/developer_session.rs:1-35)
- Local, own-key and managed cloud are separate trust boundaries; nothing may silently route a Local session to another boundary. (source: AGENTS.md section 6)

**Acceptance criteria**

1. A thread started through the host from one client appears in thread/list from a second client for the same folder.
2. Only the writer-lease holder can send turn/start; another client must take over or release first, and thread/writer_changed is emitted.
3. A client announcing an unsupported protocol version is refused at initialize with error code -32005.
4. A WebSocket server started without AGI_APP_SERVER_TOKEN does not start.
5. A cloud thread (id prefix cloud:) appears in the list only when the account privacy mode is Managed, the user is signed in and the repository matches, and turn/start on it is refused with the continue-on-web message. In Local or BYOK mode no cloud threads are listed or read. (apps/cli/src/cloud/client.rs:366-373)
6. A turn with more input items than the limit is rejected with an invalid-request error.

**Inferred requirements** (not stated anywhere; reasoned from the code or from competitor parity)

- Trust mode (local, byok, managed) shown on every thread summary is the visible provider label AGENTS.md requires. [inferred] (apps/cli/src/app_server/developer_host.rs:1625-1630)

**Proposed improvements** (suggestions, not requirements)

- [proposed] Publish the protocol as a documented page generated from the method constants so client authors do not read Rust.
- [proposed] Let Web or mobile attach to the same host through the relay with a documented capability list.

## Second reader's check

A second reader checked 11 statements of this page against the code: 7 correct, 4 wrong or partly wrong, 0 could not be checked. The statements found wrong were corrected on this page; they are listed here for the record.

- **Partly wrong (section 2/8):** "Listing cloud sessions needs a signed-in account (agi login) and a GitHub origin remote" The code shows: CloudClient::connect first calls admit(privacy), which refuses any session whose privacy mode is not Managed (NotManaged). Only then does it need a stored JWT. A Local or BYOK session therefore gets no cloud threads even when signed in. list_in returns empty on any connect error. (apps/cli/src/cloud/client.rs:361-373; apps/cli/src/app_server/cloud_threads.rs:84-90). **Corrected:** Cloud threads are listed only when the account privacy mode is Managed, the user is signed in, and the origin remote is a GitHub repo. In Local or BYOK mode the list is empty by design (trust boundary).
- **Partly wrong (section 8):** "Cloud list fails or not signed in: read returns unavailable with 'Sign in with agi login'" The code shows: read_in maps CloudError::NotManaged to unavailable(error.to_string()), the not-managed message. Every other connect error gets the 'Sign in with `agi login`' text. (apps/cli/src/app_server/cloud_threads.rs:108-114). **Corrected:** Read returns the not-managed message in Local or BYOK mode, and the 'Sign in with agi login' message only for other connect failures.
- **Partly wrong (section 3/8):** "Writer lease types in apps/cli/src/runtime/writer_lease.rs (not found)" The code shows: The file exists at apps/cli/src/platform/runtime/writer_lease.rs. developer_host.rs imports it as crate::runtime::writer_lease, so a re-export maps the path. (apps/cli/src/platform/runtime/mod.rs:13; apps/cli/src/app_server/developer_host.rs:112). **Corrected:** Path is apps/cli/src/platform/runtime/writer_lease.rs.
- **Partly wrong (section 3/6):** "app-server default listen address 127.0.0.1:8788 via AGI_CLI_SERVER_ADDR; thread/list merges cloud sessions (device and our servers)" The code shows: The default address is 127.0.0.1:8788, and AGI_CLI_SERVER_ADDR is only a fallback used when the listen argument does not parse as a SocketAddr. (apps/cli/src/lib.rs:6710-6722; apps/cli/src/cloud/client.rs:368). **Corrected:** The env var is a fallback for an unparsable listen value. The cloud half of the merge is Managed-mode only.

- The per-turn limit is 128 input items, plus a text character cap and a byte cap of 4 times the character cap (apps/cli/src/app_server/developer_host.rs:128-131). Section 7 names the constants but gives no values.
