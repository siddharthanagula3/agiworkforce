## 1. Purpose and user value

**What it does.** The record's own text ('Test', 'Click', 'Works') is placeholder text and describes no real behaviour (doc: knowledge-base/data/area-briefs/018-conversation-level-controls.md is the only source of S18.01). The one brief item, S18.01, says a new conversation gets a meaningful title without the user naming it (doc: knowledge-base/data/area-briefs/018-conversation-level-controls.md:5-6). On the web the server first saves a short plain-text cut of the first question, then may schedule a short model-written title (apps/web/app/api/chat/conversations/[id]/messages/lib/persist-message.ts:165-198).

**Why it exists.** A list of chats with blank or identical names is hard to scan and search. An automatic title gives each chat a readable name at once. The web code names the same two-stage pattern the leaders use (apps/web/app/api/chat/conversations/[id]/messages/lib/generate-title.ts:3-13).

**Who uses it.** Every signed-in person who starts a chat on any app. No special role is needed [inferred from the absence of a role check in persist-message.ts:165-198].

**Problems it solves**

- Blank rows in the chat list
- Having to name every chat by hand
- A slow or failing model call must not block sending a message (apps/web/app/api/chat/conversations/[id]/messages/lib/generate-title.ts:12-15)

**Use cases**

- A person on Web asks a long question and sees a 50-character title appear in the sidebar at once, then possibly a shorter model title.
- A CLI user runs a session and later finds it in the list under its first words (apps/cli/src/sessions.rs:327-343).
- A mobile user opens the chats list and sees 'Untitled chat' for a chat with no title (apps/mobile/src/features/chat/ChatsListScreen.tsx:122).

## 2. User experience

**Where to find it**

- Web: no control; the title shows in the conversation header menu button (apps/web/features/chat/components/ConversationTitleMenu.tsx:142-146) and the sidebar [inferred].
- Mobile: chats list row title, falls back to 'Untitled chat' (apps/mobile/src/features/chat/ChatsListScreen.tsx:122).
- CLI: session list; empty title shows '(untitled)' (apps/cli/src/sessions.rs:183-186); CLI also has a '/title' slash command (apps/cli/src/tui/tui_app.rs:6571).
- Desktop, VS Code, Chrome: the brief says done, but I did not open code for the title step on these apps; unknown.

**Before you start**

- Web: a signed-in account and a first user message.
- Web model titling runs only when the conversation's model is not a provider-offering (own-key) model (apps/web/app/api/chat/conversations/[id]/messages/lib/persist-message.ts:190).

**Screens and controls**

- No dedicated control for automatic titling on the web; the person can rename afterwards (see F018-99, S18.02).

**Journey**

1. The person sends the first message in a new conversation.
2. The server marks the conversation active and saves a plain-text title cut to 50 characters, adding '...' if longer (apps/web/lib/chat-title.ts:21-25).
3. The sidebar shows that title.
4. In the background the server may ask a cheap model for a title of 6 words or fewer and replace the provisional one (apps/web/app/api/chat/conversations/[id]/messages/lib/generate-title.ts:49-52).
5. If the person renamed it meanwhile, the generated title is dropped (generate-title.ts:330-352).

**What the person sees and gets**

- The new title in the sidebar and header.
- A failed model call shows nothing; the provisional title stands and a warning is logged (generate-title.ts:12-15).

**Settings**

- None found for turning automatic titles off.

## 4. Required behaviour

**Established requirements**

- A new conversation gets a meaningful title automatically without the user naming it. (source: capability ledger `audit/ledger/ecosystem-capability-ledger.jsonl`, item S18.01)

**Acceptance criteria**

1. After the first message on Web, the sidebar shows a non-empty title with no user action.
2. A first message over 50 characters gives a provisional title ending in '...'.
3. If the person renames the chat before the model title arrives, the rename survives.
4. A model-call failure does not block or fail sending the message.
5. A CLI session list row shows the first words of the first question, or '(untitled)' when empty.
6. Markdown markers in the first message do not appear in the title.
