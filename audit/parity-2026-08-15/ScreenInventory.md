**Audit date:** 2026-08-15 · **Commit:** `e15df56e3` (`compliance/dpdp`), working tree clean
**Purpose:** enumerate every screen that exists in this repo across all seven surfaces, reconstruct every screen the ChatGPT/Codex/Claude benchmark implies should exist, and diff the two sets. This is synthesis of the evidence base already gathered under `audit/parity-2026-08-15/` — no new discovery was performed, except where a specific claim below cites a direct `grep`/`find`/`wc -l` against the repo to confirm a detail the existing inventory docs did not settle (each such case is marked inline).

#### 1.1.3 Product — dev-or-QA (2 routes) — **corrected framing**

| Route                       | What it does                                                                                                                                                                                    |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/qa-artifacts`             | Seeds a fabricated assistant turn (hand-written reasoning, tool timeline, "web search sources") into the real chat store to exercise `ChatMessageList`/`ArtifactsPanel` without a live LLM call |
| `/dev/inline-toolcall-demo` | Same pattern; source contains a literal local-filesystem reference path (`~/Desktop/reference/ui/desktop/claude-artifacts/…`)                                                                   |

The route sweep (a `next dev` HTTP probe) reported both as reachable, unauthenticated, "shipping in the production route tree" — a P1-grade reliability claim. **`gaps/domain-dead-code.md` re-verified this against production behavior and found the sweep's framing wrong:** both routes are guarded by a Server Component `layout.tsx` that calls Next's `notFound()` whenever `NODE_ENV === 'production'`, which is always true for `next build` regardless of hosting tier; both are also listed in `robots.ts`'s `DISALLOW_APP`. `/qa-artifacts` is additionally **untracked and gitignored** (`.gitignore:252`, confirmed via `git ls-files` returning nothing) — it cannot reach a git-based deploy at all. `/dev/inline-toolcall-demo/page.tsx` **is** git-tracked and does contain the stray filesystem-path string, but that string only renders when `NODE_ENV !== 'production'`, i.e. never in a real deployment. **Corrected classification: dev-only harnesses behind a real, tested, multi-layered guard — not a live route-tree reliability defect.** The one legitimate, still-open hygiene item is replacing the literal path string in the tracked file with a generic placeholder (`GapMatrix.md` `DEAD-CODE-011`, P3).
