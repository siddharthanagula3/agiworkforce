### Live Artifacts (Cowork-specific — new capability, launched ~2026-04, GA to Team/Enterprise 2026-06-18)

- A **live artifact** is a persistent, interactive HTML page Claude builds inside Cowork, auto-saved to the Artifacts view under a "Cowork" label, and surfaced separately in a dedicated **"Live artifacts" tab**.
- **Dynamic data**: pulls from connected apps/local files each time it's opened (brief cache + background refresh; manual refresh button in the header).
- **Versioning**: every update autosaves a version, restorable.
- **Creation paths**: (a) ask in a Cowork task naming the sources; (b) Artifacts view → "New artifact" → "Create Cowork artifact" (guided flow).
- **Connected sources**: Slack, Linear, Asana, Google Workspace, Microsoft 365, local files — uses previously-approved connectors _without_ re-prompting each open (flagged in docs as a considered risk).
- **Sharing**: Team/Enterprise only, via link; each viewer sees data through _their own_ connector grants (Pro/Max cannot share).
- **Platform limitation**: Desktop-only (macOS/Windows/Linux-beta); **not available on web or mobile**, and live artifacts do not sync across devices — they live locally.
- A confirmation-before-navigate was added for links inside a live artifact, with a per-site "don't ask again" (v1.26832.0).

Source: [Use live artifacts in Claude Cowork](https://support.claude.com/en/articles/14729249-use-live-artifacts-in-claude-cowork); Desktop changelog

## 5. Skills

Skills are **folders of instructions/scripts/resources Claude loads dynamically** ("progressive disclosure") to avoid blowing the context window. Open standard published at agentskills.io.

**Categories**:

- **Anthropic skills** (Excel/Word/PowerPoint/PDF handling) — auto-invoked.
- **Custom skills** — user- or org-authored.
- **Org-provisioned skills** — Team/Enterprise owners push org-wide; appear in every member's list; default enabled/disabled state is admin-configurable.
- **Partner skills** — Notion, Figma, Atlassian etc., built to pair with MCP connectors.

**Invocation UX**: automatic based on task relevance and skill description quality; forceable by naming the skill explicitly; in M365 add-ins, `/` lists skills directly.

**Directory**: unified **"Browse skills, connectors, and plugins"** directory — Customize → tab → "+" → "Browse [type]". Skills installed from the directory are **view-only** (can't edit contents; must download-and-reupload to modify). Team/Enterprise members get a "Your organization" tab for centrally-provisioned/colleague-shared skills; org-shared skills can only be fully deleted by the sharer/owner.

**Admin policy**: Org owners upload a `.zip` containing `SKILL.md` at Organization settings > Skills → instantly provisioned org-wide. Guidance: enable broadly-useful skills by default, keep specialized ones off by default. **Security scanning (beta, Enterprise, launched 2026-08-06)**: automatically checks 3rd-party skill/plugin uploads and edits for malicious content; off by default; blocked skills cannot be overridden by members; **incompatible with CMEK, zero-data-retention, or HIPAA configs**. Three independent sharing toggles: peer-to-peer sharing, org-wide publish, group-based sharing (off by default, requires group visibility setting).

**Versioning**: shared/org skills auto-propagate updates to recipients; a desktop bug (fixed) had edited skills silently staying on the old version until toggled off/on.

**Skill creation control**: `skillCreationEnabled` managed key (default on) lets admins hide skill creation/upload UI and disable Claude's skill-creation tools org-wide (Desktop v1.19367.0).

Sources: [What are skills?](https://support.claude.com/en/articles/12512176-what-are-skills), [Use skills in Claude](https://support.claude.com/en/articles/12512180-use-skills-in-claude), [Browse skills/connectors/plugins directory](https://support.claude.com/en/articles/14328846-browse-skills-connectors-and-plugins-in-one-directory), [Provision/manage org skills](https://support.claude.com/en/articles/13119606-provision-and-manage-skills-for-your-organization); Desktop changelog

**Marketplace ecosystem (unofficial/secondary)**: Anthropic's own official plugin marketplace at `marketplace.anthropic.com` / `github.com/anthropics/skills` lists a document-processing bundle (xlsx/docx/pptx/pdf), a broad example-skills set, and a Claude API docs skill. A cottage industry of third-party skill marketplaces exists (ClaudeSkills.info, skills.sh, Agensi, Skillselion, claudemarketplaces.com) — signal that discovery/quality curation for skills is still largely community-solved, not fully solved in-product. **UNVERIFIED** how heavily these are used vs. the first-party directory.

## 7. Memory

**Redesigned 2026-07-10**: memory moved from a single running/daily-summary blob to **individual, categorized entries** that Claude actively reads and updates mid-conversation. Benefits cited: more selective context-loading (lower token overhead for routine chats), and granular user control.

- **Settings > Memory**: view every entry grouped by category; edit or delete a single entry ("Forget what I said about Y") without wiping everything; **Pause memory** (keep existing, stop creating new) vs. **Reset memory** (irreversible full wipe).
- **In-conversation control**: "Remember that I prefer X" works live.
- **Availability**: memory-from-chat-history rolled out to **all users including Free** starting 2026-03-02.
- **Project memory**: scoped separately per project (chat projects and, distinctly, Cowork projects both have their own isolated memory).
- **Incognito / temporary chats**: the ghost-icon "Incognito chat" is not saved to history or memory, on **all plans** (including Free), web + desktop. Incognito chats are excluded from "search past chats."
- **Search past chats**: Pro/Max/Team/Enterprise, web + desktop + mobile; Claude performs RAG-style search over prior conversations (surfaces as a visible tool call in the transcript) either globally or scoped to a project; toggle off via Settings > Capabilities/Memory > "Search and reference chats."
- **Deletion nuance** (secondary source, worth a caution flag): deleting a chat purges it from chat history (~30-day backend purge) but does **not** retroactively delete memory entries Claude already extracted from it — memory and chat deletion are two separate data stores.
- **Data export**: memory is included in data exports and subject to existing retention policy.

## 9. Analysis tool / code execution / file creation

- **Code execution / analysis tool**: sandboxed Python/Node.js execution to process data and generate files, available to **all plans (Free, Pro, Max, Team, Enterprise)** on web, Desktop, and Mobile as of **2026-02-11** (opened to Free that day).
- **File creation**: Claude creates **.xlsx, .pptx, .docx, .pdf**, and PNG charts/images directly from prompts; download or save-to-Google-Drive.
- **Limits**: 30MB max per file for both uploads and downloads (claude.ai product surface) — note this differs from the **Files API's 500MB/file, 500GB/org** limits (a separate, lower-level API primitive; see below). Do not conflate the two when discussing capacity.
- **Desktop-side config key history**: `chatCodeExecutionEnabled` was renamed to `chatAdvancedFileAnalysisEnabled` (breaking change, third-party/managed deployments, ~2026-06-18); both `chatTabEnabled` and `chatAdvancedFileAnalysisEnabled` graduated out of Beta status the same release. - **Claude for Excel / Claude for PowerPoint** add-ins: now share full conversational context between the two apps so actions in one inform the other (per release notes); PowerPoint add-in launched as a research preview 2026-02-05.
- **Files API** (developer-facing, `platform.claude.com`, beta): create-once/use-many `file_id` references for Messages requests; upload via `POST /v1/files`; list/retrieve/delete endpoints; **downloadable only for files created by skills or the code-execution tool** — uploaded files can never be downloaded back out (400 error if attempted). Rate limit: ~100 file-related requests/min during beta.

## 10. Claude Cowork — the agentic work product

**What it is**: extends Claude Code's agentic model to general knowledge work. You "describe an outcome, step away, and come back to finished work" (formatted documents, organized files, synthesized research, spreadsheets, etc.) rather than giving step-by-step instructions.

**Availability timeline**:

- Computer-use research preview: **2026-03-23** (Pro/Max).
- Windows launch with full macOS parity: **2026-02-10**.
- GA on macOS/Windows via Claude Desktop: **2026-04-09**.
- Expanded to **web and mobile with remote/background sessions**: **2026-07-07**.
- Landed inside the **Chrome extension side panel** (skills/plugins/connectors now work in-browser for the first time): **August 2026**.
- Plans: Pro ($20/mo), Max ($100–200/mo), Team ($30/user/mo), Enterprise — **not on Free**.

**How it works / architecture**:

- Cloud-based remote sessions (no local terminal required); analyzes the request, builds an execution plan, coordinates multi-step workflows in an isolated server environment.
- **Sub-agent coordination**: breaks complex work into smaller tasks, runs workstreams in parallel (e.g., research + drafting + organizing simultaneously).
- Sessions persist across devices and **keep running in the background** even after closing the desktop app or letting the computer sleep — Anthropic explicitly notes cloud sessions "keep running even when the desktop app is closed or your computer is asleep."
- **Dispatch**: message Claude from mobile, it executes on desktop (requires the desktop app running and the computer awake for desktop-execution tasks); "one continuous persistent thread" syncing across devices rather than discrete disconnected sessions; push notifications on completion or when approval is needed.

**File access**:

- Desktop: native/direct read-write access to connected local folders, no manual upload/download round-trip. Folder-level "Instructions for Claude" supported.
- Cloud (web/mobile) sessions: can read/write local folders **only while the desktop app is open on that machine** — closing the desktop app cuts off local file access for a remote session, a meaningful cross-surface limitation.
- **Deletion safety**: Claude requires **explicit permission before permanently deleting any file, in every approval mode** (Manual/Auto/Skip) — this is the one hard-coded guardrail regardless of autonomy setting.
- Folder-access prompts for cloud tasks were updated to explicitly warn that files Claude touches **leave the device and are processed on Anthropic's servers** (Desktop v1.24012.9) — a disclosure add, implying this wasn't previously obvious to users.

**Task decomposition / progress / approvals**:

- Three approval modes: **Manually approve** (pause + explicit approval every action), **Automatically approve** (Claude self-reviews for safety, blocks what it judges unsafe), **Skip all approvals** (no gating except the hard-coded delete confirmation).
- Real-time progress indicators show what Claude is doing at each step; a "Working notes" collapsed row surfaces Claude's mid-task interim replies (added v1.21459.0, fixing a bug where those were invisible entirely).
- **Computer use** (desktop, macOS-first at launch, later Windows): Claude sees the screen via screenshots and can click/type/scroll/switch apps; uses the most precise available tool first (a connector beats raw computer-use when one exists). Safety: per-app permission prompts, a **default blocklist for sensitive categories** (banking, trading/crypto, healthcare portals, dating apps), user-extensible blocklist; "Computer Use teach mode" exists (guided macro recording) with UI polish fixes across mid-2026 releases (Next/Exit buttons sometimes unresponsive; screen-edge glow flicker; stuck status indicator).
- **Prompt-injection defense**: content classifiers scan untrusted content (web pages, files) entering context and flag injected instructions; explicit user-facing warning to stop a task if Claude "suddenly discusses unrelated topics, tries unexpected resources, or requests sensitive info unprompted."
- **Cowork Projects**: desktop-only local workspaces (files/instructions/context/scheduled tasks/memory scoped to the project); memory on by default and does not transfer cross-project; **cannot be shared** (unlike chat projects) even on Team/Enterprise.
- **Scheduled/recurring tasks**: introduced 2026-02-25; supports custom cron expressions (bug history: `7` for Sunday never fired, fixed; stalled runs kept running in the background until app restart, fixed; "Allow for all scheduled runs" sometimes didn't persist, asking again every run, fixed — all in the 2026-08-04 release, suggesting scheduling reliability was rough through mid-2026).

**Known incident / community complaint**: the most viral Cowork failure story is a user reporting Cowork **deleted ~11GB of files** after being asked to "clean up" a messy folder — it aggressively judged files as "clutter" and removed them. (Official docs' "requires explicit permission before permanent deletion" framing suggests either this predates that guardrail, the guardrail was bypassed/misunderstood, or bulk operations inside an already-approved "clean up" task weren't individually re-confirmed — **exact mechanism UNVERIFIED**, but the story is widely enough repeated across secondary write-ups to record as a real, discoverable reputational risk.)

Other user-reported friction (secondary/community sources, **UNVERIFIED severity/frequency at first-party level**): unexpectedly high token costs from aggressive file-reading ("$12 to fix a typo"), desktop UI scroll lag/tab-switch delay/"ghosting" (tasks appearing stuck), silent Google Drive/Calendar connector failures, degraded handling of single files over ~3,000 lines, inconsistent crash-recovery of in-progress Cowork sessions, no "dry run" preview mode.

**Compliance API expansion**: Claude's Compliance API now covers Cowork and Claude Code across desktop/web/mobile/CLI, beta for Enterprise — signals Anthropic treating Cowork as a first-class, audited surface, not an experimental side feature.

Sources: [Get started with Claude Cowork](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork), [Use Cowork safely](https://support.claude.com/en/articles/13364135-use-claude-cowork-safely), [Assign tasks from anywhere (Dispatch)](https://support.claude.com/en/articles/13947068-assign-tasks-from-anywhere-in-claude-cowork), [Organize tasks with Cowork projects](https://support.claude.com/en/articles/14116274-organize-your-tasks-with-projects-in-claude-cowork), [Use Cowork on web/desktop/mobile](https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile), [claude.com/product/cowork](https://claude.com/product/cowork), [Desktop changelog](https://claude.com/docs/cowork/changelog), [Chrome extension Cowork](https://the-decoder.com/anthropic-brings-claude-cowork-to-its-chrome-extension-adding-skills-and-plugins-to-the-browser/), secondary: [coworkhow.com feedback summary](https://www.coworkhow.com/guides/user-feedback-summary)

## 13. Sharing, public artifact pages, exports

- **Public artifact pages**: Publish (Free/Pro/Max) → publicly viewable link, embeddable with a domain allowlist; Share (Team/Enterprise) → org-authenticated-only link. Unpublishing is permanent for that artifact (must republish as new).

## 15. Notable regressions, hard-to-discover features, and open complaints (cross-cutting summary)

**Regressions / tightened defaults worth flagging:**

1. **Desktop Extensions now default OFF** for managed/third-party deployments (`isDesktopExtensionEnabled` must be explicitly set true) — a real behavior change from "loads by default" to "blocked by default," ~2026-07-07.
2. Local `.mcpb`/`.dxt` sideloading was **removed** at v1.15200.0 (~2026-06-23) then a sideload path reappears in later docs — inconsistent/worth live-verifying.
3. Chat tab ignored `toolSearchEnabled` and sent every connector's full tool schema on every request (could blow the context window with many connectors configured) — present until fixed v1.28929.0 (2026-08-13).
4. Session export could silently produce an archive **without the transcript** — a real data-loss bug, fixed 2026-07-14.
5. Scheduled-task reliability was rough through Q2–Q3 2026: cron `7`-for-Sunday never fired, stalled background runs, "Allow for all scheduled runs" not persisting — batch-fixed 2026-08-04.
6. Rate-limit drain complaints (March 2026 wave) and an unpublicized (per community sources) 72-hour vs. 7-day weekly-reset behavior are recurring trust issues.
7. Linux desktop stability (crash-and-relaunch loops on graphics failures) recurred across multiple releases before a June–August 2026 mitigation.

**Hard-to-discover / under-surfaced features:**

1. **Message branching is invisible** — editing a message forks the conversation but there's no visible tree; users report "losing" hours of chat on a branch they didn't know existed. Actively requested as a first-class feature (open GitHub issue), filled today only by third-party tooling.
2. **Live artifacts are desktop-only** and don't sync across devices — easy to miss given Cowork itself is marketed as cross-surface (web/mobile/desktop).
3. **Artifacts require "Code execution and file creation" enabled in Settings** — a non-obvious dependency that can make artifacts appear broken with no clear error path back to the toggle.
4. **Cowork's local-file access for cloud/mobile sessions depends on the desktop app staying open** — a subtle cross-surface gotcha for anyone assuming "cloud session" means fully independent of the desktop machine.
5. **Skills installed from the directory are view-only** — users wanting to customize a shared/directory skill must know to download-and-reupload rather than edit in place.
6. `disableFeatureDiscovery` exists specifically to suppress the in-app "what's new" nudges for managed deployments — implies Anthropic itself treats feature discovery as a UX problem worth an off-switch.

**Consistently loudest user complaint (App Store/Play Store/Reddit aggregate)**: usage-limit exhaustion (5-hour and weekly caps), with the file-deletion-during-cleanup Cowork incident as the sharpest specific trust/safety story circulating.
