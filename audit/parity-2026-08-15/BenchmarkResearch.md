## 1. Research date and method

**Research date:** 2026-08-15. **Cutoff for "current state" claims:** unless dated otherwise, all facts below reflect the researchers' fetch/search results on that date.

**Method — two independent evidence streams, cross-checked against each other:**

1. **Live web research** (7 documents, ~2,650 lines): WebSearch + WebFetch against official vendor sources where reachable (`support.claude.com`, `claude.com`, `code.claude.com/docs`, `learn.chatgpt.com`, Wikipedia's heavily-cited product pages), plus named-outlet press (TechCrunch, Bloomberg, The Information, InfoQ, The Register, Ars-adjacent trade press), GitHub issues pulled live via `gh` CLI (real reaction counts, not estimates), Hacker News via the Algolia search API, and secondary/aggregator sites used only for corroboration and explicitly flagged as lower-confidence. Files: `chatgpt-web-desktop.md`, `chatgpt-mobile.md`, `chatgpt-work-codex.md`, `claude-web-desktop.md`, `claude-mobile.md`, `claude-code-chrome-ide.md`, `cross-cutting-and-complaints.md`.
2. **Screenshot teardown corpus** (9 documents, ~5,800 lines): a 288-image set of real product screenshots (`chatgpt_reference/`, `references-2/`, `claude_reference/` on the researcher's machine), each image opened and visually inspected — not inferred from filenames. Coverage: ChatGPT iOS shell/settings (34 images), ChatGPT iOS Health/Voice/Work/Remote (44 images), ChatGPT web + macOS + Chrome extension (37 images), Codex macOS shell (9 images), Codex macOS settings (37 images), Codex VS Code extension + iOS remote (29 images), Claude Desktop + Claude Code VS Code extension (39 images), Claude web (27 images), Claude iOS (31 images).

**Screenshots are point-in-time captures of unknown exact date and must be read as such.** File `mtime` timestamps cluster in a narrow window — **2026-07-20 to 2026-07-21** for most of the corpus (Codex macOS settings shows an internal build string starting `26.715...`), with the ChatGPT iOS Health/Voice/Work set spanning two or more separate sessions at unclear dates and the Claude iOS set spanning three sessions (8:44am, 9:10am, 4:49pm on unlabeled days). None of the 288 images carries a visible calendar date; version strings recovered from in-app UI (e.g., Claude iOS `v1.260709.0`, ChatGPT for Chrome `v1.2.27221.15725`) are the only hard anchors, and those anchors sit roughly 3–5 weeks before the 2026-08-15 research date, i.e. **screenshot evidence is systematically about a month older than the live-web-research evidence** and should be read as "a build that existed in that window," not as "shipped, current-state truth as of today." Several screenshots show account state, build flags (an "Extra High"/"Pro" model-picker ladder not matched by any live-research source, a `codex-macos-*` sidebar exposing Hooks/Git/Worktrees/Environments in a way that reads as a converged dogfood build rather than the mainstream consumer app) that the researchers explicitly flagged as **possibly staff/internal/experimental builds, not guaranteed general-availability behavior**. Every screenshot-derived claim in this document inherits that caveat.

**Confidence tiers used throughout:** ① official/primary-fetched (vendor docs, release notes fetched directly, App/Play Store listings) — highest confidence; ② named-outlet press or GitHub-issue-with-live-reaction-count — high confidence; ③ secondary/aggregator sites, community forums, single-source blog posts — flagged inline as such; ④ explicit **UNVERIFIED** — the researchers could not confirm and say so directly rather than guessing. This document preserves tier-④ flags verbatim wherever a claim carries one in the source material; do not upgrade an UNVERIFIED claim to a fact when citing this document elsewhere.

**Known research-tooling gaps — read before trusting an absence of a claim:**

- **`help.openai.com` and most `openai.com/index/*` pages returned HTTP 403 to every automated fetch attempt this session.** Nearly every OpenAI-sourced claim in this document is therefore either a search-result snippet, a third-party mirror (`ai-native-engineer/openai-mirror` on GitHub) of the same help-center article, or press paraphrase — not a live first-party page read. This is a **systematic, one-sided confidence gap**: Anthropic's `support.claude.com` and `claude.com` pages were fetchable directly and are cited as ① throughout; OpenAI's equivalent pages mostly are not.
- **`reddit.com` and `old.reddit.com` were blocked to the fetch tool for every research pass** (ChatGPT and Claude alike). No claim in this document is sourced to a directly-read Reddit thread; where Reddit sentiment is cited, it arrives through a secondary aggregator or a press paraphrase and is flagged accordingly.
- WebSearch quota was exhausted mid-session on the `chatgpt-work-codex.md` pass (200/200 calls used); a small number of intended follow-up queries (exact Codex notification granularity, exact Atlas EOL date, exact August-2026 app-sync migration scope) were left explicitly UNVERIFIED rather than guessed.
- `r.jina.ai` (a common 403-workaround reader proxy) itself returned 401 for a couple of OpenAI Enterprise pages this session and could not be used as a fallback.

Given this asymmetry, **treat ChatGPT-side claims as directionally reliable but less independently verified than Claude-side claims**, and weight any Claude-vs-ChatGPT comparison in this document accordingly — it is not that ChatGPT has fewer sources, it is that fewer of its sources could be read first-party.

## 2. Current ChatGPT product state, by surface

### 2.1 Web and desktop (chatgpt.com + unified desktop app)

OpenAI ran a major, disruptive restructuring of the whole desktop/web shell in July–August 2026. **July 9, 2026**: the separate ChatGPT desktop app and Codex desktop app merged into one Electron-based application (macOS + Windows) housing three modes — **Chat**, **Work** (new agentic/deliverable mode), and **Codex** (dev mode) — with the pre-merge native app demoted to "**ChatGPT Classic**" (still receiving model updates and security patches, but no new agent features). The merge shipped with the plain-chat experience buried in a sub-pane of the new, more complex app; OpenAI reversed that specific decision about a week later (fix landed **~July 17, 2026**) after visible backlash, including OpenAI's own president reportedly calling the app "kind of a mess" at launch. [chatgpt-web-desktop.md §13, cross-cutting-and-complaints.md §6]

**Sidebar (web + desktop), current composite state:** New chat · Search (⌘/Ctrl+K) · **Library** (new ~April 2026 unified file hub — every uploaded and every generated file, cross-chat reuse without re-upload, Aug 2026 Google Drive browsing/@-mention) · **Pinned** (merged pinned chats + custom GPTs + Projects into one collapsible section — reported collapsed-by-default, a discoverability complaint) · **Projects** · **GPTs** (demoted to `More → GPTs → My GPTs`) · **Codex** · **Images** · **Sites** (new, public beta) · **Apps** (renamed from "Connectors") · **Tasks/Scheduled** · **Activity view** (new, ~mid-April 2026) · account switcher · Settings. [chatgpt-web-desktop.md §1.1]

The screenshot corpus's web-settings capture (from a live Pro-20x account, 16-item flat settings list, no grouping) confirms and extends this: **General** (Appearance, Contrast, Accent color, Language, Higher intelligence toggle, **Enable Ultra effort** toggle — "consumes usage limit significantly faster," Enable Dictation) · **Notifications** (8 categories including a first-class **Codex** category ahead of "Group chats") · **Personalization** (Base style/tone, 4 Characteristics dropdowns, Fast answers, Suggested prompts, Custom instructions, a **"Pet"** companion picker, About-you fields, Memory with a "Memory summary → Manage" button, a **Record mode** section for voice-recording-transcript reference — none of these are documented product names outside this capture) · **Plugins** (17+ named connectors/build-targets including "Codex Browser Recorder," a **Developer mode** row) · **Voice** (9-persona carousel, separate Model/Intelligence/Language dropdowns) · **Billing** (plan shown verbatim as **"ChatGPT Pro 20x"**, $212.80 charge observed) · **Usage** (usage pooled across "Codex, Work, Workspace Agents, and ChatGPT for Excel," excludes plain chat; $0 credits + optional auto-recharge) · **Data controls** (includes "Work network access" and "**Reset ChatGPT Work**" as first-class rows, separate from chat data) · **Cloud browser** (own cookie jar, "Always ask" default, per-site override) · **Storage** · **Safety** (single toggle) · **Security and login** (passkeys, MFA, Active sessions, "**Advanced account security**" enroll flow, **Lockdown mode** — explicitly framed to end users as anti-prompt-injection protection, **Developer mode [ELEVATED RISK]** badge, "Enforce CSP in developer mode," and **Codex CLI managed as a connected OAuth app** on this same page with a device-code-auth toggle) · **Parental controls** · **Trusted contact** (opt-in crisis/self-harm-risk emergency-contact escalation, 18+ contact requirement) · **Account** (includes a "GPT builder profile" sub-section) · **Keyboard** (13 independently rebindable shortcuts, Composer + App sections). [shots-chatgpt-web-macos.md §2, §4.1]

The macOS desktop app's settings rail is **grouped** (Personal / Integrations / Coding / Archived) rather than the web's flat list, and — notably — has an entire **"Coding"** group (Hooks, Connections, Git, Environments, Worktrees) with **no web equivalent at all** in this capture, plus a three-rung permission ladder in General: **Default permissions** (ON) → **Auto-review** (ON, explicitly "can make mistakes") → **Full access** (ON — "edit any file on your computer and run commands with network, without your approval," explicit "significantly increases the risk of data loss, leaks" copy). [shots-chatgpt-web-macos.md §1.4, §4.2]

**Canvas**, ChatGPT's writing/coding workspace, was **removed from GPT-5.5 Instant/Thinking on May 28, 2026** and is on a documented glidepath to full retirement — it survives only on legacy models (o3, itself scheduled to retire **Aug 26, 2026**). Two secondary sources disagree on whether Canvas ever executed Python in-browser (one says no, one says yes via a Pyodide-style sandbox) — flagged **UNVERIFIED** in the source, unresolved. [chatgpt-web-desktop.md §5, §16; cross-cutting-and-complaints.md §6]

**Sites** (new, public beta June–July 2026): create/save/deploy/inspect OpenAI-hosted websites, dashboards, internal tools, and games, with in-app environment-variable/secret management — **not available in the EEA, UK, or Switzerland** at launch. [chatgpt-web-desktop.md §6]

**Agent Mode / ChatGPT Work:** Reachable via Tools → Agent mode or typing `/agent` for lighter tasks; **ChatGPT Work** (launched **July 9, 2026**, same day as the desktop merge) is the broader successor — a persistent agentic mode that takes a brief, works in the background for minutes to hours, and returns a finished deliverable (doc, sheet, deck, small web app, or a Site). Not a new paid tier — bundled into Plus/Pro/Business/Enterprise, usage-metered against the plan's allowance like Codex, no published flat per-task rate. Governance: "Plan mode" step-by-step approval before execution, configurable check-in frequency, browser-takeover (agent can't see typed input while user has control), confirmation required before "consequential" actions, and (Enterprise) an Auto-review layer plus a Compliance API. Desktop-only capabilities not available on web/mobile Work: local file access, a built-in browser, and **Computer Use** (click/type/manipulate files on the actual OS). [chatgpt-web-desktop.md §10]

**ChatGPT Atlas**, the standalone AI browser launched **Oct 21, 2025**, was **shut down Aug 9, 2026** — 292 days after launch. No automatic transfer of bookmarks/tabs/history at shutdown (cookies/passwords exportable to the ChatGPT desktop app, bookmarks to Chrome). Its agentic-browsing capability was folded back into ChatGPT/Codex via a new Chrome extension plus a more robust desktop-app browser surface. OpenAI's own stated rationale, echoing the earlier Sora shutdown: "the browser is a feature, not the destination." [chatgpt-web-desktop.md §14; chatgpt-work-codex.md §9]

**Model lineup and picker churn (Feb–Aug 2026):** three-way Instant/Thinking/Pro split → simplified **~June 11, 2026** to plain-language effort labels (Instant/Medium/High/Extra High) plus Pro Standard/Pro Extended, with a new Auto-switch setting → **GPT-5.6 family** (**Sol** flagship, **Terra** cost-competitive, **Luna** fastest/cheapest) shipped **July 9, 2026** → **Aug 6, 2026**: Plus/Pro's separate Instant/Thinking models folded into one GPT-5.6 Sol experience with a reasoning-effort slider as the sole manual control → week of **Aug 6–13, 2026**: GPT-5.6 Luna becomes default for Free/Go with a "Think" button. Notably, **Work and Codex modes deliberately stayed on the "July" point-in-time versions of Sol/Luna** during this August reset — i.e., as of research date, Chat-mode and Work/Codex-mode "GPT-5.6 Sol" are different builds sharing one name, a subtlety worth flagging for any capability comparison. GPT-4o retired from all plans by **April 3, 2026**; GPT-4.5 retired **~late June 2026**; o3 scheduled to retire **Aug 26, 2026**. [chatgpt-web-desktop.md §12, §16] _All model names in this section are OpenAI's own reported public strings, not values from this repo's model registry._

**Sourcing gap:** `help.openai.com/en/articles/6825453-chatgpt-release-notes` and the "Evolving Atlas into ChatGPT" article both returned HTTP 403 on every fetch attempt — the §16 dated timeline in `chatgpt-web-desktop.md` is reconstructed from `learn.chatgpt.com/docs/whats-new` (fetched directly, Codex-and-Work-centric) plus press, not from OpenAI's own consumer release-notes page.

### 2.2 iOS and Android native apps

**Store standing (2026-08-15 App Store/Play Store fetch):** iOS version **1.2026.209** (updated Aug 7, 2026), ~198.4 MB, **4.8★ / 9.4M ratings**, iOS 17.0 min. Android version **1.2026.223** (Aug 13–14, 2026), ~70.9 MB base APK, ~7.2/10 per third-party aggregator (Play Store's own rating not directly fetchable this session). Both stores' "What's New" text is **generic and undisclosed** ("Bug fixes and small improvements") — the real feature history has to be reconstructed from help-center release notes (largely 403-blocked) and press, a genuine discoverability failure for anyone trying to track what shipped. ChatGPT topped Apple's 2025 most-downloaded free iPhone apps list in the US. In-app purchase ladder on iOS: Plus $19.99, Go $8.00, Pro 5x $100.00, Pro 20x $200.00, plus consumable credit packs. [chatgpt-mobile.md §1]

**Navigation — an actively-churning, company-acknowledged-messy surface:** June 3, 2026 sidebar redesign collapsed the mobile drawer into a **horizontal top bar** (Images/Codex/Pulse/Apps) over a chat+Projects list; users reported pinned items "disappearing" and called it "one of their worst rollouts thus far." **July 2026**: OpenAI President Greg Brockman publicly acknowledged the app's navigation is "kind of a mess" and a "tab-free" unified redesign was reportedly planned for end of 2026 — an announced-but-unshipped roadmap item, not current state. [chatgpt-mobile.md §2]

**Voice — the single biggest mobile-relevant change of the period, with a genuine regression:** **July 8, 2026**, OpenAI shipped **GPT-Live** (models "GPT-Live-1" and "GPT-Live-1 mini"), replacing Advanced Voice Mode as the default across iOS/Android/web. Full-duplex, interruptible, backchanneling ("mhmm," "got it") while the user is still talking — architecturally distinct from the old separate STT→LLM→TTS pipeline. Free tier gets the mini model; Go/Plus/Pro get the full model with background delegation to a text model for hard reasoning. **Multiple independent sources confirm GPT-Live shipped without live camera or screen-sharing support**, which the legacy Advanced Voice Mode _did_ have (tap camera icon to share live video; "•••" → Share Screen) — users needing that must fall back to legacy AVM, which apparently remains selectable, with no public parity timeline given. This is a **dated, real regression, still true at the research date**, not a hypothetical. [chatgpt-mobile.md §4] The screenshot corpus separately confirms the legacy-era Advanced Voice onboarding explicitly disclosed **video** recording retention alongside audio ("Meet Voice" screen), and a 9-persona voice carousel (only "Spruce," "Calm and affirming," confirmed by name in captures). [shots-chatgpt-ios-health-voice-work.md §2]

**Health in ChatGPT** — new, real, and platform-gapped: limited beta **Jan 7, 2026**, relaunched with expanded access **July 23, 2026** (US only, logged-in 18+, Free/Go/Plus/Pro). **Explicitly web + iOS only — no Android support**, an unsurprising but confirmed structural gap given the Apple Health dependency. The screenshot corpus is the richest evidence source for this feature: a native HealthKit permission sheet requesting **~49 distinct data types** (including AFib History, ECG, Insulin Delivery, Menstruation, Ovulation Test Result, Sex, Date of Birth — all default-off even under "Turn On All"), a 4-step skippable onboarding (Connect accounts via per-health-system OAuth proxy domains like `epproxy.texashealth.org` → Add conditions via a SNOMED-CT-flavored clinical search, British spellings intact → Add medications via an RxNorm-flavored brand/generic search that also indexes non-drug consumer products like medicated shampoo → Add family history via a curated plain-language list), and a populated dashboard (Activity/Heart/Blood/Body Measurements/Other cards with sparklines, mirroring Apple Health's own taxonomy) with its own persistent medical-disclaimer footer distinct from ChatGPT's generic one. None of this backend detail (OAuth-proxy pattern, SNOMED/RxNorm sourcing) is discoverable from any marketing page. [chatgpt-mobile.md §13; shots-chatgpt-ios-health-voice-work.md §1]

**Sora integration status inside the ChatGPT app is genuinely unresolved.** The standalone Sora app/site was shut down **April 26, 2026** (~$1M/day cost vs. ~$2.1M lifetime revenue, reported); the Sora (2) API is slated to retire **Sept 24, 2026**. A pre-shutdown APK teardown (~March 2026) found unreleased UI strings ("Video in ChatGPT is here," "Create video") suggesting video generation was meant to fold into the main app — but no source confirms a launched, live entry point as of the research date. **Explicitly flagged UNVERIFIED**, not assumed either way. [chatgpt-mobile.md §12]

**"ChatGPT agent" (the old standalone Operator-derived mode) is retired**, per OpenAI's own help-center language (secondary paraphrase, primary blocked): users are pointed to **ChatGPT Work** and a "cloud browser" instead. Mobile-specific limitation: Work is reachable from web/mobile, but mobile/web clients **cannot access local files or use Computer Use** — those require the desktop app. **Codex on mobile** (shipped May 14–15, 2026, all plans incl. Free/Go in preview) is a thin remote-control client, not a coding environment — pair via QR, start/steer/approve, review diffs and test results, but cannot edit files directly or run shell commands locally. [chatgpt-mobile.md §11]

**No offline mode on any platform** (cloud-only inference, longstanding, unchanged). **No official Apple Watch app** (third-party unofficial apps only — Petey/WatchGPT, Wrist AI). **No dedicated iPad-native layout** — relies on iPadOS system multitasking. **No documented deep-link contract** to open a specific chat with a prefilled prompt from another app (a live, unresolved OpenAI Developer Community feature request). **No native "image generation complete" push notification.** [chatgpt-mobile.md §9, §14, §8]

**The "Remote" surface — a previously-undocumented capability discovered only via screenshot exploration**, not named in any marketing/help copy the researchers found: ChatGPT Pro iOS can pair with and remote-drive a **Codex CLI session running on the user's own Mac** via QR/pairing-code, browse that Mac's local project folders, view per-project session history, review collapsible diffs ("30 files changed +53 −52"), see wall-clock "Worked for 27m 58s" run summaries, and set a three-tier approval model (**"Ask for approval"** / **"Approve for me"** / **"Full access (elevated risk)"** — the risky tier's label states its own risk in the picker copy). Model configuration for the remote agent is split into three independently pickable axes: Model, Intelligence, Speed. [shots-chatgpt-ios-health-voice-work.md §3]

### 2.3 ChatGPT for Work/Business/Enterprise/Edu

Product line as of research date: Free/Go/Plus/Pro (consumer) · **Business** (renamed from "Team" Aug 2025, $25/user/mo annual, new **Premium** seat at $125/user/mo launched **Aug 10, 2026**, explicitly framed in coverage as a pre-IPO revenue move giving 5x usage) · **Enterprise** (SSO/SCIM/EKM/data residency/Compliance API/Global Admin Console, custom pricing) · **Edu** (shares most Enterprise admin surface) · **ChatGPT Work** (bundled agent mode, see §2.1) · **Codex** (see §4). [chatgpt-work-codex.md §1]

**Global Admin Console (`admin.openai.com`)**, introduced 2026: a tenant-level control plane above individual workspaces — tabs for Overview, Access (SSO enforcement per workspace: Required/Optional/Off), People, Analytics (unified ChatGPT + Codex spend tracking as of **June 18, 2026**), Billing, and Agents (workspace-agent inventory). SCIM (Okta/Entra/Google Workspace/OneLogin) is **Enterprise/Custom only, not Business**. A documented, real admin trap: disabling "view workspace members and groups" silently breaks the ability to share GPTs/Projects/Chats org-wide, because recipient-picking depends on that same visibility toggle. [chatgpt-work-codex.md §3.1–3.3]

**Company Knowledge** (cross-app "ask your org's data," Business/Enterprise/Edu): citations back to source docs, respects existing per-user source-system permissions — but is **explicitly web-only**, not available on desktop (Windows/macOS) or mobile (iOS/Android) as of research date, a concrete checkable cross-surface gap. [chatgpt-work-codex.md §3.5]

**Compliance/audit:** immutable JSONL exports via a Compliance API, retained **30 days** by default on OpenAI's side (orgs needing longer must pull and store themselves); a separate API-Platform audit-logging toggle is **disabled by default and, once enabled, cannot be disabled again without contacting OpenAI** — a documented one-way switch. EKM (bring-your-own-key via AWS/Azure/GCP KMS) and data residency across ~10 global regions are available at Enterprise/Edu. [chatgpt-work-codex.md §3.8]

**Reported (unverified) Aug-2026 disruption:** OpenAI is reportedly retiring individual-user connector sync for Enterprise/Edu in favor of admin-managed-only sync, which would break existing personally-authorized connector setups — flagged UNVERIFIED, could not corroborate exact scope/date beyond one secondary synthesis. [chatgpt-work-codex.md §3.4]

**Office integrations:** ChatGPT for Excel + Google Sheets went **GA globally May 5–6, 2026**; ChatGPT for PowerPoint (~May 2026) writes into native slide placeholders; **ChatGPT for Word requires a Business/Enterprise account** (blockable by IT) and is explicitly **manual/prompt-driven only — no event-based automation** (can't trigger off document arrival, can't email results, can't chain into calendar/CRM), operating on selected text rather than whole-document batch actions — a real, sourced capability gap versus an "autonomous document agent" framing some marketing implies. [chatgpt-work-codex.md §10]

## 3. Current Claude product state, by surface

### 3.1 Web and desktop (claude.ai + Claude Desktop)

As of Desktop **v1.26832.0 (2026-08-06)**, Chat and Cowork merged into a unified **Home** surface: a single "New" button starts either a chat or a task from one composer, with a separate **Code** tab alongside it. Sidebar: Home (chats+tasks together) / Code toggle, `+ New`, Projects, Artifacts, Scheduled, **Dispatch [Beta]**, Customize, a Recents list mixing chat and task icons, **Design [Labs]** at the bottom, then the account row. [claude-web-desktop.md §1]

**Model picker** (as of research date, per official docs cross-checked against screenshots): **Opus 5**, **Sonnet 5**, **Fable 5**, plus Opus 4.8/4.7/4.6, Sonnet 4.6 under a "More models" expansion, and a fifth, invitation-only tier **Mythos 5** gated to a cybersecurity-program-restricted context. Extended thinking and a separate 4–5-level Effort selector (Low/Medium/High/xhigh[Opus 4.7+]/Max) are **independent controls**, both in the model-name dropdown next to Send; **thinking cannot be turned off for Opus 5** in the web UI (v1.24012.9, July 24, 2026). _All model names here are Anthropic's own reported public strings, not values from this repo's registry — "Fable" and "Mythos" in particular were flagged unfamiliar/unverified by the researchers relative to previously-known Anthropic naming and should be independently checked before being repeated as confirmed fact anywhere outside this competitive-research context._ [claude-web-desktop.md §2, §11]

**Artifacts:** code snippets, HTML/SPA, React components, SVG, Markdown/plain-text, diagrams/flowcharts. Split-view pane, version selector, inline "Edit with Claude" for Markdown, **Publish** (Free/Pro/Max — public link, no login required to view) vs. **Share** (Team/Enterprise — org-auth-only), a 20MB persistent-storage limit, and a real, easy-to-hit dependency gotcha: **artifacts require the "Code execution and file creation" toggle enabled in Settings, and silently stop functioning if a user or admin turns it off, with no obvious error path back to the toggle.** A newer capability — **"AI-powered apps"** — lets a shared artifact call the Claude API directly with no key/billing/deployment step, and deliberately bills usage against the _viewer's_ plan, not the creator's, a cost-shifting design that lowers the bar for sharing small internal tools widely. [claude-web-desktop.md §3]

**Live Artifacts** (Cowork-specific, GA to Team/Enterprise **2026-06-18**): a persistent, interactive HTML page that pulls fresh data from connected apps/local files each time it's opened, auto-saves every version, and is reachable via a dedicated "Live artifacts" tab. **Desktop-only** — not available on web or mobile, and does not sync across devices, a real, easy-to-miss asymmetry given Cowork itself is marketed as cross-surface. [claude-web-desktop.md §3]

**Memory** was redesigned **2026-07-10** from a single running/daily-summary blob to **individually categorized, editable entries** Claude actively reads and updates mid-conversation. Settings > Memory: per-entry delete, **Pause memory** (stop new, keep old) vs. **Reset memory** (irreversible full wipe). Memory-from-chat-history rolled out to **all users including Free starting 2026-03-02**. A real, worth-flagging nuance: deleting a chat purges it from history (~30-day backend purge, secondary-sourced) but **does not retroactively delete memory entries already extracted from it** — memory and chat deletion are two separate data stores. [claude-web-desktop.md §7]

**Skills** are folders of instructions/scripts/resources loaded via progressive disclosure (an open standard, `agentskills.io`). Categories: Anthropic (Excel/Word/PowerPoint/PDF handling, auto-invoked), custom, org-provisioned (Team/Enterprise), partner (Notion, Figma, Atlassian, etc., paired with MCP connectors). A unified **"Browse skills, connectors, and plugins"** directory exists; skills installed from the directory are **view-only** — modifying one requires download-and-reupload, not in-place edit. **Security scanning** (beta, Enterprise, launched **2026-08-06**) auto-checks 3rd-party skill/plugin uploads for malicious content, off by default, blocked skills cannot be member-overridden, and is explicitly **incompatible with CMEK, zero-data-retention, or HIPAA configs**. [claude-web-desktop.md §5]

**Connectors/MCP:** a custom connector is a remote MCP server reachable over HTTPS _from Anthropic's cloud infrastructure_, meaning private/internal MCP servers must allowlist Anthropic's IP ranges. **Desktop Extensions** (`.mcpb`, formerly `.dxt`) are single-click-installable packages replacing manual JSON config. A real, dated regression: **Desktop Extensions now default to NOT loading at all** unless an admin explicitly sets `isDesktopExtensionEnabled: true` (Desktop v1.19367.0, ~2026-07-07) — previously they loaded by default and only the _install UI_ was gated; a documented tightening of prior default-on behavior. Separately, local `.mcpb`/`.dxt` sideloading was _removed_ at v1.15200.0 (~2026-06-23) then a sideload path reappears in later docs — an unresolved inconsistency the researchers flag as needing a live check. [claude-web-desktop.md §6]

**Claude Cowork** — the agentic-work product, extending Claude Code's model to general knowledge work. Timeline: computer-use research preview **2026-03-23** (Pro/Max) → Windows launch with full macOS parity **2026-02-10** → GA on macOS/Windows **2026-04-09** → **expanded to web and mobile with remote/background sessions 2026-07-07** → landed inside the **Chrome extension side panel 2026-08-12/13** (skills/plugins/connectors work in-browser for the first time). Plans: Pro ($20/mo), Max ($100–200/mo), Team ($30/user/mo), Enterprise — **not on Free**. Cloud sessions keep running even after closing the desktop app or letting the computer sleep; sessions persist across devices with push notifications on completion or when approval is needed. **Local file access, browser use, computer use, and live artifacts inside a Cowork session all require the desktop app to stay open** — a cloud/mobile-initiated session cannot touch local folders once the desktop app is closed, a genuine cross-surface limitation. Three approval modes: **Manually approve**, **Automatically approve** (Claude self-reviews), **Skip all approvals** — but Claude requires explicit permission before permanently deleting any file **in every mode**, the one hard-coded guardrail regardless of autonomy setting. The most-viral Cowork failure story: a user reported Cowork **deleted ~11GB of files** after being asked to "clean up" a messy folder, judging files as "clutter" — mechanism unverified but widely enough repeated to record as a real, discoverable trust risk. [claude-web-desktop.md §10]

The screenshot corpus's Cowork task-view teardown independently corroborates and deepens this: a live tool-search JSON request/response renders inline in the transcript (`select:TaskCreate,TaskUpdate,WebSearch,WebFetch`), a persistent non-modal **"Skip all approvals is on"** banner stays visible for the session duration (distinct from the hard folder-access modal, which fires even during a skip-approvals session — first-time folder grants are NOT covered by the global skip setting), and a numbered Progress stepper with a blue-ring "current step" indicator. A separate "Record a Skill" flow (screen-record a workflow → Claude synthesizes a reusable skill) has a genuinely notable failure-mode design: when given an under-informative recording (7 seconds mostly black), Claude **explicitly refuses to synthesize a fake skill**, diagnoses two plausible causes in plain language, and asks a specific clarifying question — no false-success state is shown. [shots-claude-desktop.md Parts 1–2]

**Claude Code Desktop / VS Code extension settings**, per the screenshot corpus's full walkthrough, is unusually deep: separate theme dropdowns with **live diff-preview rendering inside the closed control** (Claude Light / Claude Dark), a Local-sessions section with **Allow bypass permissions mode** (OFF by default, explicit risk copy about data loss/exfiltration via prompt injection), Enable remote control by default (OFF), Dynamic workflows (parallel-agent mode, ON), a Browser section (Browser tools ON, "Persist sessions" dropdown implying Don't-keep/Shared/Separate cookie-isolation modes), an **iOS Simulator** integration toggle, PR automation toggles (auto-PR-creation OFF, Autofix-PRs OFF, auto-archive-on-merge OFF), and a token table showing that **MCP-server access (`user:mcp_servers` scope) was added to newer OAuth tokens but not retroactively granted to older ones** for the same "Claude Code" application — an artifact only visible by comparing scope lists side-by-side. [shots-claude-desktop.md Part 6]

**Usage/limit UX** — a two-meter (5-hour session + separate weekly cap) design, with Max giving 5x/20x allowance but _still weekly-capped_. A community-documented (unverified at first-party level) discrepancy claims the "weekly" cap actually resets on a **72-hour** cadence in practice, not 7 days — Anthropic has not publicly documented this if true. A March 2026 wave of "rate-limit drain" reports (users burning 5-hour windows in 1–2 hours on workloads that previously didn't trigger limits) became a recurring high-volume complaint topic; some users described official explanations as "gaslighting." [claude-code-chrome-ide.md §4.6, §4.7]

## 4. Codex and Claude Code as developer surfaces

### 4.1 Codex — surface map and current state

By mid-2026, Codex is OpenAI's general agent runtime, not "just" a coding CLI — sharing infrastructure with Computer Use, browser automation, and (as of **July 9, 2026**) merged into the ChatGPT desktop app itself. Surfaces: **Codex CLI** (open source, Apache-2.0, **106k GitHub stars / 16.1k forks**, weekly-ish point releases 0.144–0.147 Jul–Aug 2026), **Codex cloud** (`chatgpt.com/codex`, isolated sandboxed containers, no internet during execution except pre-approved repo/deps), **Codex desktop app** (macOS-native ~Feb 2026 → Windows Mar 4, 2026 → merged into ChatGPT desktop Jul 9, 2026 → Linux public preview Aug 11, 2026, `.deb`/`.rpm`, Ubuntu 24.04/26.04, Debian 13, Fedora 43/44, x64+ARM64), **IDE extension** (VS Code + forks: Cursor, Windsurf, plus native Xcode 26.3 integration), **JetBrains plugin** (native since the 2026.3 wave, announced Jan 22, 2026), **Mobile Remote Control** (preview May 14 → GA May 29, 2026, iOS/Android, QR pairing). [chatgpt-work-codex.md §4]

**Models and reasoning-effort:** GPT-5.6 Sol (flagship, every surface) / Terra (balanced) / Luna (cheapest) shipped July 9, 2026; GPT-5.3 Codex Spark (text-only, low-latency, Pro-only, reportedly Cerebras-hosted ~15x faster) from a Feb 2026 launch. Reasoning-effort tiers exposed: Low/Light, Medium (default), High/Extra-High, Max, plus an **Ultra** tier fanning out to parallel sub-agents. GPT-5.4/5.4-mini retire from ChatGPT-authenticated Codex sessions **Aug 31, 2026**. A live, unresolved community dispute: OpenAI's **July 29, 2026** claim that efficiency work makes usage "last around 18% longer" was immediately challenged by an open GitHub issue (#36053, unanswered at fetch) asking for actual per-request distribution data rather than a marketing average. [chatgpt-work-codex.md §5]

**Approval/sandbox model, two independent axes:** `approval_policy` (`on-request`/`untrusted`/`never`/granular object) and `sandbox_mode` (`read-only`/`workspace-write`/`danger-full-access`). `--ask-for-approval never` composes with any sandbox mode — a documented "YOLO" full-auto mode community guides explicitly compare to Claude Code's `--dangerously-skip-permissions`. **Aug 4–5, 2026 (v0.146.1)**: OpenAI shipped "safer automatic-review defaults for cyber-capable models specifically" after presumably identifying elevated risk there. [chatgpt-work-codex.md §6.1]

The screenshot corpus's Codex macOS settings walkthrough independently confirms and sharpens this into a **three-axis model, not two**: Approval policy ("On request") × Sandbox settings ("Workspace write") × a _separate_ Allow-network-access toggle scoped specifically to workspace-write sandbox (OFF by default) — all three simultaneously editable via GUI dropdowns and via a raw, user-exposed `config.toml` with an "Open config.toml" escape hatch. Remote control of the local Mac from a phone or another computer is gated behind **account-level MFA on the ChatGPT web account**, enforced by an in-app modal that hands off to `chatgpt.com` — a cross-surface security dependency invisible from either surface's own docs. Pairing UX: QR code (phone) or a typed `XXXX-XXXX` code (computer), immediately followed by three bundled onboarding toggles (keep-Mac-awake, use-Mac-apps-while-locked, set-up-Chrome-extension). **Two independent, separately-configured "Elevated risk" full-CDP-access toggles exist** — one for the sandboxed built-in browser (single Approval dropdown) and one for the externally-connected Google Chrome extension (four separately configurable Approval/History/Downloads/Uploads dropdowns), both defaulting OFF. [shots-codex-macos-settings.md §12, §2–6, §37]

**MCP:** config lives in `~/.codex/config.toml` (global) or project-scoped, shared across the desktop app, CLI, and IDE extension — one setup propagates everywhere. Top-level key is `mcp_servers` (snake_case, not `mcpServers`). **A real gotcha:** project-scoped MCP config is ignored entirely for untrusted projects until `trust_level = "trusted"` is explicitly set — a new contributor cloning a repo with a committed `.codex/config.toml` won't get its MCP servers by default. Bumped to MCP protocol version 2026-07-28 (Aug 7, 2026) adding paginated tool/resource discovery. [chatgpt-work-codex.md §6.2]

**AGENTS.md:** plain Markdown, no required headings, hierarchical discovery (global → project-root → current-directory, more-local wins). Originally OpenAI/Codex-pushed, by 2026 handed to the **Agentic AI Foundation** (Linux Foundation-directed fund) for neutral multi-vendor governance — same spec now consumed by Codex, Amp, Google's Jules, Cursor, Factory. [chatgpt-work-codex.md §6.3]

**Worktrees, parallel tasks:** a worktree is an isolated git-worktree checkout sharing repo history but its own folder/branch/session — the mechanism for parallel agents on one repo without collisions. Desktop organizes agents into **projects → threads**. **July 23, 2026:** local multi-folder projects (one Codex project can span multiple related folders, one designated primary for git ops). [chatgpt-work-codex.md §6.4]

**Diff review/PR flow:** cloud tasks return a reviewable diff; a PR can be created directly from a cloud result without pulling first, useful for tasks dispatched from Slack/GitHub issues. A GitHub Actions "Codex Code Review" action **resumes the prior review thread on repeat pushes** (caches an isolated Codex home, scopes the new prompt to just the delta since the last-reviewed SHA) rather than re-reviewing the whole diff — genuine CI-level session-resume. `codex cloud exec --attempts 3` runs N independent attempts and returns the best one. [chatgpt-work-codex.md §6.5]

**Local↔cloud handoff:** the documented, first-class pattern is iterate small edits locally, delegate larger tasks to cloud, review results with continuous thread continuity. **Aug 11, 2026:** an `/import` command and desktop import flow explicitly pull in setup from **Claude Code, Claude Cowork, and Cursor** — direct, named competitive targeting worth flagging for any Claude-positioning work; OpenAI is naming Anthropic's products directly in its own onboarding. [chatgpt-work-codex.md §6.6]

**Codex Security (formerly "Aardvark")**, research preview since **March 2026**, Pro/Enterprise/Business/Edu: builds a natural-language model of how a target app works, hypothesizes vulnerabilities, sandbox-tests exploits to rule out false positives, ranks by severity, proposes patches with plain-language rationale — plus a standalone open-sourced Codex Security CLI. Related: **Daybreak** access tiers (Blue = defensive-use, Red = vetted offensive-security research on a purpose-trained "GPT-5.6-Cyber" model), announced **Aug 10, 2026**, gated behind a Trusted-Access approval process, hardware security keys mandatory for all Daybreak accounts from **Sept 1, 2026**. [chatgpt-work-codex.md §6.8; chatgpt-web-desktop.md §10]

**Community complaints (Codex):** the dominant theme across mid-2026 GitHub issues is **erratic, plan-inconsistent, occasionally-spiking token consumption with no per-request attribution** — a strongly evidence-backed weakness spanning at least seven independently-filed issues (#26150, #19607, #30349, #26689, #26306, #31770, #36053) from Apr–Jul 2026, including a reported client/server usage-state mismatch and a 20.5M-token burn in 2–3 hours vs. 4.6M for a prior full day of heavier work. Lower-confidence secondary complaints: inability to interrupt an in-flight run once started, unclear answers on whether uploaded repo code is used for training, Codex silently stripping "useless" comments as a task side-effect. [chatgpt-work-codex.md §7]

The screenshot corpus's macOS Codex shell teardown independently confirms a real, interactive **multi-tab local terminal is embedded in the desktop app** (`siddhartha@Siddharthas-MacBook-Air-2 agiworkforce %`, docking as a full-width band beneath the chat pane, independent of a separate right-hand Review/Terminal/Browser/Files dock — both can be open simultaneously), a **"Sites"** feature (build → deploy → hosted-URL, "Turn your ideas into live websites"), and Scheduled tasks that explicitly reference **calendar and email** integration ("Review recent email and calendar activity") — requiring real connected-account plumbing, not just a cron trigger. **"Computer Use" and "Chrome" ship as opt-in, explicitly-permissioned marketplace plugins**, not silent always-on capabilities. A live usage/credit meter ("5.6 Sol") renders directly in the composer chrome, not buried in a settings page. [shots-codex-macos-shell.md §2.1, §2.3, §2.7, §2.8, §2.9, §6]

### 4.2 Claude Code — surface map and current state

Version baseline at research date: CLI **v2.1.233** (Aug 14, 2026); VS Code extension marketplace also lists v2.1.233; Claude in Chrome extension v1.0.85 (Aug 6, 2026). A five-surface product family sharing one session/account layer: **CLI**, **VS Code extension**, **JetBrains plugin (beta)**, **Desktop app** (Chat/Cowork/Code tabs), **Claude Code on the web** (`claude.ai/code`, cloud sandbox), plus **mobile** (client-only) and the **Claude Agent SDK** (TypeScript/Python). [claude-code-chrome-ide.md §1]

**Adoption vs. satisfaction — a real, notable divergence:** VS Code extension **23,237,666 installs, 3.5★/5 (757 reviews)**; Chrome extension **13,000,000 users, 2.8★/5 (~1.5K ratings)**. Extremely high adoption paired with mediocre store ratings, alongside a long tail of GitHub issues about usage-limit surprises, multi-account support, and terminal rendering bugs. [claude-code-chrome-ide.md §1]

**Auto mode — the single biggest UX shift of the period.** A new `auto` permission mode became the **built-in default starting mode on Pro/Max/Team** (v2.1.228+ mac/Linux/WSL, v2.1.233+ native Windows): a background classifier model (Sonnet 5 by default) reviews every non-trivial action against an extensive, versioned, and startlingly specific default rule set — documented block/allow lists cover `curl | bash`, force-push, `git reset --hard`, unapproved PR merges, secret-manager writes, DNS/TLS changes, disabling CI checks, opening tunnels/reverse shells, printing live credentials to transcript, routing installs around an internal registry, and even **"sending keystrokes to Claude Code's own tmux pane"** (treated as Claude trying to alter its own oversight). It also explicitly reviews **Claude in Chrome browser actions that could send page content, cookies, or credentials off-origin**. Repeated blocks (3 in a row or 20 total) fall back to prompting. Six permission modes total: `default`(Manual)/`acceptEdits`/`plan`/`auto`/`dontAsk`/`bypassPermissions`. Protected paths (`.git`, `.vscode`, `.idea`, `.claude`, shell rc files, `.npmrc`/`.yarnrc`, `.mcp.json`) are never auto-approved outside bypass mode and are a **fixed list, not configurable per-project**. [claude-code-chrome-ide.md §2.5]

**Checkpoints (`/rewind`):** every user prompt creates a checkpoint; the **100 most recent** per session keep file snapshots. Documented, stated-plainly limitations: Bash-driven file changes (`rm`/`mv`/`cp` run by Claude) are **not tracked or restorable**; **subagent edits are not restored by rewind** (only foreground-forked skills are the exception) — explicitly "not a replacement for git." Checkpoints auto-expire after 30 days. [claude-code-chrome-ide.md §2.3]

**Subagents:** Markdown files with YAML frontmatter (`~/.claude/agents/` personal, `.claude/agents/` project), supporting `tools`/`model`/`permissionMode`/`skills`/`memory`/`isolation: worktree`/`maxTurns`/`hooks`/`mcpServers`/`background`. **Forking became the default** in v2.1.232 — a fork inherits the entire parent conversation, tool state, and prompt cache. `isolation: 'worktree'` subagents are hard-blocked from destructive git against the main checkout, including via `git -C`/`--git-dir`/env-var redirection/`cd`-then-git — this required **several hardening passes (v2.1.216, v2.1.222) after real bypasses were found**, i.e. the isolation guarantee was not solid on first ship. Cross-session messaging (`SendMessage`/`ListAgents`, v2.1.224+) lets subagents and separate local sessions message each other by name, with auto mode's classifier reviewing every message before delivery. [claude-code-chrome-ide.md §2.6]

**Hooks:** deterministic shell-command hooks at lifecycle events. Security hardening was a recurring theme: exit-code-2 blocking bugs, `PreToolUse` auto-allow bypasses in background agent tasks, untrusted-folder agent hooks now requiring workspace trust. [claude-code-chrome-ide.md §2.7]

**Skills absorbed custom slash commands** at some point before research date — a flat `.claude/commands/deploy.md` and a directory-based `.claude/skills/deploy/SKILL.md` both produce `/deploy` identically. Skills synced down from claude.ai are sandboxed further (v2.1.228): they can't shadow local commands/MCP prompts and can't run `!` shell substitution or `@` file expansion. [claude-code-chrome-ide.md §2.8]

**Plugins & marketplaces:** two official marketplaces (`claude-plugins-official` auto-registered on first launch; `claude-community` public, reviewed, pinned to commit SHAs, synced nightly). New in the last 6 months: an `archive` plugin source (install from a `.zip` over HTTPS with SHA-256 pinning), **GitLab marketplace support**, immediate plugin activation without restart (v2.1.221). [claude-code-chrome-ide.md §2.9]

**Settings hierarchy** — five layers, ascending precedence: Managed (`managed-settings.json`) → CLI flags → `.claude/settings.local.json` (gitignored) → `.claude/settings.json` (committed) → `~/.claude/settings.json` (personal). A documented, easy-to-hit footgun: `permissions.defaultMode: "auto"` **only takes effect from `~/.claude/settings.json` or managed settings** — setting it in project-level files is silently ignored. [claude-code-chrome-ide.md §2.18]

**CLAUDE.md conventions:** managed → `~/.claude/CLAUDE.md` → `./CLAUDE.md` → `./CLAUDE.local.md`, **concatenated, not overridden**, files closer to the working directory read _last_ (highest recency bias). **`AGENTS.md` is not read directly** — the documented pattern is `@AGENTS.md` import or a symlink. A separate **auto-memory system** writes Claude's own notes to `~/.claude/projects/<project>/memory/MEMORY.md`, capped at 200 lines/25KB, on by default and distinct from CLAUDE.md. [claude-code-chrome-ide.md §2.19]

**VS Code extension** requires ≥VS Code 1.94.0, also installs into Cursor/Devin Desktop/Kiro via Open VSX. Installing the extension does **not** put `claude` on PATH — it bundles a private CLI copy for its own panel; the standalone CLI is still required for terminal use, a real, documented gotcha. **Focus view** (v2.1.221) collapses tool-call noise; **not in the extension** (CLI-only): the full skill/command catalog, full MCP config editing, `!` bash shortcut, tab completion. [claude-code-chrome-ide.md §3.1]

**JetBrains plugin (beta)** — critically, **does not bundle its own CLI**; it launches the standalone binary inside the IDE's integrated terminal, meaning the CLI install is mandatory (not optional as in VS Code). No native GUI chat panel — the UX is the CLI's TUI inside a terminal pane; third-party "GUI" plugins exist unofficially to fill this gap. Jupyter cell execution is **not exposed** on JetBrains (VS Code-only `mcp__ide__executeCode`). A JetBrains-specific security warning is called out that VS Code's docs don't carry: in `acceptEdits` mode, Claude can modify IDE run/debug config files that JetBrains may execute automatically, increasing risk of bypassing permission prompts — the docs explicitly recommend Manual mode for JetBrains specifically. [claude-code-chrome-ide.md §3.2]

**Claude Code on the web / cloud sessions** (research preview, Pro/Max/Team/Enterprise): `claude --cloud "<task>"` starts a session; `--teleport` pulls a cloud session back to terminal **one-way** (no push from terminal to web). Non-GitHub repos (GitLab, Bitbucket) can be sent as a local bundle (≤100MB) but **can't push results back**. ## 6. What each product does better

**The benchmark is not a specification** — several of the items below are choices, not just capability gaps, and some competitor "wins" ship with their own documented costs (see §9). Cited as evidenced strengths, not blueprints to copy verbatim.

### 6.1 What ChatGPT does better

1. **Native image generation is not close.** "ChatGPT Images 2.0" (Apr 21, 2026) does multi-image consistency, ~99% text-rendering accuracy, and 2K output; Claude has **no native image generation**, and Anthropic has confirmed this is a deliberate, not technical, choice. [cross-cutting-and-complaints.md §2.1]
2. **Native video generation.** Sora 2 inside Plus/Pro produces 20-second 1080p clips with synced dialogue/SFX; Claude has nothing in this category. [cross-cutting-and-complaints.md §2.2]
3. **Voice mode multimodality (historically).** Legacy Advanced Voice Mode's live camera input and screen share, plus auto-generated visual "widget" cards (weather/stocks/sports) inside voice conversations, has no Claude equivalent — though note this is now a regressed capability inside ChatGPT itself (§9). [cross-cutting-and-complaints.md §2.4]
4. **A real consumer app-store discovery surface.** GPT Store's claimed 3M+ created / ~159K active custom GPTs dwarfs anything Claude has for _general-audience_ discovery — Claude's equivalents (Connectors Directory, Skills directory, community Code plugin marketplaces) are developer/agent-centric, not a consumer storefront. [cross-cutting-and-complaints.md §2.5]
5. **Real-time web browsing reads as more thorough for raw research collection**, per multiple independent comparison write-ups: "ChatGPT reads like a thorough report; Claude reads like a sharp briefing" — Deep Research does more of the raw collection/organization work, at the cost of being longer and less editorialized. [cross-cutting-and-complaints.md §2.3]
6. **A materially lower enterprise entry point exists on the Claude side, not ChatGPT's** — noted here for completeness of the comparison, not as a ChatGPT strength: ChatGPT Enterprise's reported ~150-seat minimum is a real disadvantage against Claude's 20-seat floor. [cross-cutting-and-complaints.md §2.6]

### 6.2 What Claude does better

1. **Coding benchmarks and the real-world agentic coding loop.** Independent aggregator reporting had Fable 5 at 95 SWE-bench Verified / 80 SWE-bench Pro, ahead of GPT-5.6 Sol on that specific family (Sol led instead on Terminal-Bench 2) — the two labs trade wins on different coding benchmarks, but Claude Code is the more consistently cited "unmatched" terminal-first coding companion across independent write-ups. [cross-cutting-and-complaints.md §3.1]
2. **A more open Publish/share model.** Claude's Publish produces public, no-login links; ChatGPT Canvas share links require a ChatGPT account to even view, and Canvas has no publish-to-web at all — export-and-paste is the only path. [cross-cutting-and-complaints.md §3.2]
3. **Memory Import — a real, unreciprocated switching-cost reducer.** Claude can migrate a user's memory _from_ ChatGPT, Gemini, and Grok. No equivalent "import your Claude memory" feature was found for ChatGPT. [cross-cutting-and-complaints.md §3.3, claude-web-desktop.md §0]
4. **Scheduled tasks keep full tool access.** ChatGPT's native Tasks explicitly strip out voice, file uploads, and Custom GPTs (plain-text-only prompts). Claude Cowork's scheduled tasks and Claude Code's "routines" both retain full Skills/connector access while running unattended. [cross-cutting-and-complaints.md §3.4]
5. **Cowork's serverless/remote execution model is a genuine differentiator.** As of the Jul 7, 2026 web/mobile expansion, Cowork sessions run in Anthropic's cloud "with no device online at all"; ChatGPT Work, by contrast, is described in coverage as needing the (recently rebuilt) desktop client for its fullest capabilities. [cross-cutting-and-complaints.md §3.5]
6. **A lower enterprise floor and earlier FedRAMP High.** Claude Enterprise's 20-seat minimum vs. ChatGPT Enterprise's reported ~150-seat minimum; FedRAMP High authorized via AWS GovCloud for Claude while ChatGPT's process is reported still underway — materially widens who can buy in earlier. [cross-cutting-and-complaints.md §3.6]
7. **Skills as an open, portable standard rather than a walled garden.** The spec is published at `agentskills.io` and (per one ecosystem report) usable across ~40 products — a different strategic posture than OpenAI's Apps SDK/GPT Store, which is ChatGPT-only by construction. [cross-cutting-and-complaints.md §3.7]
8. **Computer Use is OS-agnostic**, a portable screenshot+mouse/keyboard tool working across VMs/containers/remote desktops without an OS dependency, versus OpenAI's now-discontinued browser-only Atlas and its desktop-native replacement — trading some raw browser-task speed (reviewers say Claude "trails on browser-only tasks") for being the only major agent of the three (per one comparison) that can drive an entire desktop. [cross-cutting-and-complaints.md §3.8]

## 10. Features that exist but are undiscoverable

- **Claude**: a paying user's file-creation/code-execution upgrade lives at **Settings > Capabilities > "Code execution and file creation"** and is a hard, silent dependency for Artifacts working at all — if off, artifacts simply stop rendering with no obvious error path back to the toggle. A related independent write-up ("10 features hiding in plain sight," Tom's Guide) separately lists an "Upgraded file creation and analysis" flag buried in **Settings > Features > Experimental**. [claude-web-desktop.md §3; cross-cutting-and-complaints.md §7]
- **Claude**: Team/Enterprise web search requires an **Owner/Primary Owner to first flip a workspace-level admin switch** before any member can turn it on per-chat — a two-layer opt-in that likely explains the recurring "Claude can't search the web" folk-belief that shows up even in 2026-dated comparison articles despite web search being real and documented. [cross-cutting-and-complaints.md §7]
- **Claude**: "Reflect" (monthly usage recap) sits at **Settings > Reflect**, beta, and requires memory to be independently turned on first — a feature most users would not stumble into. [cross-cutting-and-complaints.md §7]
- **Claude Code**: `claude auto-mode defaults` prints the entire auto-mode allow/block rule set as JSON — the only way to get ground truth rather than trusting prose docs, and mentioned nowhere except deep in `permission-modes.md`. `.worktreeinclude` (gitignore syntax, solves the "my `.env` isn't in the new worktree" problem) is undocumented outside the worktrees page itself. The managed `claudeMd` key lets an org embed CLAUDE.md content directly inside `managed-settings.json` — a deployment simplification most admin-docs skimmers would miss. [claude-code-chrome-ide.md §9]
- **ChatGPT**: Agent Mode is reachable only via the `+` tools menu or by typing `/agent` — a slash-command-only discovery path for a capability advertised as a headline feature; Google Play reviews include users "unable to access the 'agent' feature despite paying $20/month," suggesting real entitlement/discoverability confusion, not just a power-user-only feature. [cross-cutting-and-complaints.md §7]
- **ChatGPT**: the "does ChatGPT read Reddit" question is a recurring misconception — ChatGPT can cite Reddit via general web-search grounding but has no dedicated Reddit connector/app; users appear to conflate "cites Reddit sometimes" with "there's a Reddit integration." [cross-cutting-and-complaints.md §7]
- **ChatGPT**: the "Remote" desktop-pairing surface for Codex-on-mobile (§2.2 above) was discovered by the screenshot researchers purely by exploring an unlabeled sidebar item behind a "Codex mobile" promo sheet — it is not documented in any marketing copy the researchers found, despite exposing a full three-tier autonomy model including a "Full access (elevated risk)" unattended-computer-control option. [shots-chatgpt-ios-health-voice-work.md §3.6]
- **Both products**: usage-limit _mechanics_ are themselves undiscoverable — neither vendor surfaces a running counter proactively; users learn how the rolling-window/dual-meter system works only by hitting the wall and researching afterward. [cross-cutting-and-complaints.md §7, §8]

## 11. Anti-patterns not to copy

Ranked roughly by how directly evidenced and how costly the mistake was, per `cross-cutting-and-complaints.md §8` plus corroborating detail pulled from the surface-specific research above.

1. **Don't let one plan-tier name mean two different things at two different price points.** OpenAI currently sells $100 and $200 plans, both called "Pro," differentiated only by usage allowance — a named, called-out source of purchase confusion in multiple pricing breakdowns.
2. **Don't rename or relocate a core surface without a visible migration story.** ChatGPT's Chat→buried-under-Work-and-Scheduled, Canvas→writing/code blocks, and Atlas→(desktop app + Chrome extension) all shipped as forced, non-optional replacements, each generating a wave of "OpenAI quietly killed X" posts. Even where the underlying decision is defensible, the _execution_ — no opt-out, no clear deprecation timeline communicated up front, features vanishing for some users/versions before others — is what generates backlash.
3. **Don't default a chat product to a non-chat mode.** The reviewer critique of ChatGPT's new desktop app ("how can a product called ChatGPT not default to chat mode?") is a sharp, quotable example of agent/work modes being prioritized over the product's namesake function in the default navigation state.
4. **Don't bury a paid, already-entitled feature behind an undiscoverable settings flag.** Claude's file-creation-and-Artifacts dependency living behind an unlabeled or "Experimental" toggle means paying users may never find (or may lose access to, silently, if the toggle gets flipped) a capability they're already paying for.
5. **Don't make usage limits a black box.** Both vendors draw sustained, high-engagement complaint threads for the same underlying failure: users cannot see a running counter, don't understand rolling-window vs. calendar resets, and (Claude's case specifically) can no longer find a published message-count reference at all because the help-center articles were removed. If usage limits exist, publish the mechanics and show a live counter before the wall, not after.
6. **Don't let a cost-saving infra change silently become a quality regression.** Claude Code's six-week degradation (a reasoning-effort downgrade meant to fix a UI-latency complaint, plus an unintended every-turn caching bug) shows how a well-intentioned performance fix can compound into a customer-facing quality incident if the eval suite doesn't catch incremental degradation — the postmortem explicitly names "internal evals used different builds" and "evaluation suites too narrow" as root causes. Ship perf/latency changes behind the same eval gates as capability changes.
7. **Don't let two independent meters (session + weekly) share one mental model with a single daily-limit expectation.** Anthropic's own users repeatedly describe the two-meter design as the single most misunderstood thing about Claude's paid plans.
8. **Don't strand a feature on legacy models that are themselves being sunset.** Telling users "Canvas still works if you use o3" while simultaneously announcing o3's retirement date is a deprecation-in-two-steps that reads, to affected users, as a broken promise rather than a supported fallback.
9. **Don't undersell a safety incident with soft language.** Anthropic's release notes describe Fable 5's pull-and-relaunch as a "redeployment... with a new jailbreak severity scoring framework" — technically accurate, but it takes outside reporting to reconstruct that this was a suspension-driven event. If a model is pulled for a safety reason, say so plainly in the first-party release notes rather than only in the reintroduction announcement.
10. **Don't ship a name nobody can hold in their head.** Six ChatGPT major-version bumps in under nine months (5.1→5.6) plus three unlabeled codenames (Sol/Terra/Luna) — even OpenAI's own CEO publicly disowns the scheme. Anthropic's parallel addition of "Fable"/"Mythos" atop the already-established Haiku/Sonnet/Opus ladder risks the same fate; keep new tier names additive and clearly ranked relative to the existing ladder, not a second unexplained naming system layered on top.
11. **Don't tighten a security default without flagging it as a behavior change.** Claude Desktop Extensions silently flipping from "loads by default" to "blocked by default" for managed deployments (v1.19367.0) is defensible as a security posture improvement, but shipped without the kind of explicit "this is a breaking change" callout that would let an admin relying on the old default catch it before something silently stops working.
12. **Don't let a single toggle name recur with silently different scope across surfaces.** Claude's "Switch models when a message is flagged" toggle appears independently, separately scoped (web/remote vs. local-session vs. worktree-level), in at least three different settings locations with the same label — functional, but a real source of "I already turned this off, why is it still happening" confusion unless the scope is stated inline every time (which Anthropic does, to its credit — the anti-pattern is the _pattern itself_, not the execution here).
13. **Don't ship an "elevated risk" permission tier without stating the risk in the picker copy itself.** Both products get credit for doing this well (Claude's "Full access... (elevated risk)" mobile picker; Codex's identical "Full access (elevated risk)" and the CLI's `bypassPermissions` acceptance dialog) — worth naming as a **pattern to keep**, since the alternative (a generic "Advanced" toggle with the risk explanation one click deeper) is the actual anti-pattern several less-careful surfaces in this same research default to for less consequential settings.
