## 0. How to read this document

This document answers **"exactly what exists."** It does not answer "what is missing" —
that is `GapMatrix.md` (168 filed gaps: 3 P0, 45 P1, 85 P2, 35 P3, synthesized from
`gaps/domain-*.json`). The two are deliberately not merged: a feature can be fully
inventoried here as COMPLETE and still have a P2 polish gap filed against it there, and
an item classified DEAD/MOCKED/BROKEN here is _reported as a fact about what exists_,
not re-litigated as a prioritized gap.

**Classification vocabulary**, used identically to the underlying `inventory/*.md` files:

| Label                | Meaning                                                                             |
| -------------------- | ----------------------------------------------------------------------------------- |
| **COMPLETE**         | Wired end-to-end (UI → state → API/IPC → runtime → persistence → UI), no fake data  |
| **PARTIAL**          | Real but incomplete — a subset of the claimed capability works                      |
| **UI_ONLY**          | Renders and looks live but has no backend behind it                                 |
| **BACKEND_ONLY**     | Fully implemented server/native logic with no UI path that reaches it               |
| **MOCKED**           | Returns fabricated/hardcoded data as if it were real                                |
| **DEAD**             | Built (sometimes fully, sometimes tested) but unreachable from any live entry point |
| **BROKEN**           | Reachable, but demonstrably fails or contradicts its own documented precondition    |
| **HIDDEN**           | Deliberately gated off (feature flag, environment, or design decision), not broken  |
| **DUPLICATED**       | Two or more independent implementations of the same capability coexist              |
| **NEEDS_VALIDATION** | Evidence is inconclusive from static reading alone; requires a runtime check        |

Every claim below carries a `path/file:line` citation or is explicitly marked
**NEEDS_VALIDATION**. Two findings from earlier drafts of this audit were retracted after
re-verification and are stated here in their corrected form, not their original wrong
form (per this audit's own correction record):

1. **The web auth-route cluster is not duplicated.** `/sign-in`, `/sign-up`, `/register`,
   `/auth/login`, `/device-auth`, and `/user` are documented, intentional `redirect()`
   aliases to the two canonical Clerk screens (`/login`, `/signup`) — not competing
   implementations. See §2.2.
2. **The product is publicly reachable.** `https://agiworkforce.com` is live, public, and
   served with a strict CSP/HSTS posture. An earlier reading of only one Vercel project's
   `domains` array wrongly concluded the product had no reachable apex domain. See §1.

> **Correction — `voice_inject_text`.** An earlier inventory pass
> (`desktop-tauri.md:394-414`) classified this **BROKEN**, reporting that the
> command is wired into the live push-to-talk flow despite its own doc comment
> forbidding exactly that, and could therefore inject text into a focused
> password field. The later voice/media domain pass refuted it, and the
> refutation was independently re-verified for this document.
>
> What is true: the front-end plumbing does exist — `stores/settings/voice.ts:744`
> exposes an `injectText` action that calls `api/voice.ts:438`, which invokes the
> command. What the first pass missed is the admission gate behind it.
> `system_dictation_available()` is a **compile-time `const fn` returning
> `false`** (`features/speech/dictation/coordinator.rs:36`), and
> `coordinator.rs:134` refuses any `DictationSource::Global` request while it is
> false. The global path is therefore closed before it can reach the injector,
> and grepping confirms the JS action has no callers outside its own definition.
>
> Corrected classification: **HIDDEN — a latent risk, not a live defect.** The
> unsafe capability is built and reachable in principle but unreachable in
> practice, held shut by one constant. It is filed as `VOICE-MEDIA-012` (P3) with
> the recommendation that the precondition be enforced in code rather than left
> to a flag someone could flip without reading the doc comment.
>
> This is a good illustration of why this audit re-verified inventory claims
> rather than trusting them: the first pass traced the call chain forward and
> stopped; the second traced it through to admission.
