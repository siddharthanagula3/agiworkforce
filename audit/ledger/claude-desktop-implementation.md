## Reproduce bounded native acceptance

Use repository Node/pnpm/Rust pins. Build `cargo build -p agiworkforce-cli --bin agi` and `pnpm --filter @agiworkforce/desktop build:electron`, then run:

```sh
node apps/desktop/electron/__tests__/native-acceptance.mjs
node apps/desktop/electron/__tests__/native-acceptance.mjs --browser
```

The harness creates isolated project/config/app directories, serves the real hosted hook and local-routine component, uses a scripted loopback model, supplies native-dialog answers only inside its owned app and captures OS fallback. It does not register the app as a default protocol handler, alter login items or claim real model quality. It prints its report directory; `AGI_ACCEPTANCE_OUTPUT_DIR` selects another output directory. It is deliberately outside automatic unit discovery.

The Office integration is explicit:

```sh
AGI_OFFICE_LOCAL_INTEGRATION=1 pnpm --filter @agiworkforce/web exec vitest run lib/services/managed-office-render.integration.test.ts
```

It requires the installed render tools and proves that local runtime, not an untested E2B image.

## Failures, compatibility and rollback

- Real Office evaluation first retained stale formula caches. Recalculation staging now removes caches/forces evaluation, then checks and transplants evaluated values into the original package. Original inputs remain untouched on failure.
- The first real normal-child turn overflowed a Tokio worker stack. Heap allocation of the large inner future fixed it; both a size regression and real binary integration now cover it.
- A routine verifier initially returned before its asynchronous condition had been established. The retained harness uses explicit awaited IPC polling, then checks persisted history and model-call counts across restart. No product recovery rule was weakened to accommodate that verifier.
- A keyless loopback model is Local and correctly receives no browser relay. The successful browser fixture explicitly selects a synthetic BYOK route; no Local egress exception was added.
- Automatic approval review rejected a proposed no-persistence child compatibility exception because it would bypass durable lifecycle ownership. It was not applied. The safe persisted-owner restriction remains.
- Additive protocol fields preserve negotiated old clients. The extension answers an unsupported new command as failure; the host does not double-open through fallback. Routine restart retains settled history, pauses unresolved claims and rechecks grants. Artifact restore appends history. Office failures preserve source bytes. SSH disconnect retires owned transport and admits no local substitute.
- Rollout remains bounded by the existing grants/capabilities. Disable new starts, cancel/drain admitted work and preserve session/routine/artifact records on rollback. Do not restore bypass spawning or replay old side effects. No database migration or production deployment/mutation was performed; isolated acceptance Previews were deployed.
