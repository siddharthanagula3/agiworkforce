# Code-Quality Audit: AGI Workforce Monorepo (Shared Code)

## Executive Summary

The AGI Workforce monorepo's shared code layer (packages/, crates/, services/) exhibits **moderate-to-high quality debt** concentrated in three areas: (1) **intentional incompleteness** (PostgreSQL adapter, artifact versioning/cloud, token usage typing) documented but left unfinished, (2) **architectural slop** (1,087 trivial wrapper functions consuming 8,582 lines with zero business logic), and (3) **duplication hazards** (divergent error-message maps, replicated yield blocks across 8 provider adapters). The codebase is **shipping with 3 CRITICAL findings** (Postgres unimplemented, artifact cloud deferred, config panics) that will cause runtime failures if production misconfigures to enable those code paths. **Verdict: Not release-blocking if these features are genuinely unsupported**, but risks are inadequately surfaced—operators cannot distinguish "not ready" from "broken" at deploy time. High-priority fixes: eliminate dead error-message map, consolidate provider error blocks, implement Postgres or remove it, replace 1,087 wrappers with a single generator.

## Prioritized Remediation Plan

### Phase 1: CRITICAL (Release Blockers) — Week 1

1. **INCOMP-001 (PostgreSQL): Resolve Shipping Risk**
   - **Immediate decision**: Is PostgreSQL production-ready? If NO: remove 'postgres' from `DATABASE_PROVIDERS` in factory.ts:87, delete adapter export, update docs to list only 'neon'.
   - **If YES**: Implement using pg driver per JSDoc spec (lines 48–99 in postgres.ts). Add integration test verifying `query()`, `execute()`, `transaction()`, `withUser()` work end-to-end.
   - **Rationale**: Postgres is selectable at runtime but non-functional. Operators cannot distinguish "not ready" from "broken" at deploy time. Removing it prevents misconfiguration entirely.

2. **INCOMP-010 (Config Panic): Unblock Startup**
   - Replace panic in `default_provider_auth_cwd()` with fallback: use system temp dir or user home if current_dir fails.
   - Add Result return type and propagate to config validation layer for proper error reporting.
   - **Rationale**: Config initialization panics crash the process before graceful-error handling can activate.

3. **INCOMP-009 (non_zero_u64 Panic): Config Validation**
   - Implement custom serde deserializer for NonZeroU64 fields that returns ConfigError instead of panicking.
   - **Rationale**: Zero values in config cause unrecoverable panics; should fail with a clear error message.

### Phase 2: HIGH (Maintenance Bloat) — Week 2

4. **wrapper-boilerplate (1,087 functions): Collapse to Generator**
   - Create `createCommandGroup(commands: Record<string, string>, group: string)` factory in packages/api/src/command-gen.ts.
   - Update agent.ts, automation.ts, chat.ts, mcp.ts, memory.ts to use factory instead of hand-written wrappers.
   - Run tsc --noEmit to ensure types still infer correctly.
   - **Impact**: 8,582 lines → ~200 lines; single edit point for future command changes.

5. **DUP-001 (Error Messages Divergence): Consolidate**
   - Delete `FRIENDLY_ERROR_MESSAGES` from packages/types/src/errors.ts:191–294.
   - Keep only packages/utils/src/errors.ts as canonical.
   - Update icon values: NOT_FOUND, PGRST116 → use 'error', not 'info'.
   - Run `rg FRIENDLY_ERROR_MESSAGES` to verify no orphaned imports.

6. **DUP-002 (Provider Error Blocks): Extract Helper**
   - Create `createStreamErrorChunk()` in llm-runtime/src/errors.ts.
   - Update all 8 providers to call helper in catch block.
   - Verify OpenAI's duplicate block is consolidated.

### Phase 3: MEDIUM (Type Soundness) — Week 3

7. **INCOMP-003 (model_context_window Optional)**: Make Non-Optional\*\*
   - Change `Option<i64>` to `i64` in TurnMeta and TokenUsageInfo.
   - Add serde(default) attributes to preserve backward compatibility.
   - Update all constructors to provide this field or compute from context.

8. **F-001 (Retry Off-by-One)**: Fix Boundary\*\*
   - Change `>=` to `>` in offline-queue retry comparison (line 271).
   - Verify `getMessageRetryStatus()` and sync loop are consistent.
   - Add test asserting items with retryCount < maxRetries are retried.

### Phase 4: LOW (Code Cleanup) — Week 4

9. **TG-002 (Test-Mode Guard)**: Refactor for Testability\*\*
   - Remove isTest guard from command.ts.
   - Inject routing logic as dependency so it's mockable without env checks.
   - Update tests to verify routing fires without mocking detect.ts.

10. **TG-001 (Constant Assertions)**: Add Semantic Tests\*\*

- Replace constant-value assertions with correctness tests.
- Verify DISPATCH_HMAC_REQUIRED_AFTER is a valid future date.
- Verify DISPATCH_SIGNATURE_ALGORITHM is in allowed list.

11. **DUP-003, DUP-004**: Mark Dead Exports\*\*

- Audit `getFriendlyErrorByCode()`, `formatErrorForChat()`, `getContextualError()`.
- Mark genuinely unused exports as `@internal` or `@deprecated`.
- Document which retry (utils vs llm-runtime) applies to each use case.

## Verified Clean

- **Error classification logic** (`classifyError()` in each provider): consistent across adapters, well-tested.
- **Permission sandbox** (absolute path enforcement): validly implemented; panic found is mathematically unreachable (Path::ancestors always yields root).
- **Factory pattern** (database/auth adapters): clean interface, proper NotImplementedError semantics for unimplemented providers.
- **Type generation** (protocol.rs → TypeScript): auto-sync working; minimal manual duplication of types.
- **Artifact store operations** (local publish, file I/O): well-scoped v1 implementation, limitations clearly documented.
- **Event bus architecture** (packages/runtime/src/events.ts): pattern sound; no-op fallback is documented limitation, not a bug (though should warn).
- **Offline queue logic**: retries correctly implemented except for the off-by-one boundary check (fixed in Phase 3).
