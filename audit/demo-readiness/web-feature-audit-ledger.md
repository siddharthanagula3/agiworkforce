# Web Feature Audit Ledger

Status: Active
Owner: Web lead
Last updated: 2026-06-05

This ledger tracks website demo-readiness one feature group at a time. A row is closed only when the user-visible UI works, every visible control is connected or intentionally gated, the related code path has been traced, focused tests pass, and evidence is recorded.

Allowed statuses: `not-started`, `in-review`, `needs-fix`, `fixed-pending-test`, `blocked-with-evidence`, `closed-with-evidence`.

## Audit Rules

- Audit Website before Desktop.
- Do not audit multiple feature groups at once.
- Do not close a row from build success alone.
- Run the unusual-behavior loop on every visited route: inspect UI, click visible primary and secondary controls, watch console/network output, verify signed-in and signed-out states where relevant, and stop on the first reproducible user-facing defect.
- Public claims about security, billing, managed cloud, models, mobile features, customers, users, or production readiness must be backed by implementation evidence or softened.
- Web is account, projects, synced app chats, artifacts, billing, and waitlist. Web must not expose BYOK/free env-key chat as a public Web chat path.
- Reference repos are for behavior comparison only. Do not copy proprietary code or assets.
