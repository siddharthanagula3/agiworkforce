## 3. Do not build as written

**No row was returned with an `UNSAFE_AS_WRITTEN` verdict.** These nine carry a specific recorded harm. The first four cause data loss or a false user-facing claim.

**1. Published-artifact expiry — data loss.** `apps/web/db/neon/0095_published_artifacts.sql:11-20` states the absence of an expiry column is deliberate and founder-pending for CAP-015: "a column defaulted to some arbitrary window would silently start deleting user-visible pages on a policy nobody approved." Do not invent a TTL. This needs a founder policy decision, not an implementation.

**2. Conversation retention control — live false claim, shipping today.** `apps/web/features/settings/components/Settings/System.tsx:171-189` renders a "Data Retention (days)" input (1-365) that validates and persists, but `retention_period` has **zero hits in `apps/web/app/api`**. A user setting 30 days believes their data is being purged. It is not. Fix by enforcing it (a purge job keyed off the value, matching the existing purge-temporary-chats cron) **or** removing the control — not by building features around it.

**3. Per-project memory scope — decorative control.** `apps/web/features/projects/components/ProjectSettingsDialog.tsx:200-207` is a `<select>` with one option and no `onChange`; `handleSave` (lines 69-96) sends only `{name, instructions}`. Same class as #2. Build real scoping or delete the select.

**4. Image "edit" path silently regenerates.** `apps/web/features/chat/components/ImageGenerationCard.tsx:384-407` — `handleDescribeEdit` concatenates `${currentPrompt}. Edit: ${text}` and sends it through the generate-only path. A user asking to change one detail gets a fresh image, not an edit — while a real edits endpoint exists at `api/media/image/generate/route.ts:303-378`. Wire the existing `operation`/`source_image`/`mask_image` fields; do not extend the concatenation.

**5. Full-duplex voice / live camera in voice.** `packages/contracts/types/src/model-catalog.ts:57-68` has no `realtime` member in the `ModelType` union. Building a duplex UI on top of the tap-based loop (`apps/mobile/src/features/voice/hooks/useVoiceConversation.ts:238`) would be a false capability claim. Keep copy at "push-to-talk."

**6. Notification channel toggles.** `apps/web/features/settings/sections/NotificationsSection.tsx:22-31` records that `emailSecurityAlerts`, `emailWeeklyDigest`, `emailProductUpdates`, `mobilePushReplyReady`, `mobilePushAgentDone`, `browserAgentDone` were **removed** because none had a backend consumer. Re-adding any toggle before its sender exists re-creates the exact bug that was already fixed.

**7. Embeddings route.** `packages/contracts/types/src/models.json:936-941` lists `gemini-embedding-2`, but its only consumer is `packages/contracts/types/src/__tests__/model-catalog.test.ts`. Building a route against a catalog entry with unconfirmed provider wiring ships a 500. Confirm router wiring first.

**8. Reranking.** No reranking-capable model exists in the catalog. A reranking endpoint has nothing to call.

**9. Domain capture (auto-join).** `apps/web/lib/server/sso/idp-metadata.ts:202-213` validates a domain for SSO routing only. Auto-joining users on domain match without a verified domain-ownership proof grants org membership via a spoofed or shared email domain.
