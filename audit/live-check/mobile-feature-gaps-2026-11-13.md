# Mobile feature gaps against the four competitor apps

Status: Open
Owner: Mobile + product (founder)
Verified: 2026-11-13
Scope: The mobile app in the working tree, read against the founder's 229 iPhone screenshots of ChatGPT, Claude, Perplexity and Gemini (2026-11-12). The features below were built on 2026-11-13 and checked by unit tests and the type check only. Nothing here was run on a device or against a server, and this is not evidence about any released build.

The full comparison, 512 features with the pictures and code lines behind each, is `docs/research/mobile-layout-2026-11-12/feature-comparison.md` and `features.jsonl` beside it. It records the app as it was before this work. The founder answered its questions in `docs/decisions/2026-11-13-founder-decisions.md` (`D-2026-11-13-01` to `D-2026-11-13-06`): build what most of the apps share, except a greeting with the user's name, image style templates, an Images page and changes to two-step sign-in. This file holds what is still open after that build: the live checks, the parts that were left out, and the steps only the founder can take.

## Left out, with the reason

A part is built only where the data or the server really supports it.

| Part                                                                                                                       | Why it was left out                                                                                                                                                                                                                                                                                                                                                                                          |
| -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Library filters for favourites, folders, suggested, pages, sites and the design, slides, sheets, whiteboard and data kinds | The Library has no such field or kind to filter on.                                                                                                                                                                                                                                                                                                                                                          |
| Coding session states "needs input" and "ready for review"; an Archived filter for sessions on a computer                  | The server has no such state.                                                                                                                                                                                                                                                                                                                                                                                |
| Adding a photo or file during live voice in Cloud                                                                          | A file reaches the live voice model only as one small inline message. Shrinking a phone photo to fit needs an image-resizing native module the app does not include, which means a new dependency and a new build.                                                                                                                                                                                           |
| A push when a plain Cloud reply finishes                                                                                   | The server sends the reply notice only for turns that run as a server-side run, today the turns that use tools. A plain turn stops when the phone disconnects, so there is no finished reply to announce.                                                                                                                                                                                                    |
| A reply notice for Local chats on iPhone after the app has been in the background for a while                              | iOS pauses the app a few seconds after it leaves the screen, so the notice appears only if the reply finishes in that window. Android keeps generating.                                                                                                                                                                                                                                                      |
| A switch to use connected apps to personalise answers                                                                      | A connected connector is already offered to every Cloud chat and is switched off per chat. A second, global switch would have nothing of its own to control.                                                                                                                                                                                                                                                 |
| A help link on the Usage page                                                                                              | The help article talks about buying, which version 1 does not offer. The page explains the limits itself instead.                                                                                                                                                                                                                                                                                            |
| Signing out an account that is not the active one, straight from the accounts list                                         | Not built. Log Out ends the active account and moves to the other one.                                                                                                                                                                                                                                                                                                                                       |
| Push for the first account straight after a switch that failed part-way                                                    | When the first account's registration was released and the other account then could not be made active, the first account registers again only once its old registration has been cleaned up, which needs the network. Until the next sign-in, mode change or restart it gets no pushes.                                                                                                                     |
| Logging out of one of two accounts while the phone is offline                                                              | Both accounts are signed out. The app cannot confirm that the first account's push registration was released, so it does not continue on the other account.                                                                                                                                                                                                                                                  |
| The Log Out question naming the account the app continues on                                                               | Not built. Log Out ends the account in use and the app moves to the other one without saying which.                                                                                                                                                                                                                                                                                                          |
| Adding a photo or file to a session on the computer from the phone                                                         | One relay message is too small to carry a file, and the relay is not being changed for now.                                                                                                                                                                                                                                                                                                                  |
| Thinking text for every model route                                                                                        | The computer relays thinking only where the route sends it: provider thinking, reasoning summaries and the managed gateway's inline thinking. Other routes show none.                                                                                                                                                                                                                                        |
| Add device while a computer is paired                                                                                      | A phone holds one pairing at a time. The device row opens the pairing page, where the current pairing is ended first.                                                                                                                                                                                                                                                                                        |
| A computer's own copy of the account's Cloud sessions in the Code list                                                     | The Cloud list already holds them, so the copies a computer relays are not listed twice.                                                                                                                                                                                                                                                                                                                     |
| An admin screen for sending a product update                                                                               | The send is an operator procedure: one authenticated call that names a published release note. It refuses an unknown release and one whose send is still on record in the background jobs. A push that could not leave is tried again by the job; after the last try the entry stays in the notification list without a push. A page that fails for good is requeued by an operator from the dead jobs list. |
| A product update push that arrives during a person's quiet hours                                                           | It is not sent later. The entry stays in the notification list, which is how every push is treated in quiet hours.                                                                                                                                                                                                                                                                                           |
| A product update entry that shows only on the phone that turned the switch on                                              | The notification list belongs to the account, so the entry also shows in the list on the web. The entry carries the first line of the release note and has no link, because the list has no link kind for a release note; adding one needs a database change.                                                                                                                                                |

## Founder steps

1. Turn on multi-session in the sign-in provider's dashboard, on the development and the production instance. Until then the accounts card shows nothing new and the app behaves as it does today. Deploy the web app first: the second account gets pushes on the phone only once the server can release the first account's device registration, which is a server change in this work.
2. Have a lawyer read the consent wording and the policy changes it implies before either switch is ever used for anything. Nothing uses customer content today, so the published pages are still true and were not changed. The statements to change before any use starts: `apps/web/app/terms/page.tsx`, `apps/web/app/privacy/page.tsx`, `apps/web/app/data-use/page.tsx`, `apps/web/app/dpa/page.tsx`, `apps/web/app/faq/page.tsx`, `apps/web/app/mobile/legal/page.tsx`, `apps/web/app/privacy/india/page.tsx`, the help articles `privacy-controls.md` and `managed-cloud.md` under `apps/web/content/support/`, and the store privacy declarations under `apps/mobile/store-listing/`. Open questions for the lawyer: whether a workspace member's personal consent can count under the data processing agreement, and whether the choice must be stored in the consent record that holds notice versions.
3. Choose how provider logos appear in the model list: option O6 in `docs/compliance/mobile-store-feature-justification.md`.
4. Before the first product update is sent in production: the platform-admin allowlist set, the background jobs schedule running, the release note published, an app build with the new switch released, and push delivery working.
