# Chrome assistant parity: live audit

Status: Open
Owner: Extension + product maintainers
Verified: 2026-11-03, America/Chicago
Scope: Installed Chrome interfaces and the current AGI working tree, including uncommitted changes. This is not evidence of a published Chrome Web Store release.

## Product being evaluated

AGI is an assistant for the browser page the user is working on: understand the current page, selection, permitted field state and relevant tabs; answer questions; edit or act when requested; verify the result. Job applications are one task within that product.

The founder's supplied comparison is a research checklist, not evidence that every listed feature exists or is absent in AGI. This audit does not assume that a declared tool, rendered button, or source module proves successful execution.

## Corrections verified in this working tree

Unit tests cover passwords (including revealed passwords), payment/autocomplete fields, hidden controls, secret redaction, bounded output, missing-receiver injection, changed sources and same-address document replacement.
- Selected-text Ask prepares browser chat without sending. Native Chrome verified the selection chip and preservation of an unsent draft. Explicit local handoff remains separate and was cancelled during its native preview test.
- The founder's duplicate Working/Worked screenshot exposed two independently rendered logs and a browser log left running after cloud completion. The correction combines them into one timeline and settles browser activity on confirmed managed completion/failure/cancellation. The rebuilt native Chrome test showed exactly one `Worked for 2s · 1 step` disclosure, with the browser read step retained when expanded and no stale Working row. The form values stayed unchanged. Typecheck, lint, production build and 236 focused tests in 11 files passed for the combined changes.

The task-grant and inline-writing changes passed typecheck, lint and production build. The complete extension suite most recently reported 3,201 passing tests and five failures in the pre-existing untracked `chrome-subscription.test.ts` and `task-tabs-background.test.ts`; the full suite is not green. Pairing tests require localhost binding; the first sandboxed run was unable to listen, and the final run used the permitted local-server test environment.

The general native batch passed the clean R4N2 live check and its retained receipt check. A batch uses one fresh document-bound observation, matches original field identity/signature and observed values, and consumes that observation. It validates protected inputs and secret-looking answers, preserves existing answers unless explicitly replacing them, and checks retained values and native validity. The job-profile adapter shares this engine. Rich editors, cross-frame/shadow-root controls and file uploads remain outside this batch path.

History import retains activity only for an unambiguous message in the same owned account/workspace with identical cloud message ID, role and content. The retained events stay device-local; metadata serialization and pending-sync checks were tested. A regression test first demonstrated loss with retention disabled. Restored activity timing uses the canonical completion event rather than the history save timestamp.

## Auto continuation routing

The extension previously resolved the user's Auto choice to a concrete local candidate and sent that model ID on every browser-tool leg. This made the server treat Auto as an explicit model selection. The corrected transport preserves `auto` or the admitted Auto profile on every leg, including Quick's Economy alias; explicitly selected models remain explicit. Wire-level tests run the real handler and SSE transport together, preserve the completed browser result and assert that the handoff is executed once. Both Auto variants failed before the correction and passed afterward.

The shared managed failover owner also stopped on a classified `invalid_model` response for a catalog model selected by Auto. It now admits that availability failure to the existing fallback plan only at the first provider dispatch of the current request, before output has been released. Named-model refusals, unknown catalog identities, safety refusals, later/unknown steps, cancellation and candidate admission remain guarded. The change does not reclassify a generic 404 or introduce an unbounded retry. Removing this branch made the three positive recovery cases fail; the restored branch passed all seven focused cases. A completed client-browser transcript is retained across the fallback.

A native Chrome read with the picker on Auto returned the unique visible text `Auto continuation R7F4. Keep this form unsubmitted.` after one browser-read step. The footer named GPT-6 Luna; the activity showed 5s and the full-response footer 12s. This is one healthy live route, not a forced upstream-failure benchmark. The operator's keyboard setup added trailing newlines to the fictional source before dispatch, so this check establishes the unique text read and successful continuation, not byte-for-byte whitespace fidelity. No form was submitted.

That run also exposed an Auto effort-help mismatch: the footer named the server's model while the picker help still named the preliminary local candidate. Continuation state now validates and uses the server-reported model, resolves effort for it and preserves the user's Auto or explicit selection. All four new executable continuation cases failed before the correction and passed afterward; malformed model receipts are refused. New source uses the existing answered-model normalizer and model catalog.
