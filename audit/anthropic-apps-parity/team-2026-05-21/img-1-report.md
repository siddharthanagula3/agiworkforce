## Recommended takeaways for the team

(Not part of the rubric; included so the lead's synthesis can prioritize.)

1. **Three modes inside one shell is the structural Claude move.** Chat is the well-known surface; Cowork is its long-running-task product (Recents/Active/Scheduled/Live artifacts/Dispatch/Customize); Code is a distinct product with sessions, repo+branch+worktree, stats heat-map, permission modes (Ask / Accept edits / Plan / Auto / Bypass), model+effort matrix. Parity work needs to either implement all three or pick a coherent subset.
2. **Customize hub is the connectors home, not Settings.** Settings explicitly defers to Customize. Per-connector pages have a tool-permission ladder (read-only / write-delete) with group-level dropdowns and per-tool quick-actions.
3. **Code surface owns the richest plan-usage UI.** The 4-bar usage popover (5-hour limit / Weekly all-models / Weekly per-tier / per-model-cap), token-count footer comparator, contribution heat-map, and per-session stat tiles together imply a serious analytics layer.
4. **Skills are slash-typed, browsable, addable.** `/` in the composer opens a fuzzy filter with installed skill icons; Customize→Skills detail renders SKILL.md + README.md with a Personal/Default toggle, edit/version controls implied by metadata stripe.
5. **Tool-permission inline prompt is the canonical "ask the user" pattern** — always-allow dropdown + Deny (esc) + the thinking-chip explaining the upcoming call.
