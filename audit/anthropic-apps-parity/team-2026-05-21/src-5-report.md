# src-5 — Chrome Extension (`apps/extension`) Audit

**Slot:** src-5 — Chrome MV3 extension. Vanilla TypeScript with raw DOM construction (no React). Entry points: `popup.ts` (23 KB), `side_panel.ts` (155 KB, monolithic UI), `content.ts` (76 KB), `background.ts` (113 KB), plus an injected shadow-DOM in-page panel and a native-messaging bridge to the desktop app.

**Scope reviewed:** `apps/extension/manifest.json`, `apps/extension/src/popup.{html,ts,css}`, `apps/extension/src/side_panel.{html,ts}`, `apps/extension/src/content.ts`, `apps/extension/src/background.ts`, `apps/extension/src/features/{background,content,side-panel,native-bridge,popup}/`, `apps/extension/src/inPagePanel/` (deprecated re-export shim) and the canonical `apps/extension/src/features/content/in-page-panel/`, `apps/extension/src/autofill/`. Tests, dist, native-host, threat model not included.

**Rubric note on Gap delta:** I did not read Claude UI references in this fresh audit — those live with `img-5`. Where the absence is structurally obvious from the source (no projects feature, no artifacts panel, etc.), I state the gap; otherwise I mark `no gap visible — needs cross-validation by the lead`.

## Surface-level architecture

The extension exposes three UI surfaces and one injection surface:

1. **Popup** (`popup.html` + `popup.ts`) — small ~360px-wide action panel: connection status, quick-action buttons (Open Chat, Capture, Refresh, Group Tab), tab/session stats, in-page panel toggle, desktop pairing, tier badge, paywall card. No chat composer, no model picker.
2. **Side panel** (`side_panel.html` + `side_panel.ts`) — full chat surface. Header (logo, model picker, summarize, history, console, settings, clear), settings drawer, auth bar with status pill, two-tab body (Chat / Workflows), composer with attachments + voice + slash chips, persistent page-context chip.
3. **In-page panel** (`features/content/in-page-panel/panel.ts`) — Shadow-DOM 380px right-anchored overlay injected into allowlisted page origins. Page-aware quick chips, composer, response area, "Open in side panel" link. Allowlist-gated (`agi_site_allowlist`).
4. **Content script automation surface** (`content.ts`) — exposes ~40 message handlers for click / type / scroll / drag / accessibility-tree / form-fill / WebMCP / page-recording; targeted by background + native bridge for browser automation, not direct user UI.

Styling: side_panel builds a single ~1.3K-line CSS string via Constructable Stylesheets (`side_panel.ts:314-1647`); popup loads `popup.css`; in-page panel uses Shadow-DOM `<style>`. CSP forbids `style-src 'unsafe-inline'` (manifest:23-26).

## Cross-cutting observations

1. **side_panel.ts is a 4254-line monolith** (`apps/extension/src/side_panel.ts:1-4254`). All UI construction, state, message handling, dropdowns, workflows, console panel, settings, recording lives in one file. A modest refactor into the already-created `src/features/side-panel/*` folder (currently only holds `markdown.ts` and `voice.ts`) would help.
2. **Two parallel module trees**: `src/autofill/*`, `src/inPagePanel/*`, `src/nlweb.ts`, `src/webmcp.ts`, `src/page-metadata.ts`, `src/pairing.ts` are re-export shims pointing at the canonical `src/features/content/*` and `src/features/native-bridge/*` versions (see deprecation banners in `src/inPagePanel/setup.ts:1-4`, `src/features/native-bridge/pairing.ts:1-8`). Dead path; should be deleted after consumer migration.
3. **`packages/unified-chat` is not consumed by the extension** — see absence of any `@agiworkforce/unified-chat` import in `package.json` workspaces of this app. The extension does pull `@agiworkforce/design-tokens`, `@agiworkforce/utils`, `@agiworkforce/types`.
4. **Bridge URL allowlist** (`ALLOWED_BRIDGE_HOSTS` in `src/background/policy.ts`) is the single security-critical client-side validator for native bridge endpoints; same validator is reused for the settings input (`side_panel.ts:2907`). Good consolidation.

## Summary

- **P0 gaps:** image attachments are collected but never forwarded to the bridge (correctness bug); no projects/folders feature; no artifacts panel; the side panel UI does not share React components with other surfaces.
- **P1 gaps:** popup has no composer/model picker; markdown lacks tables/code-copy; history is flat (no search, projects, rename, export); model-picker count badge is hard-coded; only two settings (bridge URL + API key); voice is English-only and one-way; usage meter missing; no allowlist UI; no in-side-panel agent step rendering; design tokens partially unified.
- **P2 / extension-unique:** workflows recording + scheduled tasks, native-bridge pairing, in-page panel overlay, blocked-page state, tab-group integration, job-application autofill, NLWeb runtime detection — all stand on their own and need lead cross-validation against the Claude reference set.

The extension's strong points are security posture (CSP, sanitization, secret redaction, sender validation, HMAC bridge, allowlist gating) and the breadth of browser-automation primitives. Its weak points are UI completeness against AI-chat parity (composer surfaces, attachments wiring, artifacts, projects) and the lack of shared React components.
