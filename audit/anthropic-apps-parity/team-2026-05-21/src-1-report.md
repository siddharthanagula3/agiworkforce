## Foundational notes (apply across rows)

- **Icon library:** `lucide-react` is canonical (composer, sidebar, model selector, message bubble, thinking timeline, tool-call, attachment menu, agent control, command palette, settings popover). **Default stroke width is Lucide's `2`; only Sidebar (`Sidebar.tsx:82-126`), ModelSelector mic button (`ChatInput.tsx:317`), and InlineToolCall (`InlineToolCall.tsx:289`) opt into `strokeWidth={1.75}`** — the rest are at `strokeWidth=2`. Sizes are mixed: 9/10/11/12/13/14/15/16/18 — there is no single rule (e.g. composer Plus is 16, mic 16, ArrowUp 16; sidebar nav 18; tool-call icons 13/14/15). `simple-icons` is used only for provider logos in `ModelSelector.tsx:14-22`, rendered as `<svg viewBox="0 0 24 24">` with provider brand-color fill.
- **Typography:** display font is Crimson Pro, applied inline only on the `EmptyState` headline (`EmptyState.tsx:60-62`). Body is implicit Inter via the `--chat-font-sans` token. The package itself does not import a Google Fonts URL; hosts are expected to load fonts.
- **Density:** 12px sidebar pad-top, 8px sidebar item gap (`Sidebar.tsx:195`), 32×32 px nav icon button, 8px composer toolbar pad-y, max-w-3xl composer (`ChatInput.tsx:182`). Tool-call bar is 32px tall (`InlineToolCall.tsx:283`).
- **Radii:** rounded-md (8) for surfaces, rounded-lg (12) for cards, rounded-xl (16) for popovers, rounded-2xl (24) for user bubbles, rounded-full for chips and the send button. Send button uses `rounded-full` (`ChatInput.tsx:309, 327, 338`) instead of a square or rounded-square.
- **Color application:** chat surfaces consistently reference CSS vars (`--chat-bg`, `--chat-fg`, `--chat-surface-base`, `--chat-text-primary`, `--chat-accent-primary`, etc.). A handful of older components in the package use shadcn-style `hsl(var(--popover))` / `text-primary` / `bg-muted` / `text-muted-foreground` tokens instead (e.g. `SlashCommandMenu.tsx:51-94`, `KeyboardShortcutsDialog.tsx:97-156`, `BranchNavigator.tsx:82-115`, `ChatInputToolbar.tsx:30-209`). **There are two parallel color systems coexisting** — the `--chat-*` family and a shadcn-style `--popover`/`--primary`/`--border` family — and several components reach into the latter while the rest of the package uses the former. This is a real inconsistency rather than a designed dual-scheme.
- **State boundary:** package ships its own zustand stores (`useChatStore`, `useModelStore`, `useTierStore`, …) but accepts a `hostBridge` ChatHostBridge (`ChatInterface.tsx:248-249`) so apps can override conversation persistence. The `SettingsModal` (`SettingsModal.tsx:1-22`) is a pure event-dispatcher that fires `window.dispatchEvent('chat:action', { type: 'open-settings' })` — the package **has no settings UI**; each host (web, desktop, mobile, extension) renders its own settings panel.
