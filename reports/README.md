# reports

Purpose: product, parity, screenshot, and generated evidence reports
Retention: Keep durable report collections only when they support a current plan, audit, release, or product decision. Temporary captures belong in ignored local folders or a dated archive collection with this README contract.

## Rules

- Every direct child folder must be a lowercase kebab-case report collection with its own `README.md`.
- Do not place loose files directly under `reports/`; only this `README.md` belongs at the root.
- Product evidence that affects current strategy should be summarized into `docs/current/`, `docs/plans/`, or `audit/` before the raw report ages out.
- Generated screenshots and browser captures must stay inside a named collection with an owner and deletion policy.
